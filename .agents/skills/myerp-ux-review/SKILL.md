# MyERP 用戶體驗審查

目標：在人手試用之前，自己找出用戶會困惑或被誤導的地方。依據 MASTER_PROMPT 第 20 節。

## 何時做多少

| 情況 | 範圍 |
|---|---|
| 完成或修改單一頁面 / 對話框 | 只審查該畫面，第 1–4 步 |
| 模組 QA 工作單元（打 tag 前） | 模組全部介面，第 1–5 步，產出 qa-report.md |

## 第 1 步：列出要審查的畫面與狀態

從 `docs/02-modules/<模組>/ui-spec.md` 列出所有介面。每個介面按下表找出適用狀態（不適用要註明理由）：

正常有資料、空列表、搜尋無結果、驗證錯誤、409 版本衝突、422 業務規則拒絕、500 伺服器錯誤、逾時、無權限、成功、部分成功、全部略過、全部失敗、停用按鈕。

## 第 2 步：截圖

用 Playwright 截圖（範本見 `assets/qa-capture.template.ts`，複製到 `tests/qa/<模組>/` 後修改）：

- 錯誤狀態用 `page.route()` 模擬 API 回應，不要修改後端代碼。
- 每個狀態截兩張：淺色、深色模式。
- 至少用 zh-Hant 截全部狀態；zh-Hans 與 en 各截正常狀態一張，檢查翻譯完整與排版。
- 截圖存到 `tests/qa/<模組>/screenshots/<介面編號>-<狀態>-<主題>-<語言>.png`。

## 第 3 步：逐張檢視

**必須打開每張截圖親眼檢視**（用讀圖工具），不可只憑代碼推斷。按 `references/checklist.md` 逐項判斷，每個問題記錄：截圖檔名、清單編號、問題描述、嚴重程度。

嚴重程度：
- **P1**：誤導用戶（例如沒有變更卻顯示成功）、錯誤沒有任何提示、資料可能被誤操作。
- **P2**：資訊不足（例如略過沒有原因）、未翻譯、深色模式看不清。
- **P3**：排版、對齊、字眼小問題。

## 第 4 步：修正並補測試

- P1、P2 必須在本工作單元修正；P3 可列入 backlog。
- 每個修正的問題，加一個 E2E 斷言防止退步：同時斷言**畫面訊息**與**實際資料**一致。
- 屬於共用元件（提示、匯入結果、錯誤攔截器、空狀態）的問題，修共用元件，不在個別頁面打補丁。修正後重新截圖確認。

## 第 5 步：產出 qa-report.md（模組 QA 才需要）

寫到 `docs/02-modules/<模組>/qa-report.md`：

```markdown
# <模組> QA 報告（<日期>，WU-<模組>-QA）

## 範圍
審查介面 N 個、狀態 M 個、截圖 K 張（位置：tests/qa/<模組>/screenshots/）

## 發現
| # | 截圖 | 清單 | 問題 | 嚴重 | 處理（commit / backlog ID） |

## 未審查項目與理由

## 結論
P1：0、P2：0 才可打 tag。
```
