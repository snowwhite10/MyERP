# 用戶體驗審查清單

## A. 回饋與結果一致（最重要）

- A1 成功樣式（綠色 / success）只在**實際有資料變更**時出現。
- A2 批次 / 匯入 / 多筆操作的結果訊息寫出各類筆數（新增、更新、略過、失敗）。
- A3 結果為 0 筆變更、部分成功、全部略過時，用警告樣式，不用成功樣式。
- A4 每個略過、拒絕、失敗都顯示原因，具體到列或欄位（例如「代碼 SUP1 已存在」「此記錄已刪除」）。
- A5 提示訊息與畫面上的資料一致（例如說新增 3 筆，列表就多了 3 筆）。
- A6 操作完成後畫面自動更新（列表刷新、狀態標籤改變），不需要手動重新整理。

## B. 錯誤處理

- B1 400 / 409 / 422：顯示可理解的中文原因，不顯示英文例外或代碼。
- B2 500：顯示「系統錯誤」加 traceId，方便回報。
- B3 逾時、網絡中斷：有提示，並可重試。
- B4 驗證錯誤顯示在對應欄位旁，並捲動到第一個錯誤欄位。
- B5 錯誤後表單內容保留，用戶不用重填。

## C. 狀態與引導

- C1 停用的按鈕有說明原因（tooltip 或旁邊文字）。
- C2 空列表、搜尋無結果、無權限各有不同的明確提示。
- C3 進行中的操作有載入指示，按鈕在處理期間不可重複按。
- C4 危險操作（刪除、作廢、過帳）有確認對話框，說明後果。
- C5 單據狀態（草稿、審批中、已過帳）清楚顯示，不可操作的動作被隱藏或停用並說明。

## D. 文字與翻譯

- D1 沒有未翻譯的 i18n key（例如 `inv.receipt.title` 原樣出現）。
- D2 三語都沒有中英混雜、截斷、溢出。
- D3 用詞與 SRS、其他模組一致（同一概念不出現兩個名稱）。
- D4 數字、金額、日期格式符合 ui-conventions（千分位、小數位、yyyy-MM-dd）。

## E. 視覺

- E1 深色模式下文字、邊框、圖示、圖表都看得清。
- E2 沒有元素重疊、錯位、被裁切；長文字有省略號和完整提示。
- E3 表格欄寬合理，重要欄位不被擠掉。
- E4 必填欄位有標示。
