# MD 業務規則

1. 每筆 MD 主檔歸屬一間公司；未選公司時不返回業務資料。服務查詢與資料模型都要驗證公司隔離，不能只依靠前端路由。
2. 各模組只引用 `MyERP.Modules.MasterData.Contracts` 或公開 Application 介面，不直接讀寫 MD 表；MD 也不直接讀寫其他模組表。
3. 被單據引用的主檔保留歷史，以停用取代硬刪除；跨公司 ID 應回 404，不揭露其他公司的主檔存在。
4. WU-MD-001 不建立主檔資料，只有權限目錄與主檔入口。後續每個主檔功能須獨立加入資料模型、API、測試及三語頁面。
5. 客戶分類代碼在公司內唯一且一經建立不可更改；軟刪除後仍佔用代碼，避免歷史資料重新指向另一分類。不同公司可用相同代碼。
6. 分類不因停用而消失於管理列表；軟刪除後不再列出或編輯。WU-MD-003 建立客戶與分類的關聯時，須在分類刪除前檢查同公司客戶引用；已有引用只可停用。現階段客戶表尚不存在，故未產生引用。
7. 所有修改與刪除帶 `version`；資料已改動回 409。其他公司的 ID 或已軟刪除 ID 回 404，不洩漏存在性。
7a. 客戶分類、供應商分類及物料品牌列表的 URL 僅記錄已提交查詢，輸入中關鍵字不改變查詢或 URL。`page` 必須為安全正整數，`pageSize` 限既定選項，`sort` 限代碼／名稱升降序；非法值改用預設。公司不寫入 URL，切公司後保留關鍵字而頁碼回 1，再以新公司標頭重查（WU-MD-029a／029b）。
8. 客戶代碼在公司內永久唯一且不可修改；客戶名稱非空白、最多 200 字。停用保留主檔與歷史參照，列表仍顯示，可再啟用。
9. 客戶分類可為空；新選分類時必須是目前公司未刪除且啟用的分類。分類停用後，既有客戶可保留原分類但不可新選。資料庫複合外鍵再保證公司一致；分類被客戶引用時不可軟刪除，即使客戶停用亦然。
10. 供應商分類沿用客戶分類規則（第 5–7 條）：代碼公司內永久唯一且不可修改，軟刪除後仍佔用；不同公司可用相同代碼；所有修改及刪除帶版本。WU-MD-007 建立供應商時，供應商只可新選本公司啟用分類，並以 `(company_id, category_id)` 複合外鍵參照；已被供應商引用的分類不可軟刪除（`MD.SUPPLIER_CATEGORY.IN_USE`），只可停用。
11. 供應商沿用客戶規則（第 8–9 條）：代碼公司內永久唯一且不可修改；名稱非空白、最多 200 字；停用保留主檔與歷史參照。分類可為空，新選分類必須是本公司啟用的供應商分類，已停用的原分類可保留；客戶分類不可用於供應商（型別不同，查詢的資料表亦不同）。
12. 計量單位沿用分類代碼規則（第 5–7 條），另有小數位數 0–6；數量以目標單位的小數位數、遠離零四捨五入。換算記錄「1 來源 = 係數 目標」，係數為正、最多 9 位整數及 6 位小數，全部以 decimal 計算（不得 float／double）。兩單位之間最多一條換算路徑：不可自換、不可反向重複、不可經其他單位形成循環（`MD.UOM_CONVERSION.PATH_EXISTS`）；並行新增以公司級 applock 序列化。只可用本公司啟用單位新增換算；被未刪除換算引用的單位不可刪除（`MD.UOM.IN_USE`），只可停用。其他模組經 `IUomConverter` 換算（ADR-034）。
13. 物料品牌沿用分類代碼規則（第 5–7 條）。物料分類為樹：上層可空（根），新選上層必須是本公司未刪除且啟用的分類（`MD.ITEM_CATEGORY.INVALID_PARENT`）；上層停用後既有子分類可保留原上層。不可掛到自己或子孫下（`CYCLE`）；整棵樹最多 5 層，搬移時以「新上層深度 + 子樹高度」檢查（`TOO_DEEP`）。有未刪除子分類不可刪除（`HAS_CHILDREN`），停用不受限制。新增、修改、刪除以公司級 applock 序列化，避免兩個並行搬移互相掛載成環，或掛到同時被刪除的分類下；資料庫以 `(company_id, parent_id)` 複合外鍵與 `parent_id <> id` 檢查再保證。
14. 物料代碼公司內永久唯一且不可修改，名稱必填，規格可空。基本單位必填，品牌／分類可空；新選參照須屬本公司且啟用，停用後原物料可保留。資料庫的三條複合外鍵阻止跨公司關聯；任何未刪除物料引用的單位、品牌或分類不可刪除，即使物料停用亦然。主檔不記期初庫存或庫存餘額。物料（含停用）可按版本軟刪除（`MD.ITEM.DELETE`，ADR-050）：使用方 `IItemUsage` 回報已有庫存、交易或單據時拒絕（`MD.ITEM.IN_USE`）；否則在同一交易內軟刪除專屬換算、刪除圖片與屬性值；代碼保留不可重用（含匯入）。刪除持有 `md_item`、`md_item_attribute`、`md_item_image`、`md_item_uom_conversion` 的公司排他鎖，新增圖片與取代屬性值在鎖內重新確認物料存在。
15. 物料專屬換算（ADR-035）以物料基本單位為中心：每列「1 換算單位 = 係數 基本單位」，換算單位須為本公司啟用單位且不是基本單位，同一物料同一單位只一列，係數規則同第 12 條。按物料換算時，兩端先換到基本單位：專屬換算優先（覆寫該單位的公司級換算），其他單位用公司級路徑補充；任一端換不到基本單位時退回公司級直接路徑，否則 `MD.UOM_CONVERSION.NO_PATH`。物料有未刪除的專屬換算，或使用方 `IItemUsage` 回報已有庫存、交易或單據時，不可修改基本單位（`MD.ITEM.BASE_UOM_LOCKED`，ADR-049）；新增專屬換算與修改基本單位共用公司級 applock，避免並行時換算掛在舊基本單位上。被專屬換算引用的單位不可刪除（`MD.UOM.IN_USE`）。停用物料仍可換算（歷史資料）。查看與試算用 `MD.ITEM.VIEW`，維護用 `MD.ITEM.EDIT`；其他模組只經 `IUomConverter.ConvertForItemAsync`。

### WU-MD-028d — 可重放物料換算證據（設計）

| Rule | Contract rule |
|---|---|
| BR-MD-034 | 證據 reader 與既有 `IUomConverter` 分立；既有方法只保證目標單位精度的 decimal 數值，不得把該數值充當 SCM 的六位基準單位證據。MD 是基本單位與路徑的唯一 owner；SCM 只保存 MD 回傳的完整收據。 |
| BR-MD-035 | 首次簽發以公司、物料、來源單位、原始數量、政策版本及呼叫方永久操作鍵作唯一請求；同鍵同內容冪等重放，同鍵異內容 409。讀取同一已提交版本的物料、單位與每段換算，並在交易內原子保存不可變收據；未提交、部分路徑或混合版本不得簽發。 |
| BR-MD-036 | 路徑選擇沿用 ADR-035：來源即基本單位為零段；否則物料專屬直接邊優先，其次唯一公司級路徑至基本單位。每段記錄 conversion ID、版本、來源／目標單位、方向和正數係數；反向邊以倒數的有理數計算。若資料異常造成兩條同優先級路徑，不任選一條，回 `AmbiguousPath`。 |
| BR-MD-037 | 保存 `itemId/itemVersion/baseUomId/baseUomVersion/sourceUomId/sourceUomVersion`、路徑快照、原始 decimal 數量、精確有理數分子／分母、六位小數結果、`AwayFromZero` 政策 `MD-BASE6-v1`、收據 ID／digest／簽發時間及最早到期時間。中間乘除須檢查溢位，不以浮點或逐段捨入；最後一次捨入到六位。原始數量超過六位小數或結果超出 `decimal(19,6)` 可表達範圍時回 `PrecisionUnsupported`／`Overflow`；合法捨入誤差最多半個六位單位。 |
| BR-MD-038 | 證據識別碼至少保留 90 天，並覆蓋 SCM 已發布 manifest 的保留期；若長期保留由 SCM manifest 自存完整收據，MD 過期後須明示 `EvidenceExpired`。重放只讀已保存內容，係數修正、停用、軟刪除或基本單位變更不可改舊收據；新的操作鍵取得新收據。不可重建舊收據時回 `ReplayUnavailable`，不可默默以今天的設定重算。 |
| BR-MD-039 | 首次與每次重放都由 MD 以目前公司及呼叫者授權驗證；無權限或跨公司不得洩漏收據 ID、digest、是否存在。停用的物料／單位及換算只可供具歷史讀取權的重放；新簽發不使用已停用或軟刪除的路徑，回具名不可用原因。既有一般換算與歷史試算語意不受此規則改變。 |
| BR-MD-040 | 同單位、零數量及已提交完整空來源不是缺資料：同單位仍簽發基本單位版本證據；零數量也保留路徑與收據。無路徑、停用、過期或超精度不可轉成零，SCM 應逐列標記不可用並阻止受影響預測的核准。 |
16. 倉庫沿用分類代碼規則（第 5–7 條），另有可空的地址、聯絡人、電話；儲位屬於一個倉庫且只有一層，區／排／層以代碼表達，代碼在同一倉庫內永久唯一（不同倉庫可重複），只可改名稱與啟用狀態，不可搬到別的倉庫。只能在啟用倉庫新增儲位（`MD.STORAGE_LOCATION.WAREHOUSE_INACTIVE`）；倉庫停用不改儲位狀態，儲位可用 = 倉庫啟用且儲位啟用。倉庫仍有未刪除儲位不可刪除（`MD.WAREHOUSE.HAS_LOCATIONS`）；新增儲位與刪除倉庫共用公司級 applock，資料庫以 `(company_id, warehouse_id)` 複合外鍵阻止跨公司掛載。MD 不保存庫存數量；被庫存或單據引用的倉庫／儲位不可刪除（`MD.WAREHOUSE.IN_USE`／`MD.STORAGE_LOCATION.IN_USE`），由使用方實作 `IWarehouseUsage`／`IStorageLocationUsage`（ADR-036、ADR-049）。儲位查看用 `MD.WAREHOUSE.VIEW`，維護用 `MD.WAREHOUSE.EDIT`。
17. 幣別代碼為 ISO 4217 三個英文字母（大寫、公司內永久唯一、不可修改），金額小數位 0–4；`ICurrencyLookup.GetPrecisionAsync` 以主檔小數位覆寫 `CurrencyPrecision.Default`，業務模組把它傳給 `Money.Round`。本位幣是幣別上的旗標，每間公司最多一個：設定新本位幣時自動取消舊的；公司已有任何匯率後不可再更換（`MD.CURRENCY.BASE_LOCKED`）；本位幣不可直接取消（`BASE_REQUIRED`）、不可停用（`BASE_INACTIVE`）、不可刪除（`IS_BASE`）。有匯率的幣別不可刪除（`IN_USE`），只可停用（ADR-037）。
18. 匯率意義為「1 外幣 = rate 本位幣」，`DECIMAL(19,8)`、大於 0，人手維護，不分買入／賣出價。期間含首尾，到期日空白表示持續有效；同幣別未刪除的期間不可重疊（`MD.EXCHANGE_RATE.OVERLAP`），檢查條件為「其他.生效日 ≤ 本.到期日（或無到期日）且（其他.到期日為空或 ≥ 本.生效日）」。本位幣不設匯率，查詢固定回 1；公司未設本位幣、或幣別停用時不可新增匯率。幣別與匯率的維護共用公司級 applock `md_currency`，避免並行時兩筆期間重疊或匯率落在被更換的本位幣上。單據保存自己的成交匯率與本位幣金額（MASTER_PROMPT 6.6），所以修改或刪除匯率不回溯；停用幣別仍可查詢歷史匯率。其他模組只經 `ICurrencyLookup` 取匯率，不讀 `md_` 表。查看用 `MD.CURRENCY.VIEW`，維護匯率用 `MD.CURRENCY.EDIT`。
19. 稅別沿用分類代碼規則（第 5–7 條），另有類型：銷項（Output）、進項（Input）或兩者（Both）。稅率屬於稅別，以百分比表示（0–100，最多 4 位小數，0 表示零稅率），期間含首尾、到期日空白表示持續有效；同稅別未刪除的期間不可重疊（`MD.TAX_RATE.OVERLAP`，條件同第 18 條），在公司級 applock `md_tax_code` 內檢查。只能為啟用稅別新增稅率；有稅率或被單據使用的稅別不可刪除（`MD.TAX_CODE.IN_USE`）只可停用。單據保存自己的稅率與稅額，修改或刪除稅率不回溯（ADR-038）；但已有單據的期間不可回溯改變：使用方實作 `ITaxCodeUsage`，改百分比檢查整個原期間，只改期間檢查不再涵蓋的頭尾，刪除檢查整個期間（`MD.TAX_RATE.IN_USE`，ADR-049）。`ITaxRateLookup` 預設拒絕停用稅別（`MD.TAX_CODE.INACTIVE`），重算歷史單據時傳 `includeInactive`；維護頁的查詢與試算 API 可查停用稅別。
20. 稅額只在明細行計算，表頭稅額 = 明細加總。含稅與否由單據決定：未稅時「稅額 = 取整（未稅 × 稅率 ÷ 100）、含稅 = 未稅 + 稅額」；含稅時「未稅 = 取整（含稅 × 100 ÷（100 + 稅率））、稅額 = 含稅 − 未稅」，以差額求稅額使三者恆等。取整一律 `Money.Round`，精度取自該幣別在幣別主檔的小數位，不在主檔回 `MD.CURRENCY.NOT_FOUND`（ADR-049）；退貨負數對稱。查詢稅率要指明方向：銷售用 Output、採購用 Input，類型不符回 `MD.TAX_RATE.DIRECTION_MISMATCH`。其他模組只經 `ITaxRateLookup`（`GetRatePercentAsync`、`CalculateAsync`）取稅率，不讀 `md_` 表。查看用 `MD.TAX_CODE.VIEW`，維護稅率用 `MD.TAX_CODE.EDIT`。
21. 會計科目代碼只用數字（1–30 位），公司內永久唯一且不可修改；子科目代碼必須以上層代碼開頭且較長（`MD.ACCOUNT.CODE_PREFIX`）。上層與類別建立後固定；子科目類別與上層相同（`MD.ACCOUNT.TYPE_MISMATCH`），可省略而沿用。類別有資產、負債、權益、成本、收入、費用；借貸方向省略時資產／成本／費用為借方，其餘為貸方，可指定相反方向表示備抵科目。只能在啟用上層下新增子科目；有啟用子科目不可停用，上層停用時不可啟用子科目；有子科目不可刪除。可過帳 = 啟用且沒有子科目（ADR-039）。
22. 科目是否「已被使用」由使用方模組（FI 傳票、期初餘額等）實作 `IAccountUsage` 判斷，MD 不讀 `gl_` 等表：已使用的科目不可刪除、不可改借貸方向（`MD.ACCOUNT.IN_USE`），也不可再分子科目（`MD.ACCOUNT.PARENT_IN_USE`）。其他模組只經 `IChartOfAccounts` 讀科目，過帳前呼叫 `RequirePostableAsync`。維護在公司級 applock `md_account` 內序列化。
23. 結算方式沿用分類代碼規則（第 5–7 條），是收付款明細的「怎麼付」（現金、轉帳、支票等），不綁定資金帳戶；單據另選資金帳戶。已被引用（使用方實作 `ISettlementMethodUsage`）的結算方式不可刪除（`MD.SETTLEMENT_METHOD.IN_USE`），只可停用；新單據經 `ISettlementMethodLookup.RequireActiveAsync` 只能選啟用的結算方式（ADR-040）。
24. 付款條件沿用分類代碼規則，到期規則三選一：`NetDays` 單據日 + N 天（0 = 即期）；`ClosingDays` 月結 N 天 = 結帳日 + N 天；`ClosingMonthDay` = 結帳日後第 M 個月的 D 日（M = 0 時 D 須晚於結帳日）。結帳日 1–31（31 = 月底）：單據日不晚於當月結帳日屬當期，否則屬下月；結帳日或付款日大於當月天數時取月底。單據保存付款條件代碼與算出的到期日，修改條件不回溯，所以被引用後仍可修改規則，但不可刪除（`MD.PAYMENT_TERM.IN_USE`）；停用的條件不可再試算（`MD.PAYMENT_TERM.INACTIVE`）。其他模組只經 `IPaymentTermLookup` 讀取與試算，不讀 `md_` 表（ADR-040）。
25. 資金帳戶分 Cash／Bank；幣別建立後固定、現金帳戶不存銀行欄位，對應總帳科目可空但若設定只能是同公司啟用且可過帳的資產科目。收支類別方向 Income／Expense 建立後固定；收入科目限收入、支出科目限費用或成本。設定科目與科目維護共用 `md_account` 公司級鎖，引用保護經 `IAccountUsage`；幣別被帳戶使用時不可刪除。交易、流水、期初與餘額歸 FI；FI 只經 MD Contracts 讀取主檔（ADR-041）。
26. 工序分兩層：單層的工序類別 → 工序。兩者沿用分類代碼規則（第 5–7 條），名稱可重複；排序號 0–9999，列表與 PP 下拉按排序號再按代碼。工序的類別與計件單位可空，設定或變更時必須是同公司啟用資料，未變更時不重新檢查；標準計件工價以本位幣計、≥ 0、最多 6 位小數，只是單據預設值，PP 單據須保存實際工價，修改不回溯。有工序的類別不可刪除（`MD.PROCESS_CATEGORY.HAS_PROCESSES`）；被工序使用的單位不可刪除；被 PP 引用（`IProcessUsage`）的工序只可停用。PP 只經 `IProcessLookup` 讀取（ADR-042）。
27. 客戶聯絡人與送貨地址是客戶的子資料，逐筆維護、軟刪除，查看用客戶查看權限、維護用客戶修改權限；停用的客戶仍可維護。每位客戶最多一位預設聯絡人、一筆預設地址（不強制至少一筆）；設為預設時自動取消原預設，預設必為啟用且未刪除，刪除時自動取消預設。聯絡人姓名可重複，電郵須為單一合法地址。SD 單據保存聯絡人與地址快照，修改或刪除不回溯（ADR-043）。
28. 客戶匯入以固定英文鍵 xlsx／UTF-8 CSV，一列一位客戶；預覽唯讀。提交在公司級 `md_customer_import` 鎖及單一交易內重做全部驗證，錯誤列使整批拒絕。已存在本公司代碼（含停用及軟刪除）略過、不更新；檔內重複代碼報錯；分類只按本公司啟用分類代碼對應。聯絡人及地址若出現即各建立一筆預設資料，欄位沿用一般維護驗證。最多 2 MB、1,000 列；詳細格式及例外見 ADR-044。
29. 供應商聯絡人規則同第 27 條的客戶聯絡人（查看用供應商查看權限、維護用供應商修改權限，最多一位預設，軟刪除）；供應商沒有地址子資料。PUR 單據保存聯絡人快照（ADR-043）。
30. 供應商匯入規則同第 28 條，鎖為 `md_supplier_import`，權限 `MD.SUPPLIER.IMPORT`；每列最多帶一位預設聯絡人，沒有地址欄（供應商無地址子表，ADR-043），檔內地址等未知欄位忽略。
31. 物料圖片存在資料庫，類型以檔案內容判斷（只接受 PNG、JPEG，與公司 Logo 共用 `ImageInspector`），每張 2 MB、寬高 16–4096 像素、每物料最多 10 張；伺服器不解碼影像、不產生縮圖。有圖片的物料恰好一張主圖：第一張自動為主圖；設定新主圖時取消原主圖；不可直接取消主圖；刪除主圖時由排序號最小（相同時 id 最小）者接任。上傳、修改、刪除以公司級 `md_item_image` 鎖序列化；刪除為實體刪除，稽核記錄 DELETE。查看用物料查看權限、維護用物料修改權限，停用物料仍可維護（ADR-045）。
32. 物料屬性分兩層：公司級屬性定義（代碼永久唯一、名稱、排序號 0–9999、啟用）與物料屬性值（同一物料同一屬性一個值，自由文字最多 200 字）。物料的屬性值以完整集合整批取代，每物料最多 50 個；新設定的屬性必須啟用，原有值的屬性停用後仍可保留；被任何物料使用的屬性不可刪除，只可停用；列表顯示使用的物料數。取代與屬性刪除共用公司級 `md_item_attribute` 鎖；值為實體刪除，稽核記錄 DELETE。查看物料屬性用物料查看權限、修改用物料修改權限，停用物料仍可維護。屬性不產生 SKU 變體（ADR-045）。
33. 物料匯入沿用 ADR-044 的 xlsx／UTF-8 CSV、2 MB／1,000 列、唯讀預覽、實際列號、錯誤整批拒絕、公司鎖與交易規則；鎖名 `md_item_import`。既有本公司代碼（含停用）略過、不覆寫；檔內重複代碼報錯。`baseUomCode` 必填，單位／品牌／分類代碼只接受本公司啟用資料；規格最多 500 字。預覽後參照被停用時，提交重新驗證並回 422，前端需重新預覽。僅建立物料主檔，不匯入期初庫存、圖片、屬性或專屬換算。
34. 新客戶及匯入客戶為 Pending，不可作交易；既有客戶在 migration 轉 Approved。送審以 `MD.CUSTOMER` 交 SYS，沒有適用步驟立即 Approved；最終核准／駁回由 SYS 交易內回呼更新本表，Rejected 可再送審。交易使用方只透過 MD 服務檢查 Approved 且啟用。待審時不可刪除；已被單據引用時由使用方 `ICustomerUsage` 拒絕刪除，僅能停用。軟刪除保留代碼及審計（ADR-046）。
35. 供應商審批與刪除與第 34 條客戶規則相同：新供應商及匯入供應商為 Pending，既有供應商在 migration 轉 Approved；送審以 `MD.SUPPLIER` 交 SYS，Rejected 可再送審；交易使用方（PUR 等）只透過 `ISupplierLookup` 檢查 Approved 且啟用；待審不可刪，被單據引用時由使用方 `ISupplierUsage` 拒絕刪除，僅能停用；軟刪除保留代碼及審計。客戶與供應商共用審批與刪除實作，錯誤碼前綴即 SYS 單據類型（ADR-046）。
36. 客戶與供應商可設定可空的預設付款條件與預設結算方式，必須為同公司未刪除資料；新選取時須啟用，已停用的現值可保留。匯入不設定預設值。SD／PUR 經 `ICustomerLookup`／`ISupplierLookup` 取得預設代碼後，再以付款條件與結算方式契約驗證是否仍啟用並計算到期日；單據保存自己的代碼與到期日，修改往來對象預設值不回溯。被任何未刪除往來對象設為預設的付款條件或結算方式不可刪除，只可停用（ADR-047）。
37. 審批中的客戶／供應商不可修改：主檔為 Pending 且 SYS 最近一次審批實例仍為 Pending 時，修改回 422 `{前綴}.APPROVAL_PENDING`，確保審批人核准的代碼與名稱快照與主檔一致。從未送審、已撤回或已駁回的資料可修改；核准後的維護不需重審，由 EDIT 權限與資料稽核控制（ADR-048）。刪除同理：只有審批中的資料不可刪（第 34–35 條的「待審不可刪」指審批中），從未送審或已撤回的待審資料（例如匯入錯誤）可刪；送審會遞增版本，與並發的刪除以樂觀鎖互斥（ADR-048 補充）。
38. 被引用主檔（分類、品牌、單位、付款條件、結算方式、幣別等）的刪除在公司級 applock 排他鎖內檢查引用並保存；寫入引用的維護在驗證到保存期間持有同名共享鎖，兩者互斥，避免並發時留下指向剛軟刪除資料的引用（ADR-048 補充）。
39. 物料有庫存追蹤方式：只按數量（None，預設）、批號（Lot）、序號（Serial）。追蹤方式決定 INV 入出庫是否須採集或核對批號／序號，MD 不存任何批號、序號或數量。任何使用方 `IItemUsage` 回報物料已有庫存、交易或單據後，不可改變追蹤方式，只能另建新物料；改變時持有 `md_item` 公司排他鎖到提交，INV 寫入端在驗證到保存期間持有同名共享鎖並經 `IInventoryReferenceGuard` 取得追蹤方式，避免檢查完使用後才出現第一筆無批號的異動。匯入建立的物料一律為 None（ADR-060）。
40. 客戶及供應商列表的搜尋條件以最後一次提交值為準；編輯輸入中的文字不影響分頁或重試。列表請求失敗時不得顯示空資料提示，以免把載入失敗誤認為沒有記錄；操作失敗的訊息與列表失敗分開（WU-MD-027b1）。
41. 物料及計量單位列表沿用第 40 條搜尋提交與錯誤區分規則；單位列表失敗不影響獨立的換算列表及試算，物料列表遷移不得影響換算、圖片、屬性與匯入對話框（WU-MD-027b2）。
42. 倉庫、幣別、稅別列表沿用第 40 條搜尋提交與錯誤區分規則。搜尋只在提交時去除前後空白並套用；分頁、排序與重試繼續使用已提交值；排序僅接受 code、name。列表失敗時保留明確錯誤及重試入口，不把空資料當成成功；儲位、匯率、稅率及試算入口維持原權限和行為（WU-MD-027b3）。
