# PUR 業務規則

WU-PUR-005f3b 前端沿用 BR-PUR-016 的不可變報價：首版只使用已發送詢價的保存行及受邀供應商，修訂以目前版為起點且明確傳保存版本。每次成功只依 API 已保存結果更新畫面；撤回不刪修訂。409 保留未存值並要求確認重載；422／404 不沿用可能失效的舊詳情。逐行價格以字串發送以避免瀏覽器浮點轉換。

| ID | 規則 | 需求 |
|---|---|---|
| BR-PUR-001 | 請購是需求提議；建立、編輯、送審、核准均不改庫存。只有後續採購入庫經 INV 公開 Application 契約寫異動。 | REQ_F4114.3.2, REQ_F4114.3.4 |
| BR-PUR-002 | SYS 單號在建立交易內分配；同公司永久唯一，即使軟刪也不重用。 | REQ_F4114.3.2, REQ_F4114.3.6 |
| BR-PUR-003 | 僅草稿或修訂後的駁回單可編輯；保存時重新驗 MD 引用的公司、啟用和軟刪狀態。舊版本回 409。 | REQ_F4114.3.3 |
| BR-PUR-004 | SYS 最終核准與請購狀態轉換同交易；駁回保存意見及歷史，不建立下游單據。 | REQ_F4114.3.4, REQ_F4114.3.5 |
| BR-PUR-005 | 後續採購單只可引用同公司已核准請購行；多張採購單累計不得超過請購量，取消轉單才可釋回。此切片先定上限，轉單細節由 WU-PUR-006 實作。 | REQ_F4114.3.1, REQ_F4114.3.4 |
| BR-PUR-006 | 無權限回 403、他公司單回 404；列表按公司先過濾。成功提示只在真實建立／更新／刪除後顯示。 | REQ_F4114.3.1, REQ_F4114.3.6 |
| BR-PUR-007 | 請購 Application 進入點必須有正數目前公司；缺公司或無效 ID 回 403。載入指定請購後再核對表頭公司，不同公司只回 404。002 實體查詢仍須受 EF Global Query Filter 限制。 | REQ_F4114.3.1～6 |
| BR-PUR-008 | VIEW 查詢先套用 SYS 有效授權資料範圍；本人以請購人判斷，部門／分店以保存時歸屬判斷，無相應組織歸屬時降為本人。範圍外詳情回 404；建立時歸屬須取 SYS 當前授權。 | REQ_F4114.3.1～3 |
| BR-PUR-009 | 建立草稿時忽略請求內的請購人、分店及部門值，只接受 SYS 目前公司授權的用戶與組織歸屬；驗證輸入與 MD 物料後，在同一交易取 SYS 單號並保存整單，失敗則整單及流水號回滾。 | REQ_F4114.3.2 |
| BR-PUR-010 | 修改與刪除按各自 EDIT／DELETE 資料範圍定位；範圍外一律 404，版本不符 409。修改在單一交易中先驗新行與 MD 物料再整組替換，駁回修訂回草稿；僅草稿可軟刪，兩者均不寫 INV。 | REQ_F4114.3.3, REQ_F4114.3.6 |
| BR-PUR-011 | 送審只接受目前公司、SUBMIT 資料範圍內的草稿及目前版本。重驗所有已保存物料後，在同一交易設待審並建立 SYS 審批實例；SYS 若立即核准則同交易設已核准。失敗一律回滾，且不寫 INV 異動。 | REQ_F4114.3.4 |
| BR-PUR-012 | SYS 人工最終核准／駁回只接受同公司且仍待審的請購；SYS 實例、逐步意見與 PUR 狀態在同一交易保存。單據狀態已變時回 409 並回滾決定，修訂後新送審建立新輪次，舊意見保留。 | REQ_F4114.3.1, REQ_F4114.3.4, REQ_F4114.3.5 |
| BR-PUR-013 | CSV 僅對同時具有 VIEW 與 EXPORT 的目前公司用戶顯示；列表與每張詳情仍由伺服器依 VIEW 資料範圍查詢。客戶端逐頁讀取並檢查總筆數與唯一 ID，完整讀取每張已保存明細後才下載；最多 10000 明細行。公式前導字元需轉義；取消、篩選／公司改變、資料變動或任一讀取失敗不輸出部分檔。 | REQ_F4114.3.1 |
| BR-PUR-014 | 詢價只向 1～50 個不同有效供應商邀請，發送時凍結行與名單；不寄外部 email、不改庫存、不消耗請購餘量。SYS 單號與整單保存同交易，草稿軟刪不重用號碼。 | REQ_F4114.4.2～6 |
| BR-PUR-015 | 詢價來源只能是同公司已核准請購行；詢價量可重複比較，但單次不得超過目前未轉採購量。詢價沒有預留權，採購單提交時才再次驗剩餘量。 | REQ_F4114.4.2, REQ_F4114.6.3 |
| BR-PUR-016 | 報價只屬於發送時受邀供應商；詢價關閉後不收新報價。報價修訂以不可變版本保存，撤回或過期版不可決標；引用後的歷史永不覆寫。 | REQ_F4114.5.1～4 |

| BR-PUR-017 | 比價以同一詢價、同一基本單位數量和報價有效期為前提。原幣單價與依 MD 有效匯率換算的本位幣含稅總成本分欄展示；缺匯率或稅率時該報價不可排序或決標，不暗用 1:1。展示匯率日期與來源。 | REQ_F4114.6.1～2 |
| BR-PUR-018 | 決標逐行選一個有效報價並保存理由、原幣單價、稅率、匯率與本位幣比較值快照；更新以版本與唯一約束守衛，重複選同一詢價行不得覆寫。 | REQ_F4114.6.2 |
| BR-PUR-019 | 轉單只組合同一供應商已決標未轉的行，在單一 SQL 交易建立採購單草稿、來源連結及永久唯一單號；任一行衝突整批回滾，不顯示部分成功。訂單後續提交時才按 BR-PUR-005 消耗請購量，採購入庫才經 INV 契約寫庫存。 | REQ_F4114.6.3 |
| BR-PUR-020 | VIEW／CREATE／EDIT／DELETE／SEND／CLOSE／QUOTE／COMPARE／AWARD／CONVERT 各自按 SYS 目前公司授權及資料範圍檢查；範圍外單據 404。0 筆、全部拒絕或無資料變更時不得顯示成功訊息，失敗需列明行及原因。 | REQ_F4114.4.1～6, REQ_F4114.5.1～4, REQ_F4114.6.1～3 |
| BR-PUR-021 | 詢價 CSV 按 VIEW + EXPORT 顯示；按已套用條件讀完所有分頁及每張保存詳情才下載，核對總筆數、唯一 ID、版本，最多 10000 明細行，UTF-8 BOM 並防公式執行。取消、離頁、換公司／條件、0 行、超上限、重複或任何讀取錯誤均不下載部分檔；超限及早停止後續詳情讀取。列印每次重新 GET 保存詳情，不使用舊畫面快照，列印媒體白底黑字。 | REQ_F4114.4.1 |

WU-PUR-005e4 契約細化：轉單只接受明確列出的 1～1000 個不同決標 ID，全部須屬同公司、同詢價、同供應商、同原幣且未轉；不得將無效行靜默略過。訂單行複製決標的數量、原幣單價、稅率、匯率與本位幣金額快照，不以轉單日 MD 主檔重估。來源唯一連結、SYS 單號、訂單行及詢價版本在一個交易內原子提交；取消後來源證據仍保留，重轉規則待 006 決定。轉單階段不改請購已轉量或庫存。此段目前是設計契約，尚未實作。

WU-PUR-005f1 呈現 BR-PUR-014／020 的唯讀保存資料。所有列表／詳情由後端授權與資料範圍決定；前端換公司後不可留著上一公司的詳情。空資料、無搜尋結果、載入失敗各用獨立文案，不顯示寫入成功訊息。

WU-PUR-005f3a 呈現 BR-PUR-016／020 的報價唯讀歷史：報價是否過期由 GET 回應即時計算；Withdrawn 與 Awarded 仍列入列表，全部修訂都保留原本日期、行價、幣別及稅率 ID。畫面不得把歷史價重新取整，且切換公司、篩選、頁碼時不得留下舊詳情。

WU-PUR-005e3 落地 BR-PUR-018：決標先鎖詢價表頭並確認 AWARD 動作範圍、詢價版本及 Sent 狀態，再依當日 MD 公開匯率／進項稅率快照重算選中報價行。已決標行不能覆寫，詢價表頭每次決標遞增版本；報價標記 Awarded，歷史修訂仍不可變。決標與報價狀態同一交易保存，任何不可比原因或故障不留下部分資料。轉單及請購餘量仍由 005e4／006 處理。

WU-PUR-005d3 落地：報價首版與修訂要求與詢價完全相同的行集合；寫入時透過 MD 公開契約重驗啟用幣別與報價日有效進項稅率，舊修訂僅新增歷史、不更新。修訂須持有目前表頭版本且當前修訂未過期；整單交易失敗時不保留部分行。

WU-PUR-005d4 落地：撤回須持有目前表頭版本，僅已發送詢價的 Active、未過期報價可撤回；只改表頭為 Withdrawn，歷史修訂及行保持不變。Awarded 為決標流程後續寫入的持久狀態，修訂與撤回均拒絕；過期由 `IClock` 與目前修訂有效日計算，查詢以 `isExpired` 呈現，不新增持久狀態或背景寫入。
