# PUR 業務規則

| ID | 規則 | 需求 |
|---|---|---|
| BR-PUR-001 | 請購是需求提議；建立、編輯、送審、核准均不改庫存。只有後續採購入庫經 INV 公開 Application 契約寫異動。 | REQ_F4114.3.2, REQ_F4114.3.4 |
| BR-PUR-002 | SYS 單號在建立交易內分配；同公司永久唯一，即使軟刪也不重用。 | REQ_F4114.3.2, REQ_F4114.3.6 |
| BR-PUR-003 | 僅草稿或修訂後的駁回單可編輯；保存時重新驗 MD 引用的公司、啟用和軟刪狀態。舊版本回 409。 | REQ_F4114.3.3 |
| BR-PUR-004 | SYS 最終核准與請購狀態轉換同交易；駁回保存意見及歷史，不建立下游單據。 | REQ_F4114.3.4, REQ_F4114.3.5 |
| BR-PUR-005 | 後續採購單只可引用同公司已核准請購行；多張採購單累計不得超過請購量，取消轉單才可釋回。此切片先定上限，轉單細節由 WU-PUR-006 實作。 | REQ_F4114.3.1, REQ_F4114.3.4 |
| BR-PUR-006 | 無權限回 403、他公司單回 404；列表按公司先過濾。成功提示只在真實建立／更新／刪除後顯示。 | REQ_F4114.3.1, REQ_F4114.3.6 |
| BR-PUR-007 | 請購 Application 進入點必須有正數目前公司；缺公司或無效 ID 回 403。載入指定請購後再核對表頭公司，不同公司只回 404。002 實體查詢仍須受 EF Global Query Filter 限制。 | REQ_F4114.3.1～6 |
| BR-PUR-008 | VIEW 查詢先套用 SYS 有效授權資料範圍；本人以請購人判斷，部門／分店以保存時歸屬判斷，無相應組織歸屬時降為本人。範圍外詳情回 404；建立時歸屬須取 SYS 當前授權。 | REQ_F4114.3.1～3 |
| BR-PUR-009 | 建立草稿時忽略請求內的請購人、分店及部門值，只接受 SYS 目前公司授權的用戶與組織歸屬；驗證輸入與 MD 物料後，在同一交易取 SYS 單號並保存整單，失敗則整單及流水號回滾。 | REQ_F4114.3.2 |
| BR-PUR-010 | 修改與刪除按各自 EDIT／DELETE 資料範圍定位；範圍外一律 404，版本不符 409。修改在單一交易中先驗新行與 MD 物料再整組替換，駁回修訂回草稿；僅草稿可軟刪，兩者均不寫 INV。 | REQ_F4114.3.3, REQ_F4114.3.6 |
