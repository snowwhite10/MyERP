# SYS 組織業務規則

1. 公司是資料隔離根。不得將客戶端提供的 `X-Company-Id` 視為授權；正式查詢前必須查核用戶公司權限。
2. 公司代碼全域唯一；分店／部門代碼在公司內唯一。軟刪除後不可重用代碼。
   代碼輸入先去除首尾空白並轉大寫，只允許 1–30 個 ASCII 英文字母、數字、連字號或底線；名稱去除首尾空白後須為 1–200 字元。
3. 部門所屬分店及上級部門必須與該部門同公司；上級鏈不可形成循環。
4. 已有業務資料引用的組織主檔只能停用。停用不改歷史資料；新業務單據不得選取停用組織。
5. 組織修改使用樂觀鎖 `version`；審計欄位由共用 interceptor 填入。
6. 停用部門後不可作為新部門的上級；停用公司後，內部服務不得在該公司建立新分店或部門。

## 用戶及密碼

7. 帳號去除首尾空白，限 3–100 個 ASCII 字母、數字、點、底線及連字號；以大寫正規化值判斷全系統唯一，刪除後也不可重用。
8. 密碼使用 ASP.NET Core Identity `PasswordHasher<SystemUser>`；預設至少 12 字元，須有大小寫、數字與符號，90 天到期。`Security:PasswordPolicy` 可調整長度、複雜度與到期天數；到期天數 0 表示停用到期檢查。
9. 連續錯誤 5 次鎖定 15 分鐘，鎖定期間不驗證密碼；到期後重設失敗次數。成功後清除失敗次數及鎖定期限。登入流程簽發 Token 前須檢查密碼到期。
10. 密碼、雜湊及 Token 不得寫入日誌或 API 回應；用戶 API 只回 `isLocked`／`isPasswordExpired` 布林值。
10a. 用戶管理只涵蓋目前公司有用戶公司關聯的用戶，範圍外 404；建立用戶時同一交易加入目前公司（預設、無角色）；帳號已存在（含他公司）回 409，不會加入本公司；帳號建立後不可修改；不可停用自己；重設密碼另需 `SYS.USER.RESET_PASSWORD`，重新起算到期並清除鎖定（ADR-016）。

## 登入與 Token

11. 登入順序：欄位驗證 → Captcha（一次性，錯誤亦作廢）→ 以正規化帳號查用戶 → `VerifyPasswordAsync`（鎖定與失敗計數）→ 密碼到期檢查 → 簽發 Token。帳號不存在時仍做一次雜湊驗證，使回應時間接近。
12. Access Token 15 分鐘，無狀態，Redis 不可用時仍可使用至到期；Refresh Token 7 天，存 Redis 鍵 `myerp:sys:refresh:{SHA-256}`，值為用戶 Id 與簽發時間，以 Lua 原子取出刪除實現輪替。刷新時用戶須仍啟用且未鎖定，且 Token 簽發時間不得早於 `password_changed_at`；本人修改或管理員重設密碼後，之前簽發的全部 Refresh Token 失效（ADR-029）。
12a. 本人修改密碼須驗證目前密碼；錯誤計入現有鎖定規則，新密碼須不同且符合政策。成功時密碼雜湊、修改時間與稽核同次儲存，回傳新的 Token。到期密碼可用帳密及一次性 Captcha 匿名修改，成功後登入；登入與此入口均在發 Token 前檢查 IP 白名單。稽核不記錄明文密碼或 Token。
12b. 前端收到修改密碼成功回應時，立刻替換 Access／Refresh Token；失敗不改工作階段，清空密碼欄位。到期密碼流程每次失敗後重新取得 Captcha。語言與主題偏好只在目前瀏覽器保存，無跨裝置同步；切換語言同時更新 ng-zorro 與 HTML `lang`，切換主題也更新圖表配色。
13. 簽章金鑰 `Security:Jwt:SigningKey` 至少 32 bytes，不得提交；非 Development 未設定即拒絕啟動，Development 未設定時用程序內臨時金鑰（ADR-012）。
14. Captcha 萬用碼只在 Development 有效；任何其他環境設定了即拒絕啟動。日誌不記錄密碼、Captcha 答案或 Token。
15. 登入類端點按客戶端 IP 限流（固定視窗、不排隊）：login、refresh 每端點 5 次／分鐘，captcha 10 次／分鐘，因每次登入失敗前端會再取一題（ADR-018）。帳號鎖定（5 次 15 分鐘）與 IP 限流互相獨立：前者防止猜同一帳號，後者防止同一來源大量嘗試。
16. 客戶端 IP 是連線 IP；只有 `Security:ForwardedHeaders` 列明的 Proxy 送來的 X-Forwarded-For 才改用轉送的 IP，未設定任何 Proxy 時一律不處理（框架在清單皆空時會信任所有來源，故不啟用）。登入日誌的 RemoteIp 同樣取這個值。

## 角色、權限與資料範圍（ADR-014）

15. 權限代碼 `{PREFIX}.{RESOURCE}.{ACTION}` 全大寫；前綴必須是宣告模組的前綴。各模組在程式中宣告權限，角色只能授予目錄內的代碼；已不在目錄的舊授權忽略。
16. 角色為全系統定義，用戶在每間公司分別指派角色；必須先有該公司的存取關聯（`sys_user_company`），角色才可指派。
17. 有效權限只計算啟用且未刪除的角色、啟用的用戶公司關聯、啟用且未刪除的用戶與公司。全權角色擁有全部權限，資料範圍為全公司。
18. 同一權限由多個角色授予時取最寬的資料範圍：Self < Department < Branch < Company。分店範圍只看同一分店、部門範圍只看同一部門（不含下級），本人範圍只看負責人為自己的資料；用戶缺少對應的分店／部門歸屬時退回本人。
19. 已登入請求帶的 `X-Company-Id` 必須可存取，否則整個請求回 403，不進入端點；沒有公司上下文的請求不具任何權限代碼。
20. 角色仍被指派時不可刪除，只能停用；停用立即生效。角色修改以 `version` 樂觀鎖，權限集合與角色同一交易更新。
21. 每位用戶最多一間預設公司；設定新的預設公司時，同一交易內先取消其他預設。前端未指定公司時使用預設公司（沒有預設時取代碼最小的公司）。

## 組織 API 授權（WU-SYS-001、ADR-015）

- 公司維護只涵蓋用戶獲授權的公司：用戶與用戶公司關聯須啟用，公司可為停用。範圍以外的公司在列表中不出現，修改時回 404。
- 建立公司時，在同一交易內授權建立者：新增非預設的用戶公司關聯，並沿用建立者在目前公司的角色。
- 公司列表預設只列啟用公司，`includeInactive=true` 時一併列出停用公司以便重新啟用。停用的公司不能作為 `X-Company-Id`。
- 分店與部門列表包含停用資料，以狀態標籤區分；新增或修改部門時，只可選目前公司中啟用的分店與上級部門。

## 稽核日誌（WU-SYS-007，ADR-019）

- 業務資料一律經 EF ChangeTracker 修改，由 interceptor 自動寫入稽核，業務代碼不必自行寫入。審批、作廢、過帳以 `IAuditTrail.MarkAction` 標示操作類型。
- 軟刪除記為 DELETE；沒有欄位實際變更的 SaveChanges 不寫稽核。
- 稽核與業務資料同一交易：回滾、失敗或版本衝突都不留下稽核記錄，重試時也不重複。
- 稽核記錄不能修改或刪除，資料庫 trigger 會拒絕。
- 公司只看自己的稽核記錄；用戶登入、登出等沒有公司的安全事件，該用戶所屬的每間公司都看得到。帳號不存在的登入失敗不顯示給任何公司。

## 單號規則（WU-SYS-008，ADR-021）

- 單號 = 前綴 + 單據業務日期按日期格式格式化 + 左補零的流水號。例如前綴 `SO`、`YearMonth`、長度 4、每月重設：2026-10 第一張為 `SO2026100001`，2026-11 重新由 `SO2026110001` 起。
- 流水號按（公司、規則、週期）分開計數；週期鍵依單據日期，不是系統日期。補登上月單據沿用上月的計數。
- 重設週期必須包含在日期格式內：每年重設要有年份、每月要有月份、每日要有日期；否則不同週期會產生相同單號。
- 取號與單據儲存在同一交易：交易回滾時號碼退回，不跳號；交易期間同一規則同一週期的其他取號會等待。
- 已發出單號的規則：日期格式與重設週期鎖定、流水號長度不可縮短；可改名稱、前綴、加長流水號、停用。規則不刪除。
- 流水號超過長度上限（例如長度 3 的第 1000 號）時拒絕取號，需加長流水號長度。
- 每個單據模組的單號欄位使用 `VARCHAR(30)`，並以 `(company_id, 單號)` 唯一索引作最後防線。
- 舊系統（BlueWhale）以單一函式按單據類型組號；MyERP 改為可按公司設定的規則，並以資料庫原子更新保證併發不重號。

## 審批流程（WU-SYS-009，ADR-022）

- 每間公司每個單據類型最多一條審批流程，步驟 1–10 個，依次序逐級審批。步驟的審批人是一個角色（目前公司任一擁有該啟用角色的啟用用戶都可處理，一人處理即可）或一位指定用戶。
- 金額門檻：步驟可設最低金額，送審金額（本位幣）≥ 門檻才需經過該步驟；沒有門檻的步驟一律需要。例如「主管（全部）→ 經理（≥ 10,000）→ 總經理（≥ 100,000）」，5,000 只需主管，250,000 需三級。
- 沒有啟用中的流程，或金額未達任何步驟的門檻：送審即自動核准，仍建立一筆已核准的實例作記錄；此時不呼叫結果處理器，送審模組依回傳狀態直接處理。
- 送審時把適用的步驟複製成實例步驟並重新編號（1…n）。之後修改或停用流程，不影響審批中的實例。
- 同一單據同時只能有一個審批中的實例（資料庫篩選唯一索引保證，併發送審只有一個成功）；駁回或撤回後可再次送審，舊實例保留作歷史。
- 職責分離：送審人不可審批自己送審的單據（`SELF_APPROVAL`），流程設定「允許自審」除外；設定在送審時複製到實例。自己送審的單據不出現在自己的待辦。
- 核准目前步驟後進入下一步；最後一步核准即「已核准」。任一步駁回即「已駁回」，必須填寫意見，其餘步驟標記為「略過」。撤回亦把未處理的步驟標記為「略過」。
- 審批代理：被代理人可在起訖日期內（含頭尾，以業務日期 `IClock.Today` 判斷）把審批工作交給代理人；代理人可處理被代理人的用戶步驟與其角色步驟，記錄上同時保存實際處理人與被代理人。代理不連鎖（代理人的代理人不能處理）。兩人都必須是公司的啟用用戶；同一被代理人的啟用代理期間不可重疊。
- 停用的角色、停用的用戶或停用的公司授權不能處理步驟。
- 併發：核准／駁回帶實例 `version`，兩位審批人同時處理同一步驟時只有一位成功，另一位得到 409（或已完成 422）。
- 結果分派：最終核准或駁回時，在同一交易內、儲存前呼叫該單據類型的 `IApprovalResultHandler`，由單據模組更新自己的單據；處理器失敗，整個審批動作（含步驟記錄）回滾。SYS 不讀寫其他模組的資料表。
- 稽核：審批實例的修改以 `APPROVE`／`REJECT` 記入 `sys_audit_log`，與審批動作同一交易；流程、代理、實例步驟的變更亦自動記錄。
- 舊系統（BlueWhale）每種單據只有單級「審核」；MyERP 以共用引擎提供多級、金額門檻與代理，BlueWhale 各單據的 Approve 功能將由各模組經本引擎實現。

## IP 白名單（WU-SYS-006，ADR-025）

- CIDR 必須是網段基址；單一 IP 正規化，IPv4 對映 IPv6 可匹配 IPv4 規則。有效日期含頭尾，以 `IClock.Today` 判斷。
- 同層規則任一符合即通過；全系統、用戶及每個有效角色各層都要通過。匿名請求只檢查全系統。沒有有效規則時放行；有規則而連線 IP 缺失時拒絕；loopback 永遠通過。
- 角色取自用戶在任何啟用公司的啟用角色；停用角色／公司授權不生效。總開關從設定載入，Development 預設關閉，健康檢查例外。可信代理由 ForwardedHeaders 決定連線 IP。
- 規則停用代替刪除，修改帶版本；同對象相同網段只能有一筆（包含停用者）。拒絕回 403、記 Warning 與 `IP_DENIED` 安全稽核，每 IP／用戶每分鐘最多一筆。

## 種子資料（WU-SYS-013，ADR-023）

- 種子只在 Development 執行，而且要明確下指令（`--seed`）；正式環境沒有種子帳號。
- 冪等：以公司代碼、（公司、分店／部門代碼）、角色代碼、帳號比對，只新增缺少的資料，不修改既有資料。
- 種子角色的權限是規則，不是固定清單：每次執行都對照目前的權限目錄，補上符合規則但缺少的權限；不移除額外加入的權限。
- 示範密碼是公開值，刻意不套用密碼政策；帳號 `hr` 低於管理 API 的 3 字元下限，也是刻意例外。
- 每個種子帳號可存取兩間示範公司，預設 TW01；分店為各公司的第一間（總公司），部門依角色（例如 finance → FIN）。

## 系統參數（WU-SYS-010a，ADR-026）

- 參數由所屬模組宣告，SYS 只負責保存與畫面。鍵的前綴必須屬於宣告的模組，例如負庫存開關由 INV 宣告為 `INV.*`。
- 參數值按公司分開。未修改過的參數使用宣告的預設值，資料庫不存這一列；新模組加參數時不需補資料。
- 保存時先檢查全部項目，任何一項錯誤就整批不保存。每項帶讀取時的版本，防止覆蓋他人的修改。
- 數量與單價小數位數只限制輸入與顯示的位數，上限受資料庫欄位精度限制（數量 4 位、單價 6 位）。降低位數不會改寫已保存的單據。金額的位數仍由幣別決定（`Money.Round`）。
- 舊系統（BlueWhale）以單一表的固定欄位保存，沒有範圍與權限檢查；MyERP 改為模組宣告、型別驗證與權限控制。舊系統的「啟用審批」改由審批流程設定決定，第三方整合金鑰不放進參數。

## 列印設定（WU-SYS-010c，ADR-027）

- 列印設定是 SYS 在 `print` 分組宣告的系統參數，按公司保存；權限、版本、批次驗證與稽核都與系統參數相同。
- 列印抬頭的公司名稱留空時，列印公司主檔名稱。其他抬頭欄位與頁尾留空則不列印。
- 採購單與銷售出貨單的頁尾備註由 SYS 統一設定，PUR／SD 列印時經 `IPrintSettingsReader` 讀取，不直接讀參數或公司表。
- 是否列印 Logo／印章只是開關；圖片由 WU-SYS-010d 上傳。沒有上傳圖片時，列印模組應略過，不應報錯。
- 舊系統每間分店一組列印設定；MyERP 按公司設定（分店共用公司抬頭）。

## Logo 與印章（WU-SYS-010d，ADR-028）

- 每間公司最多一張 Logo、一張印章，存在資料庫（`sys_company_image`）；分店共用公司的圖片。
- 只接受 PNG 與 JPEG，以檔案內容判斷類型；副檔名或瀏覽器宣告的類型不算。SVG 等可內嵌腳本的格式一律拒絕。
- 檔案上限 1 MB，寬與高各 16–2048 像素。
- 替換與刪除要帶讀取時的版本；兩人同時修改時後者收到 409，需重新載入。
- 權限沿用系統參數（`SYS.PARAMETER.VIEW／EDIT`）。新增、替換、刪除都寫稽核，圖片內容只記錄位元組數。
- 是否列印由 `SYS.PRINT_SHOW_LOGO`／`SHOW_STAMP` 控制（ADR-027）。列印模組經 `ICompanyImageReader` 讀取；開關開啟但沒有上傳圖片時略過，不報錯。

## 站內通知（WU-SYS-012，ADR-031）

- 發布時以目前公司為隔離單位；公司與用戶公司關聯都必須啟用，用戶也須啟用。發布端只引用 SYS Contracts。
- 每筆通知只有一名收件人。來源鍵應由模組、單據 Id、事件及步驟組成，同公司與收件人下唯一；重試查得同一 Id，不再新增通知。
- `TargetPath` 只接受單斜線開頭的站內路徑，不能為協定相對 URL、外部網址或含反斜線。通知文字不含 HTML 格式。
- 寫入時 `read_at = null`、`expires_at = IClock.LocalNow + 90 天`。收件箱、未讀數、已讀操作只處理 `expires_at > IClock.LocalNow`；日期顯示跟隨既有 UTC+8 規則。每日背景作業跨公司只刪除過期通知；失敗記錄日誌並在下次執行重試。
- 收件箱只顯示本人資料，示範種子讓每個業務角色都有 `SYS.NOTIFICATION.VIEW`／`READ`（與本人審批待辦相同）；正式角色由管理員在角色權限設定。
