# INV 優化記錄

| 日期 | 問題 | 原因 | 改進 | 效果 |
|---|---|---|---|---|
| 2026-10-13 | 初始模組尚無資料表或業務 API | 庫存交易需要先決定統一狀態與異動規則 | 只註冊權限與領域狀態守衛；資料表與過帳服務留給 WU-INV-003 | 避免空 API 與暫時性資料表；架構及狀態測試可先驗證邊界 |
| 2026-10-13 | 儲位刪除在鎖外檢查 Usage 並保存 | INV 寫入可在檢查與保存之間引用儲位 | 刪除全程取 `md_warehouse` 排他鎖；MD 引用守衛持共享鎖 | SQL 整合測試檢查鎖在提交前不釋放 |
| 2026-10-13 | Usage 若反查 MD 主檔會破壞模組邊界 | MD 刪除時只能詢問 INV，不能讓 INV 為回答再依賴 MD 查詢 | `inv_reference` 同筆保存不可變代碼快照，Usage 只查 INV 表與公司索引 | MD 刪除與 INV 寫入在兩種提交順序下分別得到 409／404，無懸空引用 |
| 2026-10-13 | 全量回歸的兩個 SYS 案例受共用資料影響 | 系統白名單規則與種子帳號雜湊在測試結束後仍留於共用 SQL 資料庫 | 在案例的 `finally` 停用新增白名單規則、還原原雜湊並刪除新增授權；保留原斷言 | Release 建置 0 警告，全量後端 773/773 通過 |
| 2026-10-13 | 過帳數值驗證對 `decimal.MinValue` 呼叫 `Math.Abs` 會溢位 | 絕對值超出 `decimal` 正數範圍 | 改以正負界限比較，加入極小值資料列 | 非法輸入一致回 400 驗證錯誤；避免未處理溢位 |
| 2026-10-13 | 並發出庫及純入庫需要不同鎖粒度 | 所有鍵一律取排他鎖會讓不影響超賣的入庫互相阻塞 | 只對有出庫的結存鍵依物料／倉庫／儲位排序取鎖，入庫仍與同來源鎖互斥 | 雙連線出庫測試阻止超賣；純入庫不競爭結存鍵 |
# WU-INV-004 設計審查（2026-10-13T17:42:52+08:00）

| 審批核准與入庫可能分兩次提交 | SYS 處理器與 INV 過帳均會保存 DbContext | ADR-054 規定立即核准與最終處理器均使用同一交易，失敗全數回滾 | 待 INV-REC-003／004 真實 SQL 驗證 |
