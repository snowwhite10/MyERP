# WU-INV-004a 檢查與優化（2026-10-13T18:05:22+08:00）

| 問題 | 原因 | 調整 | 效果 |
|---|---|---|---|
| 送審或編輯失敗後，同一 DbContext 仍追蹤已回滾的單據、SYS 審批實例或異動 | EF 不會因交易回滾而還原追蹤狀態 | 服務的交易包裝在回滾後 `ChangeTracker.Clear()`，`DbUpdateConcurrencyException` 轉 409 | 停用物料造成的過帳失敗後，單據仍是草稿、版本不變，無引用或異動殘留（INV-REC-004） |
| 多行引用相同物料／倉庫／儲位時重複取 MD 鎖與查詢 | 逐行呼叫 guard | 依 (物料, 倉庫, 儲位) 去重後各驗證一次 | 每張單據的 MD 查詢次數與不同組合數成正比，而非行數 |
| 只改明細時表頭版本不遞增 | 表頭欄位值未變，EF 不產生 UPDATE | 編輯時強制標記狀態欄位為已修改 | 並發的送審以舊版本失敗；雙連線測試只一方成功 |

| 測試以 `IgnoreQueryFilters()` 檢查無殘留時會看到其他公司資料 | 無參數版本同時移除公司篩選 | 改用 `IgnoreQueryFilters([ErpQueryFilters.SoftDelete])` | 斷言只針對本公司，平行測試不互相干擾 |
