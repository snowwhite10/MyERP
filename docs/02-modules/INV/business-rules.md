# INV 業務規則

- BR-INV-001：每筆庫存交易由目前公司隔離，跨公司單據狀態轉換立即拒絕；`inv_reference` 已套用公司篩選，跨模組不建 SQL 外鍵。
- BR-INV-002：數量用基本單位 `decimal(19,6)`；出庫不得造成負庫存；異動帳不可改寫，來源行防重放。
- BR-INV-003：單據狀態依 ADR-051；核准後才能過帳，已過帳以反向單據沖回。
- BR-INV-004：有儲位管理的倉庫要求同公司、同倉庫且啟用的儲位；否則儲位為 null。
- BR-INV-005：引用物料與倉庫時，先取得公司級 `md_item`、`md_warehouse` 共享鎖，再驗證同公司、未刪除且啟用；儲位須屬所選倉庫。鎖持有到寫入交易提交，與 MD 物料／倉庫／儲位刪除排他鎖互斥。使用中檢查須在排他鎖內執行。
- BR-INV-006：INV 來源行以公司與 `source_key` 唯一識別，首次寫入持久化引用 ID 與不可變代碼快照。已被引用的主檔只能停用，不可刪除；歷史引用不因來源作廢而移除。後續庫存寫入方必須先呼叫 `InventoryReferenceService.RecordAsync`，同一交易內寫來源與引用。
- BR-INV-007：來源類型與 ID 在公司內只允許一份異動內容。再次提交相同日期與完整明細回原異動 ID；任何差異回衝突。來源鎖、MD 引用鎖、結存鍵鎖依固定順序取得，持有至交易提交。
- BR-INV-008：同一結存鍵的出庫先取排他鎖，再以已提交異動合計加本次淨額檢查非負；交易失敗時新增引用與異動一起回滾。純入庫只增加結存，無須競爭出庫鍵鎖。
- BR-INV-009：`inv_stock_movement` 的 UPDATE／DELETE 由 SQL trigger 拒絕。現存量即時由方向與正數數量加總；來源單據沖回以新的反向過帳表示。物料基本單位換算由上游單據負責，本服務拒絕超過六位小數的數量。

具體事務與估值規則見 ADR-051；舊系統原始碼只作業務規則參考，不沿用其表結構或程式碼。
