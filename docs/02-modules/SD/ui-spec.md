# SD UI specification (WU-SD-000 proposed)

WU-SD-004a1 adds no UI or `REQ_IO_A` item. WU-SD-004c owns delivery screens and visible balance errors after SQL-backed commands are available.

The first nine interface numbers preserve the reference mapping: 2.1–2.3 quotation View/Create/Edit, 2.4–2.6 order View/Create/Edit, 2.7–2.9 delivery View/Create/Edit; 2.10 is Select Client. SRS 4.4, SRS 4.5 and SDS 4.2 use this same View → Create → Edit sequence. The first deliverable page defines each field's `REQ_IO_A` ID and English Description/Purpose/Format/Range in its implementation unit; WU-SD-000 allocates no interface item IDs for unbuilt controls.

Additional price, invoice, credit and return interfaces append after 2.10 when specified. Every page needs zh-Hant/zh-Hans/en, light/dark, explicit empty/search-empty/no-permission, validation and server/network error states. A disabled action explains the reason; 5xx shows traceId. Success is displayed only after a persisted change. Implementation units use `myerp-ux-review` and `web-design-guidelines` with Playwright screenshots. WU-SD-001 adds no page or dialog; UI acceptance remains with the later page units.

WU-SD-006d credit interaction design only: append a `Customer Credit Check Interface` after existing 2.10 interface allocations when implemented, and show a compact credit panel on Sales Order View/Create/Edit. It labels base currency, effective date, FI limit, posted open AR, approved unbilled SD commitments, candidate order and remaining headroom separately, with an advisory/recheck notice. A numerical refusal shows measured excess and an optional reasoned override action only when the user has both the order action and `SAL.CREDIT.OVERRIDE`; a disabled action explains the missing grant or invalid customer. FI unavailable, limit missing and invalid snapshot each have distinct messages. Never show a preview as an approval or save success. Three languages, light/dark, empty/no-permission, validation, 409, 422, 500/traceId and timeout states are 006c QA gates. Actual interface/`REQ_IO_A` IDs are assigned only with the screen in 006c; this section adds none.

WU-SD-007d invoice interaction design only: append `Sales Invoice View Interface` and `Sales Invoice Create Interface` after existing 2.10 allocations when 007b implements pages, then allocate actual `REQ_IO_A` IDs. View shows permanent number, Posted state, source delivery/order links, saved tax/amount snapshots, FI posting reference and replay status. Create selects only Posted delivery lines from one customer/order/currency, shows saved and already billed quantities with an advisory available balance, and recalculates on submit. The form explains source mismatch, over-billing, stale balance, tax snapshot inconsistency and FI unavailable by line; a disabled ISSUE action gives its reason. An identical retry shows the existing saved invoice as a warning with no new-success toast. A timeout prompts persisted-status lookup by request key. Three languages, light/dark, normal/empty/filtered-empty/no-permission, validation, conflict, FI failure, 500/traceId and network states are 007b QA gates. Each E2E assertion compares visible quantity/amount/status with persisted invoice and FI posting, including zero-change failure. No actual page or item ID is added here.

WU-SD-008d return interaction design only: append `Sales Return View Interface`, `Sales Return Create Interface` and `Sales Return Edit Interface` after earlier interface allocations when 008b implements them; allocate actual `REQ_IO_A` IDs then. View shows source Posted delivery, original outbound movement, new inbound movement, source invoices, FI credit reference, SYS rounds and immutable Posted state. Create/Edit display saved Posted, invoiced, already returned and available six-place quantities; user assigns billed invoice portions and unbilled quantity, selects receiving warehouse/tracking and sees the partition sum. Preview is advisory and has no success toast. Pending explains why editing is disabled; rejected revision retains decision history; Posted offers no edit or direct reversal. A line-specific balance/lot/cost/FI error explains the failed operation; 409 refreshes balances while preserving safe draft input, 500 includes traceId, and timeout checks saved status by request key. Only persisted SD return plus matching INV/FI references merits a success message; replay shows a warning with zero new rows. Three languages, light/dark, normal/empty/filtered-empty/no-permission, validation, success, rejection, conflict, 422, 500 and network states are 008b QA gates. E2E compares visible quantities and money with saved SD/INV/FI data. No actual page, control ID or screenshot is added here.

WU-SD-002d interaction design only: View shows stored status and a separate expired indicator, source order link and SYS history. Create/Edit display server-calculated line net/tax/gross and header totals; save/submit state the exact reference or line that failed. Edit of Rejected explains that saving restarts Draft while retaining earlier approvals. Pending disables edit/delete/void with a reason; Approved enables conversion only while unexpired and unused, and void only while unused. No change toast appears for a conflict or zero persisted rows. WU-SD-002b allocates `REQ_IO_A2.1.*`, `A2.2.*` and `A2.3.*` against actual controls and English SRS item text, then supplies three-language, light/dark screenshots. No item IDs or screen completion are claimed here.

WU-SD-002b0 read-client contract: `SalesQuotationService` exposes the saved quotation list and detail only. List sends page/pageSize and optional trimmed keyword, inclusive `from`/`to`, status, customer ID and whitelisted sort to the server; the server applies company and `SAL.QUOTATION.VIEW` data scope. Detail carries saved line amounts, approval history, current instance and a separate derived `isExpired` flag. Monetary values are display data and must not be recalculated by the browser. The later screen unit owns URL filter state, localized errors, permission/empty states, three-language light/dark review, and persisted-data E2E checks; no interface item ID or screenshot is allocated by this contract unit.

WU-SD-003d order interaction design only: View (2.4) shows saved status, source quote, approval rounds, each line's ordered/delivered/pending/remaining base-unit quantity, monetary snapshots and specific credit result. Create (2.5) offers manual entry or an eligible quote selector; selecting a quote fills all saved lines and marks the commercial snapshot read-only. An unavailable FI/AR credit contract shows a clear block on submit, without suggesting an approval succeeded. Edit (2.6) permits full-line replacement only in Draft/Rejected, displays the saved version and explains that editing Rejected restarts Draft while retaining SYS history. Pending has decision-only actions; Approved cancellation is disabled with a reason when any pending/posted delivery exists. Conflict, invalid reference, credit refusal, 500/traceId and timeout clear false success and keep user-entered draft where safe. WU-SD-003c allocates actual `REQ_IO_A2.4.*`–`A2.6.*` IDs and verifies three languages, light/dark and persisted-result consistency; this design adds no screen or item ID.

WU-SD-004d outbound interaction design only: View (2.7) shows saved Draft/Pending/Rejected/Posted state, each source order line's ordered/Posted/other Pending/available base-unit quantity, saved lot/serial selections, SYS history and INV movement IDs after posting. Create/Edit (2.8/2.9) select an Approved order, warehouse/location and tracking, display six-place balance and recheck on submit; a displayed balance is advisory because concurrent deliveries can change it. Draft gives no stock or order reservation claim; Pending explains its order reservation and why edit/delete are disabled. Rejected may be revised and resubmitted, preserving prior decisions. Posted actions are read-only and point to a future return flow rather than direct reversal. A 409 refreshes balances without claiming success; 422 shows the exact line, warehouse, lot/serial or stock reason; 500 includes traceId, and timeout/network errors require a fresh persisted-state check. Success appears only after the saved state/INV reference confirms change. WU-SD-004c allocates actual `REQ_IO_A2.7.*`–`A2.9.*` IDs and performs three-language, light/dark Playwright QA. No control ID or screen is claimed here.

WU-SD-005d pricing interaction design only: append Sales Price Rule View/Create/Edit Interfaces after 2.10 when pages are implemented; WU-SD-005b allocates their stable interface and `REQ_IO_A` numbers. Rule list shows customer-specific versus default scope, item/currency, inclusive validity, price, discount ceiling, state and version; form validates six/four-place decimals, inclusive dates and overlapping intervals with an exact conflicting rule reason. Quotation and manual-order forms request a dated quote when customer/item/currency/business date changes, show rule source and price/ceiling, and label the calculation as provisional until saved. Manual price or above-ceiling discount exposes reason input only to an actor with `SAL.PRICING.OVERRIDE`; missing permission explains the disabled save. A missing/expired rule offers a clear manual-override path to authorised users, while others see the specific block. Saved documents display immutable price, discount, rule/version, override reason and rounded money snapshot; converted order lines are read-only. 409 stale quote preserves user input and requests a fresh quote; 400/403/422 show field and permission reasons; 500 displays traceId; timeout/network failure never claims success. Rule quote shows no save toast, and successful rule/document write is confirmed from persisted data. Three languages, light/dark and normal/empty/filtered-empty/no-permission/error states are WU-SD-005b QA gates. This unit adds no actual control or screenshot.
