# SD business rules (WU-SD-000 planned baseline)

- BR-SD-001: SD owns quotations, orders, deliveries, invoices and returns. MD supplies customer, item, currency, output-tax and payment references through Contracts. SD stores commercial snapshots and never reads MD tables directly.
- BR-SD-002: SYS owns company-scoped numbering, permissions, data scope and approval decisions. Each SD action checks its own permission and action scope; a VIEW permission is not required for a CREATE/EDIT-only workflow. Every document preserves approval history and audit/version fields.
- BR-SD-003: Quotation conversion is explicit and single-use. The order retains immutable quotation and line source IDs plus price, discount, tax and currency snapshots. Quotation draft or expiry cannot be converted. No quotation action changes stock.
- BR-SD-004: Order approval revalidates current customer and credit through public contracts before SYS final decision. With FI/AR not yet available, approval must fail with a specific unavailable-credit reason; no fabricated exposure or silent bypass. Approval alone does not post INV.
- BR-SD-005: Each delivery line refers to an approved order line; summed posted quantity plus active pending delivery quantity must not exceed ordered base-unit quantity. Lock order lines in ascending ID order and recheck during submit and final approval. Draft does not reserve or post stock.
- BR-SD-006: Final SYS delivery approval, SD Posted state and `IExternalInventoryPostingService.PostSalesOutboundAsync` run in one SQL transaction. SD provides saved item/warehouse/location/basic-unit quantity/tracking, never sales price as cost. INV owns negative-stock, serial/batch, duplicate-source and ledger rules (BR-INV-040–042); a failure rolls back every module's changes.
- BR-SD-007: Rejection releases any delivery reservation once; repeated decision or retry cannot post twice. Posted delivery is immutable. Corrections use a new return/reversal source, never direct INV aggregate updates. Return source type requires an explicit future INV contract extension.
- BR-SD-008: Monetary lines use decimal, saved output tax and currency rate effective on business date, and `Money.Round` at currency precision. Sum already rounded line values for header totals. Existing snapshots never change because a master rule changes.
- BR-SD-009: Invoices cover only posted, uninvoiced delivery quantity. SD owns commercial invoice; FI owns receivable/posting and consumes SD via its public interface when available. SD must not write FI tables. Credit exposure likewise comes from FI/AR, never from direct reads.
- BR-SD-010: All writes are whole-document atomic; no silent skip or partial success. Repeated code, deleted/disabled reference, stale version, invalid status and cross-company source produce specific errors. List/export and UI messages must reflect saved data, including zero changed records.

These rules are design decisions for later implementation, not claims of working functionality. Legacy source, if consulted later, supplies business understanding only; no code or schema is copied.
