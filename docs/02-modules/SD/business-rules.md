# SD business rules (WU-SD-000 planned baseline)

- BR-SD-001: SD owns quotations, orders, deliveries, invoices and returns. MD supplies customer, item, currency, output-tax and payment references through Contracts. SD stores commercial snapshots and never reads MD tables directly.
- BR-SD-002: SYS owns company-scoped numbering, permissions, data scope and approval decisions. Each SD action checks its own permission and action scope; a VIEW permission is not required for a CREATE/EDIT-only workflow. Every document preserves approval history and audit/version fields.
- BR-SD-003: Quotation conversion is explicit and single-use. The order retains immutable quotation and line source IDs plus price, discount, tax and currency snapshots. Quotation draft or expiry cannot be converted. No quotation action changes stock.
- BR-SD-004: Order approval revalidates current customer and credit through public contracts before SYS final decision. With FI/AR not yet available, approval must fail with a specific unavailable-credit reason; no fabricated exposure or silent bypass. Approval alone does not post INV.
- BR-SD-005: Each delivery line refers to an approved order line; summed posted quantity plus active pending delivery quantity must not exceed ordered base-unit quantity. Lock order lines in ascending ID order and recheck during submit and final approval. Draft does not reserve or post stock.
- BR-SD-006: Final SYS delivery approval, SD Posted state and `IExternalInventoryPostingService.PostSalesOutboundAsync` run in one SQL transaction. SD provides saved item/warehouse/location/basic-unit quantity/tracking, never sales price as cost. INV owns negative-stock, serial/batch, duplicate-source and ledger rules (BR-INV-040–042); a failure rolls back every module's changes.
- BR-SD-007: Rejection releases any delivery reservation once; repeated decision or retry cannot post twice. Posted delivery is immutable. Corrections use a new return/reversal source, never direct INV aggregate updates. Return source type requires an explicit future INV contract extension.
- BR-SD-008: Monetary lines use decimal, saved output tax and currency rate effective on business date, and `Money.Round` at currency precision. Sum already rounded line values for header totals. Existing snapshots never change because a master rule changes.
- BR-SD-009: Invoices cover only posted, uninvoiced delivery quantity. SD owns commercial invoice; FI owns receivable/posting and consumes SD via its public interface when available. SD must not write FI tables. Credit exposure likewise comes from FI/AR, never from direct reads.
- BR-SD-010: All writes are whole-document atomic; no silent skip or partial success. Repeated code, deleted/disabled reference, stale version, invalid status and cross-company source produce specific errors. List/export and UI messages must reflect saved data, including zero changed records.

These rules are design decisions for later implementation, not claims of working functionality. Legacy source, if consulted later, supplies business understanding only; no code or schema is copied.

## WU-SD-002d quotation decisions (planned)

- BR-SD-011: Quote states are `Draft`, `Pending`, `Rejected`, `Approved`, `Voided`. Creation is Draft. Edit is allowed from Draft or Rejected with the current version; editing Rejected resets it to Draft but keeps all prior SYS rounds. Submit is allowed from Draft only, after rechecking the approved customer and active item/currency/output-tax references. Pending cannot be edited, deleted, voided or submitted again. Final SYS `IApprovalResultHandler` maps approval/rejection to Approved/Rejected within the SYS transaction. A zero-step SYS `SubmitAsync` returns Approved immediately and SD must set its own status in the same transaction; SYS does not call the handler in that case.
- BR-SD-012: `expiry_date` is inclusive. It must be at least the quotation business date on save; submission and conversion additionally require `IClock.Today <= expiry_date`. Approval status remains Approved after expiry for audit; the API also returns an `isExpired` derived flag. Do not use a background mutation to mark expiry. A voided quote stays visible in history. Only an Approved, unexpired, unvoided quote can convert.
- BR-SD-013: One quote converts to at most one order, including when the order is later soft-deleted or cancelled. The future order header stores immutable `source_quotation_id` and each order line stores immutable `source_quotation_line_id`; unique database constraints on these links include soft-deleted rows. Convert locks the source in the same transaction, validates company and version, and creates the order with all saved lines. No partial line conversion is supported in the first quote-to-order flow. A second concurrent conversion loses with 409; no order or number is retained from the losing transaction. Direct order creation has null source IDs.
- BR-SD-014: Quote save snapshots MD item identity, item code/name, currency, effective output tax rate and exchange rate; reference IDs are verified through MD Contracts on create/edit/submit. The client supplies a nonnegative unit price with at most six decimal places, a discount rate from 0 to 100 with at most four decimal places, and a positive base-unit quantity with at most six decimal places. For each line, `net = Money.Round(quantity * unitPrice * (1 - discountRate / 100), currency)`; `tax = Money.Round(net * taxRate / 100, currency)`; `gross = net + tax`. Convert each rounded original-currency amount to base currency at the saved rate, then `Money.Round(..., baseCurrency)` per line; header totals sum saved rounded line amounts. Reject decimal overflow before persistence; do not silently truncate. Tax and exchange rate selection use the quotation business date, not the current date. Later MD changes cannot recalculate saved values.
- BR-SD-015: `SAL.QUOTATION.SUBMIT` authorises submission, while approval/rejection uses SYS `SYS.APPROVAL.PROCESS`. Draft soft delete requires `SAL.QUOTATION.DELETE` and current version; void requires a distinct `SAL.QUOTATION.VOID` permission and only Approved without a source order. These new action codes are a design target for WU-SD-002a, not present in the current permission catalog. All lookups apply current company and the exact action's SYS data scope before revealing a quote. Whole-document failures leave neither quote rows nor SYS approval changes; audit records each accepted transition.

## WU-SD-003d order decisions (planned)

- BR-SD-016: Order states are `Draft`, `Pending`, `Rejected`, `Approved`, `Cancelled`. Create is Draft; edit of Rejected returns Draft and retains SYS history. Draft may be deleted; only Draft may submit. SYS final decision maps Pending to Approved/Rejected in its transaction. A zero-step SYS submit may approve immediately only after the same credit check succeeds. Pending/Approved/Cancelled content is immutable. Every command requires its exact `SAL.ORDER.*` permission, current company, action data scope and version.
- BR-SD-017: Manual create and quote conversion share one amount/snapshot policy: MD customer/item/currency/output-tax references and dated rate are resolved through public contracts, then line original/base net, tax and gross are rounded with `Money.Round` before header summation. Conversion copies the saved quote commercial snapshot and all lines without recalculating against changed MD prices or rates. Source quote/line IDs are immutable, unique including soft-deleted orders, and same-company. Lock quote before conversion, use a database unique constraint as the final concurrent guard, and roll back the losing number and document.
- BR-SD-018: Submit and final approval revalidate customer status and credit through an FI/AR public contract. The contract must return available limit and exposure for the same company/customer/business date; SD never reads FI tables. Until this contract exists, return a named `SAL.CREDIT.UNAVAILABLE` business error and leave order Draft/Pending as appropriate. A future override needs a separate action permission, reason, actor, time and one auditable decision per approval round; it cannot bypass inactive/unapproved customer or company checks. No placeholder exposure or automatic approval is allowed.
- BR-SD-019: Delivery balance is derived from saved order quantity minus posted delivery and active pending reservation. A delivery cannot exceed it. Approved order cancellation requires zero active pending and posted deliveries and a current version; cancellation retains number, quote source, lines and SYS history. A soft-deleted Draft does not release a used quotation source. Rejected revision cannot alter source identity. No order action writes INV; delivery posting is governed by BR-SD-005–007.
- BR-SD-020: Order list/detail queries use action scope before lookup; a 404 hides cross-company/out-of-scope IDs. Each write replaces all draft lines in one transaction and checks decimal overflow, duplicate line IDs, precision, valid references, status and concurrency before commit. No batch/partial success semantics apply. API and UI show specific field, state, credit or conflict reasons; no zero-change success message.
