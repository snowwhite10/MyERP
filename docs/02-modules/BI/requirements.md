# BI reporting requirements

## WU-BI-000d financial read boundary (design only)

This unit fixes the BI side of BlueWhale financial reports 4.1.1.7.5.1–7. BI owns presentation, filtering and export. FI owns Posted accounting facts and their authorised read contracts. No report endpoint, page, table or executable product behaviour is delivered here.

| Requirement ID | Version | Description | Author | Acceptance Criteria |
|---|---|---|---|---|
| REQ_F4117.5.1 | 1.0 | System should enable user to view Cash & Bank Report. | Developer | An authorised report for one company, fund account and inclusive date range shows FI's saved book opening, ordered Posted cash movements and closing at one committed cutoff. Bank statement balance is separately labelled and never substituted for book balance. |
| REQ_F4117.5.2 | 1.0 | System should enable user to view Accounts Payable Details Report. | Developer | FI's authorised Posted payable and committed allocation source supplies supplier, original amount, allocated amount, open amount, business date and immutable source links at one cutoff; Draft, Pending and unapplied payment are excluded. |
| REQ_F4117.5.3 | 1.0 | System should enable user to view Accounts Receivable Details Report. | Developer | FI's authorised Posted receivable and committed allocation source supplies customer, original amount, allocated amount, open amount, business date and immutable source links at one cutoff; Draft, Pending and unapplied collection are excluded. |
| REQ_F4117.5.4 | 1.0 | System should enable user to view Client Statement. | Developer | FI's authorised customer statement supplies opening, ordered charges, credits and allocations, closing and stable cutoff. Every page and export uses the same source set and company base currency. |
| REQ_F4117.5.5 | 1.0 | System should enable user to view Supplier Statement. | Developer | FI's authorised supplier statement supplies opening, ordered payables and allocations, closing and stable cutoff. Every page and export uses the same source set and company base currency. |
| REQ_F4117.5.6 | 1.0 | System should enable user to view Other Income & Expenses Detail Report. | Developer | Only FI Posted other collections and other payments appear, signed and separately classified with saved category, business date, base amount and journal/source IDs. They do not affect AR/AP open balances. |
| REQ_F4117.5.7 | 1.0 | System should allow user to export Other Income & Expenses Detail Report as Excel. | Developer | Export contains exactly the authorised frozen filtered set and totals seen in the report, escapes formula-leading text, names its cutoff and changes no accounting data. An expired cutoff fails explicitly instead of silently refreshing. |

The BI read layer must not query another module's tables. FI source contracts for cash book and partner statements are specified in REQ_F4116.12.1–3 and REQ_F4116.11.1–3; AR/AP detail and other income/expense report sources still require implementation slices. UI field IDs are allocated when pages exist. The other 15 BlueWhale report requirements remain in `reference-notes.md` and EP-BI1 for later slices.

## WU-BI-002d operational report baseline (design only)

The following sixteen BlueWhale reports use owner-module authorised read contracts. PUR, SD and PP own their document status and quantities; INV owns Posted stock movements and balance. BI owns filters, grouping, presentation and frozen export only. A tracking row is a saved document state, never a stock or accounting balance. PP has no module implementation yet, so its five source contracts are proposals with an explicit dependency. No report route, UI, table or executable product test is delivered by this unit.

| Requirement ID | Version | Description | Author | Acceptance Criteria |
|---|---|---|---|---|
| REQ_F4117.1.1 | 1.0 | System should enable user to view Purchase Order Tracking Report. | Developer | PUR returns authorised saved orders and line status, ordered quantity, Posted received quantity, Posted returned quantity and open quantity at one committed cutoff; Draft/Pending receipts are separately labelled, never received. |
| REQ_F4117.1.2 | 1.0 | System should enable user to view Purchase Detail Report. | Developer | PUR returns immutable order and Posted receipt/return source links, dates, item, supplier, base-unit quantities and saved commercial amounts; each movement is counted once. |
| REQ_F4117.1.3 | 1.0 | System should enable user to view Purchase Summary Report (By Product). | Developer | Group only the same authorised PUR detail set by saved product identity, currency and unit; full-set quantities and saved amounts reconcile to detail, with returns shown separately. |
| REQ_F4117.1.4 | 1.0 | System should enable user to view Purchase Summary Report (By Supplier). | Developer | Group the same PUR detail set by saved supplier identity and currency; totals reconcile to detail and retain inactive historical suppliers. |
| REQ_F4117.2.1 | 1.0 | System should enable user to view Sales Order Tracking Report. | Developer | SD returns saved order-line status, ordered, Posted delivered, Posted returned and open base-unit quantities at one cutoff; invoices and credit exposure are separately labelled. |
| REQ_F4117.2.2 | 1.0 | System should enable user to view Sales Detail Report. | Developer | SD returns authorised saved order, Posted delivery/return and Posted invoice source links with distinct business dates, quantities, currency and saved commercial amounts; a delivery is not a sale invoice. |
| REQ_F4117.2.3 | 1.0 | System should enable user to view Sales Summary Report (By Product). | Developer | Group the same SD detail set by product and currency; separate ordered, delivered, returned and invoiced measures and reconcile full-set totals to detail. |
| REQ_F4117.2.4 | 1.0 | System should enable user to view Sales Summary Report (By Client). | Developer | Group the same SD detail set by saved client identity and currency; current MD labels or prices do not restate historical sales. |
| REQ_F4117.3.1 | 1.0 | System should enable user to view Production Planning Tracking Report. | Developer | Once PP exists, its authorised saved plans and orders supply planned, released, completed and cancelled quantities with status and stable cutoff; a plan is not a Posted inventory movement. |
| REQ_F4117.3.2 | 1.0 | System should enable user to view Material Requisition Detail Report. | Developer | Once PP exists, its saved requisition lines and independently confirmed Posted INV issue references supply requested, issued and reversed base-unit quantities; unposted requests stay distinct. |
| REQ_F4117.3.3 | 1.0 | System should enable user to view Material Requisition Summary Report. | Developer | Group the same PP requisition detail by material and base unit; full-set totals reconcile, with shortages and reversals identified. |
| REQ_F4117.3.4 | 1.0 | System should enable user to view Production Inbound Detail Report. | Developer | Once PP exists, its saved completion lines and Posted INV inbound references supply completed and accepted quantities; rejected or pending completions do not increase stock. |
| REQ_F4117.3.5 | 1.0 | System should enable user to view Production Inbound Summary Report. | Developer | Group the same PP completion detail by product and base unit; totals reconcile to Posted inbound source links and distinguish unposted completions. |
| REQ_F4117.4.1 | 1.0 | System should enable user to view Product Inventory Balance Report. | Developer | INV returns authorised opening, Posted in/out and closing base-unit quantities by item/warehouse/location at one committed cutoff; no monetary value is implied. |
| REQ_F4117.4.2 | 1.0 | System should enable user to view Product Inbound & Outbound Detail Report. | Developer | INV returns every authorised Posted movement once with source, direction, business date, posted time, location and base-unit quantity, including both transfer legs. |
| REQ_F4117.4.3 | 1.0 | System should enable user to view Product Inbound & Outbound Summary Report. | Developer | Group the same INV Posted detail set by item/warehouse/location and direction; opening plus inbound minus outbound equals closing and totals reconcile across all pages. |

Each report is limited to one company, an inclusive business-date interval of at most 366 days, and a filter-bound durable committed source set. The owner enforces document/warehouse/partner scope on every page and export. The BI permission does not grant an owner permission. Historical snapshots retain saved IDs and labels after MD inactivation. Currency amounts are never combined across currencies, and quantities are grouped by base unit. Source contract, HTTP and page implementation are separately scheduled in backlog; UI item IDs are allocated with pages.
