# ADR-052：INV 來源引用的持久化與刪除互斥

日期：2026-10-13。狀態：Accepted。工作單元：WU-INV-002。

## 背景

MD 刪除物料、倉庫或儲位時，必須知道 INV 是否已有引用。跨模組不能直接讀表或建 SQL 外鍵；僅有驗證鎖而沒有持久化引用，提交後無法拒絕刪除。

## 決定

建立 `inv_reference`（REQ_DS43.134），每個公司及來源鍵一筆，保留物料、倉庫、可選儲位 ID 與不可變代碼快照。INV 寫入方透過 `InventoryReferenceService.RecordAsync` 在 MD guard 的共享鎖內驗證並保存；如來源與引用分步保存，呼叫方必須以同一外部交易包覆。MD 刪除取得同公司排他鎖後，向 INV 註冊的三個 Usage 契約詢問，INV 只查自己的引用表。跨模組不建外鍵。歷史引用永久保留，作廢單據不能使曾引用的主檔變為可刪。

`source_key` 是 INV 來源行的穩定識別，禁止重用。WU-INV-003 的異動帳及其後單據須建立來源引用；此表本身不承載數量與成本，也不能代替過帳帳本。

## 驗證與後果

真實 SQL 雙連線整合測試令寫入與刪除交易重疊：寫入先提交時刪除回 409；刪除先提交時寫入回 404。公司篩選及索引使 Usage 不需查 MD 表。引用表增加一筆每來源行的保存成本，換取明確的模組邊界與刪除安全。
