# ADR-069：拆卸成本分攤與審批邊界

- 日期：2026-10-18
- 狀態：Accepted
- 工作單元：WU-INV-012d

## 背景

BlueWhale 將 Product Disassembly 列於 Inventory。MyERP 組裝已具備鎖定估值、SYS 審批及原子異動；拆卸須反向消耗一個成品並產出多個組件，不能憑組件數量推測各組件成本，也不能讓用戶指定最終入庫成本。

## 決定

每張拆卸單保存恰一個成品來源行及 1–999 個組件目的行，總行數至多 1000；不用 PP BOM。各組件行保存正數、最多六位小數的成本分攤權重；權重是相對值，不要求加總 100。草稿保存權重快照，修改須整組替換並帶版本。成品不得同時作組件，以免同一物料成本池於單次作業內自我循環。不同組件行可指向同一物料，但每行行號唯一，批序號按行及位置核驗。

SYS 文件類型 `INV.DISASSEMBLY`，審批金額 0。最終核准處理器於同一 SQL 交易按物料 ID 升序取得公司／物料排他鎖，讀取成品當前可靠移動平均；成品出庫價值依 `Round(quantity × averageUnitCost, 4, AwayFromZero)`。前 N−1 個組件依權重比例分得四位行值，最後一行承接四位尾差；組件單價各以六位計算並須使 `Round(quantity × unitCost, 4, AwayFromZero)` 精確回到分得行值。未知成本、溢位、無法表示的分攤值或單價均拒絕整單，不把未知值視為零。明確零成本可分攤為零。成品出庫異動單價為 null，鎖定單價另存拆卸行；組件入庫異動使用分攤後單價。此規則以四位行值守恆，不聲稱各組件可回收原組裝時個別成本。

成品 Out、組件 In、Posted 與 SYS 最終決定同交易。來源固定 `DISASSEMBLY` 加單據 ID，沿用 INV 來源快照重放檢查、結存與批序號鎖。任一不足、引用失效、序號衝突或寫入錯誤時，SYS 決定與全部異動回滾。駁回只保存意見及歷史，沒有異動；已過帳不可修改，以新反向單據更正。INV 只經 MD Contracts 查主檔、經 SYS Application 契約查審批，不直接讀其他模組表。

## 後果

新增拆卸表頭、明細、批序號三表及單據 CRUD／過帳處理器；成本權重只作分攤依據，與實際入庫單價分開保存。未來 PP BOM 可提供建議，但不得在未經用戶確認時覆寫已保存拆卸明細。後端需以真實 SQL 證明成本、批序號及 SYS 回滾；前端需以三語亮暗畫面驗收。
