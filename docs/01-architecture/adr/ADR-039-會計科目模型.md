# ADR-039 — 會計科目模型

- 日期：2026-10-12
- 狀態：Accepted
- 工作單元：WU-MD-019（會計科目主檔）

## 背景

BlueWhale 與舊系統都沒有會計科目（總帳科目）：BlueWhale 的「Account Management」（REQ_F4118.5）與 `REQ_DS43.1 Account` 指資金帳戶（現金／銀行，見 reference-notes 與 R-010），舊系統 `account` 表也只有代碼、名稱、期初餘額，沒有上層、類別、借貸方向或末級旗標。因此科目規則只能依會計實務自行定義（ADR-002 追加需求）。

backlog 決定科目屬 MD：FI（總帳、應收付、資金）、CO、BI 都要讀科目，但 FI 的傳票表（`gl_` 前綴）不得被 MD 讀取，MD 也不能引用 FI。

## 決定

1. **一張表 `md_account`（REQ_DS43.121）。** 沿用分類基底（`code`、`name` 200、啟用、軟刪除、`custom_fields`、版本、審計欄位），另加：
   - `parent_id`：可空，同公司複合外鍵 `(company_id, parent_id)` → `(company_id, id)`，與物料分類相同；
   - `account_type` varchar(30)：`Asset` 資產、`Liability` 負債、`Equity` 權益、`Cost` 成本、`Revenue` 收入、`Expense` 費用（CHECK）。保留「成本」類，讓中國企業會計準則的生產成本、勞務成本類科目有獨立類別；IFRS 公司可不用；
   - `balance_direction` varchar(10)：`Debit` 借方、`Credit` 貸方（CHECK）。
2. **代碼只用數字，子科目代碼以上層代碼開頭且較長。** 代碼 1–30 位 ASCII 數字（400 `code`），公司內永久唯一含已刪除（409 `MD.ACCOUNT.DUPLICATE_CODE`）。例如 `1002` 銀行存款 → `100201` 某銀行。不強制固定段長（4-2-2 之類），不同公司可用不同編碼方案；違反前綴規則回 422 `MD.ACCOUNT.CODE_PREFIX`。
3. **上層與類別在建立後不可修改。** 因代碼不可修改且受前綴規則約束，上層也就固定，不會出現循環，不需要樹搬移檢查；層數由 30 位代碼自然限制。子科目類別必須與上層相同：建立時可省略類別（沿用上層），填了不同類別回 422 `MD.ACCOUNT.TYPE_MISMATCH`；根科目必須填類別（400 `accountType`）。類別不可修改，用錯時刪除重建（未被使用時）。
4. **借貸方向可與類別慣例不同。** 省略時按類別預設：資產、成本、費用為借方，負債、權益、收入為貸方。可明確指定相反方向以表達備抵科目（例如累計折舊為資產類、貸方）。方向可修改，但已被使用的科目不可改（見第 6 點）。
5. **停用與末級。**
   - 只能在啟用的上層下建立子科目（422 `MD.ACCOUNT.INVALID_PARENT`，別公司或已刪除同樣）；
   - 有啟用子科目的科目不可停用（422 `MD.ACCOUNT.HAS_ACTIVE_CHILDREN`）；上層停用時不可啟用子科目（422 `MD.ACCOUNT.PARENT_INACTIVE`）；
   - 「可過帳」= 啟用且沒有未刪除子科目（末級）。不另存 `is_leaf` 欄位，避免與子科目資料不一致；新增子科目後上層自動變成非末級；
   - 有子科目不可刪除（409 `MD.ACCOUNT.HAS_CHILDREN`）。
6. **使用檢查由使用方模組提供。** MD.Contracts 定義 `IAccountUsage.IsInUseAsync(accountCode)`，FI（傳票、期初餘額）等模組實作並註冊；MD 服務注入全部實作（目前沒有，視為未使用）。被使用的科目：不可刪除（409 `MD.ACCOUNT.IN_USE`）、不可改借貸方向（409 `MD.ACCOUNT.IN_USE`）、不可在其下新增子科目（422 `MD.ACCOUNT.PARENT_IN_USE`，否則已過帳金額會停留在非末級科目）。這樣 MD 不讀 `gl_` 表、也不引用 FI。
7. **契約 `IChartOfAccounts`。**
   - `FindAsync(code)`：含停用，不存在回 null；`AccountInfo(Code, Name, ParentCode, AccountType, BalanceDirection, IsActive, IsPostable)`；
   - `RequirePostableAsync(code)`：給 FI 過帳驗證，不存在 404 `MD.ACCOUNT.NOT_FOUND`、停用 422 `MD.ACCOUNT.INACTIVE`、非末級 422 `MD.ACCOUNT.NOT_POSTABLE`。
   - `AccountType`、`BalanceDirection` 為 Contracts 列舉，JSON 以名稱傳遞。
8. **並行。** 建立、修改、刪除在公司級 applock `md_account:{companyId}` 內執行，避免同時「刪除上層」與「新增子科目」、或同時停用上層與啟用子科目。
9. **權限與 API。** `MD.ACCOUNT.VIEW／CREATE／EDIT／DELETE`。`GET /api/v1/md/accounts` 一次回傳目前公司全部未刪除科目（含停用，按代碼排序，附 `isPostable`），前端組樹；`POST`、`PUT /{id}`、`DELETE /{id}?version=`。

## 不在本工作單元

- 輔助核算（客戶、供應商、部門、項目）、科目幣別、數量核算：由 FI 總帳工作單元按需要追加欄位，仍經本契約讀取；
- 標準科目表範本（台灣商業會計、中國企業會計準則、IFRS 示範）匯入：留待 WU-MD-022 種子資料或 FI 初始化；
- 期初餘額、科目餘額屬 FI（`gl_` 表）。

## 影響

- 追加需求 REQ_F4118.39（Chart of Accounts）、REQ_DS43.121；介面 8.87–8.88（頁面在第二段）。
- FI、CO、BI 取科目一律經 `IChartOfAccounts`，不得讀 `md_account`；FI 必須實作 `IAccountUsage`，否則科目刪除與方向修改無法受保護（FI 工作單元驗收條件）。
