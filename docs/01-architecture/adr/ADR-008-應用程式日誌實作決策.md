# ADR-008 應用程式日誌實作決策（Serilog、Application Insights 相依、enricher、慢 API）

- 狀態：Accepted
- 日期：2026-10-10
- 工作單元：WU-P0-009
- 相關：ADR-001（套件版本）、ADR-005（共用核心）；設計見 [logging.md](../logging.md)

## 背景

ADR-001 列出 `Serilog.Sinks.ApplicationInsights` 5.0.1 與 `Microsoft.ApplicationInsights.AspNetCore` 3.2.0，並要求 WU-P0-009 驗證兩者相依。實際還原結果：sink 5.0.1 相依 **`Microsoft.ApplicationInsights` 2.23.0**（舊版 SDK），而 `Microsoft.ApplicationInsights.AspNetCore` 3.x 改以 OpenTelemetry（Azure Monitor Exporter）為核心，`Microsoft.ApplicationInsights` 升為 3.x，舊版 `TelemetryConfiguration` / `ITelemetry` 行為改變。兩者同時引用會把 sink 的相依提升到 3.x，相容性沒有保證。

此外還需決定：enricher 如何取得 scoped 的 `ICurrentUser` / `ICurrentCompany`、慢 API 如何量測、多個測試主機共存時 Serilog 全域狀態如何處理。

## 決定

1. **只引用 `Serilog.Sinks.ApplicationInsights` 5.0.1，不引用 `Microsoft.ApplicationInsights.AspNetCore`**。有連線字串時，以 `new TelemetryConfiguration { ConnectionString = … }`（2.23）建立並註冊為 DI 單例（關機時由容器釋放並送出緩衝），sink 用 `TelemetryConverter.Traces`。MASTER_PROMPT 8.1 只要求日誌寫入 Application Insights；請求 / 相依遙測（AspNetCore SDK 的自動收集）需要時再另寫 ADR 評估 Azure Monitor OpenTelemetry Distro。ADR-001 該列標註「不使用」。
2. **套件放在 `MyERP.Shared.Infrastructure`**（`Serilog.AspNetCore`、`Serilog.Sinks.File`、`Serilog.Sinks.ApplicationInsights`），提供 `AddMyErpLogging` / `UseMyErpRequestLogging`，Api 只呼叫。業務程式碼只用 `ILogger<T>`。
3. **enricher 在寫日誌當下讀取** `HttpContext.RequestServices` 的 `ICurrentUser` / `ICurrentCompany`（而非在中介層 `LogContext.PushProperty`），因此不受中介層順序影響，認證中介層之後的日誌自然帶有 UserId；請求範圍已釋放時捕捉 `ObjectDisposedException` 並省略。
4. **TraceId = `Activity.Current.TraceId`**（32 碼），與 ProblemDetails `traceId`（W3C traceparent，ADR-005）可互相對應；沒有 Activity 時用 `HttpContext.TraceIdentifier`。
5. **慢 API 用 Serilog 請求日誌的 `GetLevel`**：`elapsed > App:SlowRequestMilliseconds` → Warning，否則 Debug。不自寫計時中介層（Serilog 內部以 `Stopwatch` 量測，不違反 IClock 規則——IClock 只管牆上時間）。5xx 不在請求日誌重複寫 Error。
6. **`preserveStaticLogger: true`**：不改寫全域 `Log.Logger`；`UseSerilogRequestLogging` 明確傳入 DI 的 `Serilog.ILogger`。同一測試程序內多個 `WebApplicationFactory` 主機互不干擾。
7. **檔案格式 CLEF JSON**（`CompactJsonFormatter`），每天滾動、單檔 100 MB、以 `retainedFileTimeLimit` 保留 30 天（按天數而非檔案數，單日多檔也不會提早刪除）。
8. **設定在啟動時驗證**（`ErpLoggingOptions.FromConfiguration`），錯誤即拋出 `FormatException`，與 `App:TimeZoneOffset` 一致（ADR-005）。

## 考慮過的方案

| 方案 | 不採用原因 |
|---|---|
| 同時引用 `Microsoft.ApplicationInsights.AspNetCore` 3.2.0 | 把 sink 相依提升到 3.x，相容性未驗證；也會自動收集大量請求遙測，超出 8.1 要求 |
| 降級 `Microsoft.ApplicationInsights.AspNetCore` 到 2.x | 舊版 SDK 已進入維護期；目前不需要自動遙測 |
| 中介層 `LogContext.PushProperty` 加 UserId | 必須放在認證之後，認證之前的日誌（含請求摘要外層）拿不到；順序容易出錯 |
| 自寫慢 API 中介層 | 與 Serilog 請求日誌重複量測與記錄 |
| 純文字檔案格式 | 不利於 log-analysis.md 的自動分析；CLEF 可直接 `ConvertFrom-Json` |
| 修改全域 `Log.Logger` | 整合測試多主機並行時互相覆寫、關機時被他人 CloseAndFlush |

## 影響

- `appsettings.json` 以 `Serilog:MinimumLevel` 取代 `Logging:LogLevel`（Serilog 取代預設提供者後原設定不再生效）。
- App Insights 連線字串只能經環境變數 / user-secrets 提供，CI 不設定。
- WU-SYS-003 加入認證後，UserId 自動出現在日誌，無需修改本機制；WU-SYS-002 補敏感資料遮罩工具。
