# ADR-020：稽核查詢頁的單據歷史連結，以及前端單元測試的逾時

- 日期：2026-10-11
- 狀態：採用
- 工作單元：WU-SYS-007（第二段）

## 背景

1. 稽核查詢頁（介面 8.66）除了一般查詢，也要能顯示單筆單據的完整修改歷史（REQ_F4118.27.6）。日後各模組的單據頁會有「稽核歷史」頁籤（MASTER_PROMPT 第 9 節），需要一個穩定的進入方式。
2. 加入第 31 個前端測試檔後，整體並行執行（`ng test`，Vitest + jsdom）時，各 worker 中第一個渲染 ng-zorro 元件的測試冷啟動常超過 Vitest 預設的 5 秒。每次失敗的檔案不同，例如登入頁和用戶權限對話框。逾時後 TestBed 沒有重設，同一 worker 之後的測試檔全部出現 `Cannot configure the test module when the test module has already been instantiated`，一次逾時就造成十多個連帶失敗。

## 決定

1. **單據歷史用 query string**：`/sys/audit-logs?tableName=<表名>&recordId=<Id>[&userId=<Id>]`。
   - 頁面以 `withComponentInputBinding` 取得參數（`input()` 別名 `tableName`、`recordId`、`userId`）。參數改變時，篩選條件隨之更新並重新查詢。
   - 列上的「資料表／記錄」連結也只改 query string，所以網址可以分享，瀏覽器上一頁可以回到前一份歷史。
   - 「重設」會清除網址參數。不合法的 `userId`（非正整數）忽略。
   - 不另做獨立的歷史元件。單據頁的稽核頁籤直接連到這個網址；要嵌入頁籤時再抽出共用元件。
2. **欄位差異以 grid 呈現**：nz-table 會接管展開列內巢狀 `<table>` 的 `<thead>`，所以展開列的差異表改用 `div` grid（`role="table"`）。
3. **前端測試逾時改為 15 秒**：新增 `src/frontend/vitest-base.config.mts`（`test.testTimeout: 15_000`），由 `angular.json` 的 `test.options.runnerConfig` 載入。這只放寬單一測試的時間上限，不改任何斷言。之前 `users.spec.ts` 個別測試設的 15 秒逾時保留不動。

## 影響

- 單據頁的稽核頁籤只需要產生連結：`/sys/audit-logs?tableName=sd_sales_order&recordId=123`。
- 前端測試真的卡住時，要等 15 秒才失敗（原為 5 秒）。整體執行時間不變（約 3 分鐘）。
- 如果測試檔繼續增加後冷啟動仍超過 15 秒，再考慮調整 Vitest 的 pool 或 isolate 設定。
- 前端單元測試不要和後端建置／測試同時執行：本輪兩者同時執行時，用戶權限對話框的第一個測試仍超過 15 秒；單獨執行時 335 / 335 通過。
