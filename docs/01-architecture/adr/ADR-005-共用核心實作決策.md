# ADR-005 共用核心實作決策（時間、審計、公司隔離、覆蓋率量度）

- 狀態：Accepted
- 日期：2026-10-10
- 工作單元：WU-P0-007
- 相關：ADR-001（套件清單）、ADR-003（單一 MyErpDbContext）、ADR-004（MTP）；設計見 [shared-core.md](../shared-core.md)

## 背景

WU-P0-007 實作 MASTER_PROMPT 6.3 / 6.4 與 api-conventions.md 要求的共用核心時，有幾處規範沒有寫明細節，須決定並記錄，讓之後所有模組一致。

## 決定

1. **IClock**：`Now` 回傳 `DateTimeOffset`（偏移 = `App:TimeZoneOffset`，預設 `+08:00`），另提供 `LocalNow`（`DateTime`，Kind Unspecified，寫入 `DATETIME2(6)` 時間戳欄位）與 `Today`（`DateOnly`，依設定時區而非 UTC 日期）。`SystemClock` 以注入的 `TimeProvider` 讀時間，是 ArchitectureTests 白名單中**唯一**可讀系統時間的型別；`TimeProvider.GetUtcNow/GetLocalNow` 一併列入禁用 API，防止繞過 IClock。設定格式錯誤時啟動即失敗。
2. **系統用戶 Id = 0**（`SystemUser.Id`）：沒有登入用戶（背景作業、種子程序）時 `created_by` / `updated_by` 填 0。SYS 種子資料不得使用 Id 0 建立真實用戶（IDENTITY 從 1 起，自然滿足）。
3. **公司隔離封閉失敗**：沒有公司上下文（無 `X-Company-Id`）時，公司篩選化簡為 `WHERE 0 = 1`，不回傳任何資料；新增 `ICompanyOwned` 實體時若未明確指定 `CompanyId` 即拋出例外。`X-Company-Id` 只做格式解析，用戶能否存取該公司由 WU-SYS-004 驗證。
4. **具名 Query Filter**（EF Core 10）：`Company` 與 `SoftDelete` 分開命名，`IgnoreQueryFilters([ErpQueryFilters.SoftDelete])` 可查已刪主檔但仍保留公司隔離；略過 `Company` 必須在程式註解說明理由。
5. **樂觀鎖流程**：Application 層把請求帶來的 `version` 設為 `Entry(e).Property(x => x.Version).OriginalValue`；interceptor 以 OriginalValue + 1 寫入新版本，EF 以 OriginalValue 比對，不符拋 `DbUpdateConcurrencyException` → 全域處理器回 409 `COMMON.CONCURRENCY.CONFLICT`。interceptor 同時把 `created_at`、`created_by`、`company_id` 還原並標為未修改。
6. **pageSize 範圍 1–200**：api-conventions.md 列的 10 / 20 / 50 / 100 / 200 是前端下拉選項；後端只驗證 1–200（超出回 400），避免 API 呼叫端被不必要地限制。
7. **共用錯誤代碼前綴 `COMMON`**：`COMMON.REQUEST.VALIDATION_FAILED`、`COMMON.CONCURRENCY.CONFLICT`、`COMMON.RESOURCE.NOT_FOUND`、`COMMON.SERVER.INTERNAL_ERROR`；模組錯誤代碼仍用模組前綴。`RequestValidationException` 命名避開 FluentValidation 的 `ValidationException`。
8. **覆蓋率量度**：MTP 的 `dotnet test --coverage` 需要 `Microsoft.Testing.Extensions.CodeCoverage`（不在 ADR-001 清單，實測回 exit 5）。改以 `dotnet vstest` + 既有 `coverlet.collector` 量度（xunit.runner.visualstudio 仍提供 VSTest 介面），封裝為 `tools/scripts/Get-BackendCoverage.ps1`（結果寫 `logs/coverage`，低於門檻 exit 1）。測試的通過 / 失敗仍以 `dotnet test --solution` 為準（ADR-004）。

## 考慮過的方案

| 方案 | 不採用原因 |
|---|---|
| IClock 只回傳 `DateTime` | API 規範要求時間戳 JSON 帶 `+08:00`，保留 `DateTimeOffset` 才不會遺失偏移 |
| 沒有公司上下文時不套用篩選 | 開放失敗，任何漏設標頭的請求都會看到全部公司資料 |
| 單一合併的 Query Filter | 查已刪主檔時必須連公司隔離一起略過，容易出錯 |
| 新增 `Microsoft.Testing.Extensions.CodeCoverage` / `coverlet.MTP` | 需修改 ADR-001 套件清單；現有 coverlet.collector 已足夠 |
| 對 SQL Server 跑 interceptor 整合測試 | `myerp_test` 重建機制屬 WU-P0-008；本單元以 ChangeTracker（不連線）與 `ToQueryString()` 驗證 |

## 影響

- 每個模組以 `IModuleDbModel` 註冊 EF 設定；實體繼承 `BusinessEntity`（單據）或 `MasterEntity`（主檔）即自動取得必備欄位、篩選、樂觀鎖與審計。
- WU-P0-008 須補：對 `myerp_test` 的整合測試（實際寫入時蓋章、版本衝突回 409、公司篩選）。
- WU-SYS-003 / 004：JWT 的 `sub` 必須是用戶 Id（long）；授權中介層驗證 `X-Company-Id`。
