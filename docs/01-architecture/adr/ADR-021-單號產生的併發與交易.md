# ADR-021：單號產生的併發控制與交易語意

- 日期：2026-10-11
- 狀態：採用
- 工作單元：WU-SYS-008（第一段）

## 背景

MASTER_PROMPT 第 5 節要求共用的單號產生服務，可按公司、單據類型、年月設定前綴與流水號，併發下不重號。各模組（SD、PUR、INV、FI…）建立單據時都要取號。需要決定：

1. 用甚麼機制保證併發不重號；
2. 取號與單據儲存的交易關係（會不會跳號）；
3. 規則已發出單號後，哪些設定可以修改；
4. 介面放在哪一層，令其他模組可呼叫又不破壞模組邊界。

## 決定

1. **計數表＋單一 MERGE 語句**：`sys_number_sequence` 每條規則每個週期一列。取號執行
   `MERGE sys_number_sequence WITH (HOLDLOCK) … WHEN MATCHED UPDATE current_value + 1 WHEN NOT MATCHED INSERT 1 OUTPUT inserted.current_value`。
   - HOLDLOCK 令 MERGE 在唯一索引 `(company_id, rule_id, period_key)` 的鍵（或鍵範圍，首次建立週期時）取得更新鎖，同一鍵的並行取號排隊，不會讀到相同值，首次建立也不會插入兩列。
   - 不使用 SQL Server SEQUENCE 物件：每家公司、每種單據、每個週期都要獨立計數，且 SEQUENCE 在交易回滾時不退回，會跳號。
   - 不使用 `sp_getapplock`：鎖範圍與 MERGE 的資料列鎖相同，但要另外管理鎖名稱與釋放。
   - 不寫成 Stored Procedure：只有一條參數化語句，屬一般 CRUD 範疇（MASTER_PROMPT 第 5 節的 SP 原則用於大量運算）。語句全部參數化（`SqlParameter`，`period_key` 為 `VARCHAR(8)` 避免隱含轉換）。
2. **與呼叫端同一交易**：`NumberGenerator` 使用同一個 scoped `MyErpDbContext`，`ExecuteSqlRaw` 自動加入目前的交易。
   - 單據服務應在交易內「取號 → 儲存單據 → 提交」。交易回滾時流水號一併回滾，下一張單據拿到同一號碼，**不跳號**。
   - 代價：交易期間同一規則同一週期的其他取號會等待提交。單據交易應保持短小（不在交易內呼叫外部服務）。
   - 同一交易需要多個不同類型的單號時（例如出貨同時產生發票），按單據類型代碼排序後依次取號，避免兩個交易以相反次序鎖定而死結。
   - 沒有交易時，取號語句自動提交；之後單據儲存失敗會留下空號。此用法只適合可接受空號的情況。
   - 計數列不經 EF ChangeTracker，因此不寫稽核記錄（計數變化沒有業務意義，且會造成大量雜訊）；規則本身的修改照常經 interceptor 寫稽核。
3. **單號由業務日期決定**：日期部分與週期鍵都取自呼叫端傳入的單據日期（`DateOnly`），不是系統時間。補登上月單據會沿用上月的計數。
4. **重設週期必須包含在日期格式內**：每年重設須有年份、每月須有月份、每日須有日期，否則不同週期會產生相同單號（400）。
5. **已發出單號的規則（有計數列）**：日期格式與重設週期鎖定、流水號長度不可縮短（422 `SYS.NUMBER_RULE.IN_USE`）；名稱、前綴、加長流水號、啟用狀態可改。規則沒有刪除，只能停用；停用後取號回 422 `SYS.NUMBER_RULE.INACTIVE`。
   - 剩餘風險：同時改前綴與加長流水號，理論上可能組出與舊單號相同的字串。各模組的單號欄位必須另設 `(company_id, 單號)` 唯一索引作最後防線。
6. **介面放在 `MyERP.Shared.Numbering.INumberGenerator`**：各模組只依賴 Shared，不引用 SYS 專案；SYS 模組註冊實作 `NumberGenerator`。公司取自 DbContext 的目前公司（請求標頭 `X-Company-Id`），沒有公司上下文時回 403。
7. **單號長度上限 28**（前綴 10＋日期 8＋流水號 10）；各模組單號欄位統一 `VARCHAR(30)`。流水號超過上限回 422 `SYS.NUMBER_RULE.SEQUENCE_EXHAUSTED`。
8. **單據類型代碼** `{PREFIX}.{DOCUMENT}`（例如 `SAL.ORDER`），目前自由輸入並以格式驗證。第一個單據模組開發時，再加入由各模組宣告的單據類型目錄（類似權限目錄），並由種子資料建立預設規則。

## 影響

- 各模組建立單據：`await using var tx = await db.Database.BeginTransactionAsync(); order.Number = await numbers.NextAsync("SAL.ORDER", order.OrderDate); db.Add(order); await db.SaveChangesAsync(); await tx.CommitAsync();`。
- 整合測試以 100 次並行取號（16 個並行 DbContext，一半在交易內）驗證沒有重號、沒有跳號（SYS-NUM-001），以回滾驗證號碼退回（SYS-NUM-002）。
- 規則維護頁（介面 8.67）留待 WU-SYS-008 第二段。
