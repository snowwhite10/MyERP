# ADR-090 — FX difference read／export reconciliation

Date: 2026-11-06. Status: Accepted (WU-FI-014j).

## Context

BR-FI-123 requires FI's exchange-difference read and export to reconcile saved settlement allocations and valuations with each Posted GL leg at one durable cutoff, to label draft／rejected／rolled-back／deleted history without counting it as Posted, to serve pages and export from the same set and to escape formula-leading text. ADR-084／085／087／088 fix the arithmetic, journal shape and run summary but not how the read compares saved sources with GL, which signs are reported, or how paging and export share one set. The tax reconciliation rule (ADR-083, `TaxGlReconciliationRules`) and the INV stock-flow CSV escaping (BR-INV-056) are the existing patterns.

## Decision

- `FxDifferenceReconciliationRules.Reconcile(scope, sources, glLegs)` is pure. The scope carries company, a positive committed `CutoffSequence`, base currency code and decimals (0–4). Every source and GL leg must carry a positive commit sequence not beyond the cutoff; a later row is an input error (`AfterCutoff`), never silently dropped, because the reader must freeze the set first (a maximum row ID alone is not a cutoff, BR-FI-117／127).
- Input errors reject the whole read with collection／index／field: null or invalid scope, duplicate source or GL line ID, other company (`CrossCompany`), undefined kind／side／state／role, invalid currency code or source currency equal to base (`SameCurrency`), rate outside `decimal(19,8)`, amounts beyond `decimal(19,4)` or base scale, non-zero overlay on a valuation, reference blank or longer than 64, two-sided or zero GL legs, and journal ID presence inconsistent with state (a Posted settlement and Posted non-zero valuation need one; a zero valuation and every non-Posted source have none). Totals beyond `decimal(19,4)` are rejected under `totals`.
- Amount signs: realised and unrealised differences are P&L signed (gain positive); a GL leg contributes `credit − debit`. Settlements compare realised gain／loss legs, valuations unrealised gain／loss legs. The released carrying overlay implies a P&L reversal of `−overlay` for AR and `+overlay` for AP (ADR-087), compared with the overlay reversal gain／loss legs.
- Differences per Posted source in fixed order: no legs `Missing`; legs in another journal `JournalMismatch`; a role foreign to the kind (e.g. realised leg on a valuation) `UnexpectedRole`; debit ≠ credit `Unbalanced`; gain／loss total ≠ saved difference `AmountDifference`; overlay reversal ≠ expected `OverlayDifference`. A leg on a Posted zero valuation is `UnexpectedLeg`; a leg on any non-Posted source is `LegOnNonPostedSource`; untagged or unknown-source legs are `Unmatched`. The rule never proposes a balancing line.
- Rows: one per source in (exposure ID, source ID) order with kind, realised／unrealised category, state, `CountsAsPosted` (Posted only), side, reference, both currencies, rate, original amount, saved and GL difference, expected and GL overlay reversal, journal and GL line IDs and the row's difference kinds. Posted totals count only Posted sources; GL totals count every leg by role and are informational, so offsetting differences never net to a pass. Counts per state are exact.
- `Page(report, pageNumber, pageSize)` slices the same rows (page 1-based, size 1–200, a page past the end is empty, no overflow for large page numbers). `Export(report, headers)` writes a company line, a cutoff line, the caller's 19 translated headers and every row in report order; more than 10,000 rows rejects the export instead of truncating. `EscapeCsvText` prefixes an apostrophe when the first non-blank character is `= + - @` or the value starts with tab／CR, and quotes cells containing comma, quote, tab or line breaks; numbers are invariant culture and not escaped, so negative amounts stay numeric. The API adds the UTF-8 BOM.

## Consequences

014b／014c read the committed set under one cutoff token in a read-only transaction, map saved rows to these records, enforce `FX.DIFFERENCE.VIEW／EXPORT` and company scope, and render rows in three languages and light／dark modes. The rule changes no FI／GL／audit state; SQL reads, manifest tokens, permissions, API and screens are not part of this decision.
