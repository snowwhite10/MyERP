# ADR-047：往來對象預設付款條件與結算方式

- 日期：2026-10-13
- 狀態：Accepted
- 工作單元：WU-MD-025

## 情境

ADR-040 建立了付款條件（`md_payment_term`）與結算方式（`md_settlement_method`），並把「客戶／供應商的預設值」留到本工作單元。BlueWhale 客戶、供應商沒有帳期欄位；SD／PUR 開單時需要帶出往來對象的預設付款條件與結算方式，且不得讀 MD 資料表。

## 決策

1. **欄位放在共用基底。** `BusinessPartner<TCategory>` 加 `DefaultPaymentTermId`、`DefaultSettlementMethodId`（可空 bigint），`md_customer` 與 `md_supplier` 對應 `default_payment_term_id`、`default_settlement_method_id`。沿用分類欄位做法：以 `(company_id, default_payment_term_id)`、`(company_id, default_settlement_method_id)` 複合外鍵參照 `md_payment_term`／`md_settlement_method` 的 `(company_id, id)` 備用鍵（`NO ACTION`），資料庫層阻止跨公司引用；兩個外鍵各有索引。
2. **API 以 id 收發。** 與 `categoryId` 一致，Create／Update 請求與回應帶 `defaultPaymentTermId`、`defaultSettlementMethodId`（可空）。PUT 是完整取代：缺少欄位即清除。驗證與分類相同：id 必須大於 0、屬於目前公司且未刪除；新選取時必須啟用，未改變的已停用值可保留（400 `defaultPaymentTermId`／`defaultSettlementMethodId`）。
3. **匯入不含預設值。** 客戶／供應商匯入範本（ADR-044）維持不變，匯入資料預設值為空，之後在頁面設定；日後需要時以 `paymentTermCode`／`settlementMethodCode` 欄位追加，不影響本決定。
4. **刪除檢查。** 付款條件、結算方式被任何未刪除的客戶或供應商設為預設值時，刪除回 409 `MD.PAYMENT_TERM.IN_USE`／`MD.SETTLEMENT_METHOD.IN_USE`（同模組，直接查 MD 表）；仍可停用。單據引用仍由使用方 Usage 契約判斷（ADR-040 第 5 點）。
5. **契約帶出代碼。** `CustomerIdentity`／`SupplierIdentity` 追加 `DefaultPaymentTermCode`、`DefaultSettlementMethodCode`（可空）。使用方以代碼呼叫 `IPaymentTermLookup.CalculateDueDateAsync`／`ISettlementMethodLookup.RequireActiveAsync`，所以預設值已停用時由這兩個契約回 422；MD 不在 `RequireApprovedAsync` 擋下往來對象。單據保存自己的付款條件代碼與到期日，修改往來對象預設值不回溯。
6. **頁面。** 客戶／供應商共用的 `PartnerList` 表單加兩個可清除的下拉（只列啟用項目，另保留目前已選但已停用的值），列表加「付款條件」欄。選項經 `/api/v1/md/payment-terms`、`/api/v1/md/settlement-methods` 讀取，所以編輯往來對象的使用者需要對應 VIEW 權限才看得到選項名稱；沒有權限時下拉為空，不影響其他欄位。

## 後果

- 新 migration `MasterData_PartnerPaymentDefaults`；舊資料兩欄為 null。
- 需求追加 REQ_F4118.1.8（客戶）與 REQ_F4118.2.8（供應商）；REQ_DS43.106（`md_customer`）與 REQ_DS43.108（`md_supplier`）升為 1.2。
- 測試用 DbContext 組合含客戶或供應商模型時，必須一併加入 `PaymentSetupDbModel`。
