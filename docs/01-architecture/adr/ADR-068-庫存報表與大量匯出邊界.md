# ADR-068：庫存報表與大量匯出邊界

- 日期：2026-10-18T05:06:22+08:00
- 狀態：Accepted
- 工作單元：WU-INV-017d

## 情境

現有結存、異動明細及批序號追溯均可分頁；前端 CSV 逐頁抓取，資料量大時會產生大量請求，而且頁與頁之間若有新過帳，匯出內容可能不一致。估值 SP 依 `posted_at, id` 計算公司物料的暫估金額，不能把業務日期的進出存數量直接當成同一口徑的會計金額。

## 決策

1. 新增唯讀的「進出存報表」：指定一個業務日期區間，按物料、倉庫、儲位列出期初、期間入、期間出、期末基本單位數量。期初只計 `business_date < from`，期間含 `from`／`to`，期末為三者相加。公司及可選物料／倉庫／儲位條件在 SQL 內套用；無異動的鍵不列。數量精度六位，負期末照實呈現並標示異常，不自動修正異動帳。
2. 查詢讀取一次資料庫一致性快照，並回傳 `queriedAt`；報表只含快照開始前已提交的異動。分頁按 `(item_id, warehouse_id, location_id)` 穩定排序，總數在同一查詢快照內計算。不同 HTTP 請求是不同快照，畫面要標示查詢時間；完整匯出由伺服器在**單一快照**內串流產出，不讓前端逐頁拼接。不得用 ID 上限代替提交快照，因交易提交順序不一定與 ID 一致。
3. 報表數量權限為新 `INV.REPORT.VIEW`；匯出另需 `INV.REPORT.EXPORT`。批序號追溯匯出保留 `INV.TRACKING.VIEW` 並另需 `INV.TRACKING.EXPORT`。匯出只含目前公司及畫面篩選條件；對非授權範圍回 403，不以空檔掩蓋權限錯誤。
4. 匯出格式先定為 UTF-8 BOM CSV，逐欄依既有安全規則防試算表公式注入；明確標示 `.csv`，不把它稱為原生 `.xlsx`。原生 XLSX 的工作表列數、記憶體與套件成本尚未驗證，本單元不承諾該格式；若業務要求，另列 backlog 及 ADR。大檔以 HTTP 串流、取消令牌及伺服器端列數上限控制，超上限回 422 並說明縮小篩選範圍，不回截斷卻標成功的檔案。
5. 進出存僅是數量報表，不乘暫估平均成本；金額仍由 ADR-063 的過帳時間估值契約處理。批序號歷史匯出沿用不可改寫追蹤明細與異動帳，不能把既有詳情端點「最近 1000 筆」當成完整匯出。
6. WU-INV-017 拆成 017d（需求、規則、契約與完整情境）、017a（先寫失敗的真實 SQL／HTTP 測試，再做進出存唯讀報表及索引量測）、017b（三語亮暗報表頁及伺服器 CSV、E2E）、017c（批序號完整歷史匯出、大量追溯效能與回歸）。父單元在三個實作切片全部驗收後結案；BI 跨模組儀表板仍屬 EP-BI1。

## 驗證界線

017d 不新增資料表、migration、API 或畫面。現有 `inv_stock_movement`（REQ_DS43.135）與追蹤明細（REQ_DS43.144）是唯一來源；017a 量測實際 SQL IO／計畫後才決定補充索引。快照隔離、無重漏分頁、匯出取消／上限與真實資料一致性，必須在後續測試中證明，不能以本 ADR 宣稱已實作。
