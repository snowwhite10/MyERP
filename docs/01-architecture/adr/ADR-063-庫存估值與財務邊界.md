# ADR-063：庫存估值與財務邊界

- 日期：2026-10-14
- 狀態：Accepted
- 工作單元：WU-INV-014d

## 情境

異動帳不可更新；期初及其他入庫保存單價，出庫、調撥及盤點盈虧的異動成本為空。單據上的出庫金額只是審批估算。直接把估值結果寫回異動帳會破壞過帳不可變性，也會把晚到的業務日期誤當作實際過帳順序。

## 決策

1. 採公司＋物料層級的**移動加權平均**，幣別先採公司記帳本位幣；同物料跨倉庫及儲位共用成本池。估值順序是 `posted_at, id`，查詢截止值也是過帳時間；`business_date` 只供顯示與財務期間對照，不改變已發生的成本順序。讀取已提交異動時以一致性快照計算；同一截止時間再次查詢可因較晚提交的異動而改變，故即時結果標為暫估。
2. 已知成本入庫的行值為 `quantity × unit_cost`，在異動行取四位小數、遠離零。出庫行值為 `quantity × (池內剩餘價值 / 池內剩餘數量)`，同樣在行層級取四位；清空成本池時取走全部剩餘價值，避免尾差。過程中數量六位、單價六位、行值四位，內部除法使用足夠的 SQL decimal 精度，最後檢查 `decimal(19,4)` 溢位。零成本是有效的已知成本。
3. `TRANSFER` 同來源的出入兩腿須按行號配對且數量相等，先驗證再作價值中性的單一事件，不受兩筆 ID 先後影響；不把目的入庫的 NULL 成本當作未定價。倉庫級金額不由本估值查詢推算，以免逐倉取整的尾差與公司總值不符。盤點淨增及其他 NULL 成本入庫沿用**入庫前**池內平均成本；若當時池內沒有已知成本基礎（明確零成本仍算已知），該物料標為 `Unpriced`，期末金額回 NULL，未定價數量回**全部在庫量**，因混合後無法可靠區分哪一單位未定價。未定價池在數量完全歸零後可由下一筆已知成本入庫重新開始；不得默默以零成本代替。盤點淨減按出庫處理。
4. 查詢 SP `usp_inv_value_item` 只讀 `inv_stock_movement`，參數為公司、物料、截止過帳時間；回期末數量、期末值、平均單價、未定價數量、估值狀態及處理的異動數。任何負池量、調撥不配對、算術溢位均報錯，不回看似有效的金額。公司及物料篩選在 SQL 內執行；以 `(company_id, item_id, posted_at, id)` 覆蓋索引支援順序讀取。SP 不查 MD／FI 表。
5. INV 的應用層提供唯讀估值契約；公開 API 需 `INV.VALUATION.VIEW`，只讀目前公司，`Unpriced` 明示而不輸出金額。FI 不直接讀 INV 表或呼叫 SQL；將來只透過 INV 契約取得估值。即時查詢**不得直接用來過帳總帳**。FI 月結要有獨立工作單元，在鎖定過帳窗口後持久化帶版本與高水位的估值快照，經 `IGlPostingService` 過帳差額及沖回，並處理較晚到的異動；此 ADR 不提前建立 FI 分錄或跨模組資料表。
6. 分批交付：014d 固定需求及驗收；014a 以真實 SQL 測試先行，實作唯讀 SP、migration、索引及內部查詢契約；014b 加受權 API、三語／暗色頁及 E2E。每段可獨立驗收，父單元在三段完成後結案。

## 後果與待驗證風險

過去的異動與業務單據均不需改寫。未定價庫存會阻止可靠的期末金額，後續成本調整單元須有審批及稽核，不能由報表自行猜價。大資料量的估值需測試 SQL 執行計畫、100,000 筆順序掃描及截止查詢；若不達標，再以可重建的估值快照優化，不能改成直接維護庫存彙總。
