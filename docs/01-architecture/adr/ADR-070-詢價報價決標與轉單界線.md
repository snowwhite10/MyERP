# ADR-070 詢價報價決標與轉單界線

- 狀態：採納
- 日期：2026-10-21
- 工作單元：WU-PUR-005a

## 背景

請購已可核准，但沒有詢價與供應商報價。後續採購單要引用已核准請購的剩餘量，同時保留比價時所見的價格及匯率證據。BlueWhale 購買基線只有採購單和採購入庫，MyERP 追加詢價、報價和逐行決標；新 ID 排在請購 4.3 之後。

## 決定

1. 詢價發送是系統內狀態轉換，固定需求行與受邀供應商。外部 email／供應商入口不在本單元範圍；介面不宣稱消息已送達供應商。
2. 一張詢價可收多家報價。報價修訂新增不可變版本，撤回及過期版本保留歷史但不參與比價。每個詢價／供應商只有一個目前有效報價表頭。
3. 比價按詢價行對齊物料與基本單位數量，展示原幣單價、MD 匯率日期及本位幣含稅行成本。缺有效匯率或稅率的報價不可排序、決標；逐行用 `Money.Round`，表頭由行加總。
4. 決標逐行選供應商並保留理由及商業快照；同一行只決標一次。轉單只聚合同一供應商已決標未轉行，在一筆交易建立採購單草稿與來源唯一連結。005e 建最小採購單草稿持久化，006 擴充完整訂單、審批與取消。轉單不改庫存，也不消耗請購量；006 的訂單提交才使用請購行鎖與餘量約束。此時若餘量變小，提交明確拒絕，不靜默縮量。
5. MD 與 SYS 的主檔、匯率、稅率、單號和資料範圍只透過公開契約查詢；PUR 表只存外模組 ID，不建立跨模組 FK。後續 INV 異動只經其公開 Application 契約。

## 理由與影響

不可變報價版本與決標快照讓日後價格、匯率或供應商主檔變更不會改寫決策證據。詢價不預留請購量，避免多家詢價凍結同一需求；採購單提交仍需重新驗餘量。005a 僅是需求、設計和測試情境基線；表與 API 在 005b～e 落地後才可宣稱驗收。
