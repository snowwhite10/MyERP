# ADR-061：庫存調撥拆分與守恆

- 日期：2026-10-13T23:52:38+08:00
- 狀態：Accepted
- 工作單元：WU-INV-009（拆為 009d 設計、009a 後端、009b 前端）

## 背景

WU-INV-009 同時要求草稿、SYS 審批、跨儲位雙向異動、批序號、三語介面與驗收。現有 `IInventoryPostingService` 已接受同一來源行號的 `Out` 與 `In`，並在同一交易檢查結存和批序號。先固定調撥單據與介面契約，避免後端及前端各自猜測出入庫行的配對方式。

## 決策

1. 分成 009d（需求、資料、API、介面、測試設計）、009a（migration、服務、API、真實 SQL／HTTP 測試）、009b（三語頁、列印／匯出、前端與 Playwright）。父單元待 009b 驗收完成才關閉。
2. 一行只描述一個物料與一對結存鍵：來源倉庫及可選儲位、目的倉庫及可選儲位、正數基本單位數量、可選批序號。來源和目的的倉庫／儲位組合不得完全相同；同倉不同儲位可調撥。兩側都經 MD guard 驗證目前公司、啟用狀態及儲位歸屬。草稿不寫異動。
3. 最終 SYS 核准在同一交易將每行展開為相同 `lineNo`、相同物料和數量的 `Out` 與 `In`，呼叫一次 `IInventoryPostingService.PostAsync`；來源類型 `TRANSFER`、來源 ID 為單據 ID。批序號清單複製到兩個方向，兩側完全相同。出庫及入庫成本皆留空，後續 WU-INV-014 估值處理價值轉移；SYS 審批金額為 0，按文件類型配置審批規則。單據 `Posted`、審批決定及兩個方向異動一起提交或回滾。
4. 來源結存鍵由既有過帳鎖序列化，不足回 `INV.STOCK.INSUFFICIENT`；批序號不足回既有 `INV.LOT.INSUFFICIENT`／`INV.SERIAL.NOT_AVAILABLE`。對序號而言，同一過帳來源的出入淨額為 0，不會誤判為重複入庫；目標位置已有該序號但來源位置沒有時仍拒絕。兩個並發調撥搶同一來源庫存只可有一方成功。
5. 草稿可先缺批序號；送審前須與 MD 追蹤方式相符、合計等於數量，單據內同物料序號不重複。草稿及駁回修訂採整組替換明細，版本衝突 409；僅草稿可軟刪除。重複審批不得再次過帳；相同過帳來源重放由 ADR-053／ADR-060 的內容快照辨別。
6. 表頭、明細及明細批序號分別為 `inv_transfer`、`inv_transfer_line`、`inv_transfer_line_tracking`（REQ_DS43.148–150）。物料、倉庫、儲位為 MD 跨模組 ID，不建 FK；INV 內子表用含 `company_id` 的複合 FK。每個外鍵與常用列表篩選建索引。

## 影響

調撥不直接修改庫存彙總。過帳後的異動帳仍只增不改；列印／匯出使用已保存的單據資料。009a 應先以真實 SQL 測試證明守恆、批序號轉倉、公司隔離、併發不足、核准回滾與重放，再實作單據。
