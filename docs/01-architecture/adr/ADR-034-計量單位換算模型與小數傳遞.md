# ADR-034 — 計量單位換算模型與小數傳遞

- 日期：2026-10-12
- 狀態：Accepted
- 工作單元：WU-MD-010（計量單位與換算）

## 背景

BlueWhale 的 `unit` 表（REQ_DS43.85）只有名稱，不能換算；MyERP 的 INV／PUR／SD 需要在單位之間換算數量（例如採購以箱、庫存以個）。需要決定：

1. 換算的形狀：每對單位各存一條？還是允許經中間單位推算？
2. 如何避免同一對單位有兩個互相矛盾的係數（A→B 與 B→A 各自設定，或 A→B→C 與 A→C 不一致）。
3. 前端以 JSON 傳遞 decimal 時，JavaScript `number`（雙精度浮點）會不會失真。
4. 物料專屬換算（例如某物料 1 箱 = 12 個）放在哪裡。

## 決定

1. **公司級換算邊，經路徑推算。** `md_uom_conversion` 每條記錄「1 個來源單位 = factor 個目標單位」；反方向以除法推得，經中間單位則沿路徑相乘／相除。分子與分母分開累乘，最後一次相除，再按**目標單位**的小數位數（`md_uom.decimal_places`，0–6）以 `MidpointRounding.AwayFromZero` 捨入。全部以 `decimal` 計算。
2. **兩單位之間最多一條路徑（換算圖為森林）。** 新增換算時，如兩單位已可互換（同一對、反向、或經其他單位），回 409 `MD.UOM_CONVERSION.PATH_EXISTS`。因此換算結果唯一，不會有循環或矛盾。並行新增以公司級 `sp_getapplock`（`md_uom_conversion:{companyId}`，交易範圍）序列化；另有 `(company_id, from_uom_id, to_uom_id)` 過濾唯一索引（`is_deleted = 0`）作最後防線。要改用其他路徑，先刪除（軟刪除）舊換算。
3. **換算係數上限 15 位有效數字**：`decimal(15,6)`，正數，最多 9 位整數及 6 位小數。15 位有效數字以內的十進位數經 JSON → JS `number` → JSON 可無損往返，前端因此可以照常用 JSON 數字傳遞係數，不需改全系統的序列化規則。前端只做格式驗證，不做數量運算；換算試算由後端 `GET /api/v1/md/uom-conversions/convert` 計算，數量以原文字放入查詢字串。
4. **物料專屬換算不在本單元。** 公司級換算只放與物料無關的換算（公斤↔公克等）。物料的包裝換算由 WU-MD-012 物料主檔決定（物料可覆寫或補充公司級換算），屆時另寫決策。
5. **其他模組只經契約換算。** `MyERP.Modules.MasterData.Contracts.IUomConverter.ConvertAsync` 是唯一入口；其他模組不得讀 `md_uom`／`md_uom_conversion`。

## 影響

- 已被（未刪除的）換算引用的單位不可刪除（409 `MD.UOM.IN_USE`），只可停用；停用單位不可新增換算，但既有換算仍可用於換算歷史資料。
- 單位的小數位數可修改；WU-MD-012 起若物料或單據已使用該單位，是否鎖定小數位數由該單元決定。
- 超過 15 位有效數字的業務數值（例如金額、數量）日後如需由前端輸入，必須另行評估（例如以字串傳遞），不可直接套用本 ADR。
