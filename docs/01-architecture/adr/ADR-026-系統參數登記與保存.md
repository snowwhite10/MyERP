# ADR-026：系統參數由模組宣告、按公司保存

- 日期：2026-10-11
- 狀態：採用（WU-SYS-010a）

## 背景

BlueWhale 的 Parameter Settings（4.1.1.8.17，介面 4.4.1.8.55）只有一張 `SystemSet` 表，每間分店一列，固定欄位混在一起：列印抬頭（公司、地址、電話）、是否啟用審批、是否禁止負庫存、列印 Logo／印章、四個商品自訂欄位名稱，以及第三方整合金鑰。畫面沒有預設值、範圍檢查或權限檢查（`CheckPower` 已註解）；數量／單價小數位數有欄位但沒有畫面。這些參數分屬庫存、主檔、列印等不同模組。

MyERP 的模組陸續開發，若用固定欄位，每加一個參數就要改 SYS 的資料表，SYS 也要知道其他模組的業務。

## 決定

1. **模組宣告參數**：`MyERP.Shared.Settings` 提供 `ParameterDefinition` 與 `IParameterDefinitionProvider`。每個模組宣告自己的參數：鍵 `{PREFIX}.{NAME}`（全大寫、最多 80 字，前綴必須屬於該模組）、畫面分組、型別（Boolean／WholeNumber／Number／Text／Option）、預設值與範圍／長度／選項。宣告錯誤（鍵格式、預設值不合規則、前綴不屬於模組、重複）在建立目錄時拋出。SYS 以 `ParameterCatalog` 彙整，做法與權限目錄（ADR-014）相同。
2. **按公司保存，只存修改過的值**：`sys_parameter`（REQ_DS43.73）每間公司每個參數最多一列，`(company_id, param_key)` 唯一。沒有資料列就用預設值，新模組加參數不必補資料。值以正規化字串保存：布林為 `true`／`false`，數字用不變文化且不用浮點，文字去除前後空白，選項保存為宣告時的寫法。
3. **批次保存**：`PUT /api/v1/sys/parameters` 一次保存多個參數，同一交易。先驗證全部項目，再把錯誤一次列出（欄位 `items[i].key`／`items[i].value`）。每項帶 `version`，未修改過為 0；版本不符或同時建立同一列回 409。值沒有改變就不寫入，不產生稽核記錄。修改經稽核 interceptor 記錄。
4. **讀取**：各模組在進程內經 `ISystemParameters` 讀取，不經 HTTP。同一請求只查詢一次。未宣告的鍵或型別不符視為程式錯誤（`ArgumentException`）。如果參數的型別或範圍收窄後，已保存的值不再合規則，讀取時改用預設值，下次保存時再驗證。
5. **權限**：`SYS.PARAMETER.VIEW`／`SYS.PARAMETER.EDIT`。沒有新增或刪除端點。
6. **參數歸屬**：SYS 這次只宣告數量小數位數（`SYS.QUANTITY_DECIMALS`，0–4，預設 2）與單價小數位數（`SYS.UNIT_PRICE_DECIMALS`，0–6，預設 4）。上限對應資料庫欄位 `DECIMAL(19,4)`／`DECIMAL(19,6)`；調整位數不改寫已保存的資料。BlueWhale 的其他欄位由各自模組在開發時宣告：禁止負庫存歸 INV，商品自訂欄位名稱歸 MD，列印抬頭與備註歸列印設定（WU-SYS-010c）。BlueWhale 的「啟用審批」由審批流程設定取代：某單據類型有啟用的流程才需要審批（ADR-022），所以不另設開關。第三方整合金鑰屬於機密，不是業務參數，不放進參數表。

## 後果

- 新模組加參數只需宣告，不需要 migration；SYS 也不必依賴業務模組。
- 值以字串保存，不能在資料庫層做型別約束，改由宣告和保存流程驗證。讀取時再驗證一次，以容許參數規則收窄。
- 參數畫面（WU-SYS-010b）依 API 回傳的型別、範圍與選項產生輸入欄位，參數和分組名稱由前端 i18n 按鍵翻譯。
