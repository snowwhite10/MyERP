# ADR-022：審批流程引擎的形式與跨模組整合

- 日期：2026-10-11
- 狀態：採用
- 工作單元：WU-SYS-009（第一段）

## 背景

MASTER_PROMPT 第 5 節要求共用的審批流程（多級、金額門檻、代理人）。舊系統 BlueWhale 每種單據只有單級「審核」功能，由各單據自行實作。MyERP 的採購、銷售、庫存、財務單據都需要審批，需要決定：

1. 引擎放在哪裏，各模組怎樣送審、怎樣接收結果，又不跨模組讀寫資料表；
2. 流程如何定義（多級、金額門檻、審批人類型）；
3. 修改流程對審批中單據的影響；
4. 代理、職責分離、併發與稽核的規則。

## 決定

1. **引擎屬於 SYS 模組，介面放在 `MyERP.Shared.Approvals`**（與 ADR-021 的單號產生相同模式）。
   - 送審：單據模組在進程內呼叫 `IApprovalWorkflowService.SubmitAsync(ApprovalSubmission)`，傳入單據類型 `{PREFIX}.{DOCUMENT}`、單據 Id、單號、本位幣金額與摘要。另有 `CancelAsync`（撤回）與 `GetStateAsync`（最近一次送審狀態）。
   - 結果：單據模組實作並以 DI 註冊 `IApprovalResultHandler`（依 `DocumentType` 分派）。審批人作出最終決定（最後一步核准或任一步駁回）時，引擎在**同一交易內、SaveChanges 之前**呼叫處理器（architecture.md 的「交易內事件」）；處理器拋出例外即整個審批動作回滾。
   - SYS 只存單據 Id（不建 FK），不讀寫其他模組的資料表；單據模組也不讀 SYS 的審批表，只經介面查狀態。
   - 不採用非同步訊息／Outbox：目前是單體應用，同一交易可保證單據狀態與審批記錄一致；日後拆分時再改為交易後事件。
2. **流程定義**：每公司每單據類型一條流程，1–10 個依次序執行的步驟。步驟審批人為「角色」（公司內任一擁有該啟用角色的啟用用戶，一人處理即可）或「指定用戶」。步驟可設最低金額，送審金額 ≥ 門檻才適用；沒有門檻的步驟一律適用。不支援會簽（多人同時核准）與條件分支，需要時另立工作單元。
3. **送審時複製步驟快照**：適用的步驟複製到 `sys_approval_instance_step` 並重新編號 1…n，連同「允許自審」設定一起保存。之後修改或停用流程不影響審批中的實例。沒有啟用流程或沒有適用步驟時自動核准，仍建立已核准實例作記錄，但**不呼叫結果處理器**——送審模組依 `SubmitAsync` 回傳狀態直接處理，避免同一呼叫中重入單據模組。
4. **同一單據最多一個審批中實例**：篩選唯一索引 `(company_id, document_type, document_id) WHERE status = 'Pending'`。送審前先查一次給出友善錯誤，併發送審由索引擋下並轉為 409 `SYS.APPROVAL.ALREADY_PENDING`。
5. **併發核准**：核准／駁回帶實例 `version`，以 EF 樂觀鎖保證同一步驟只有一位審批人成功（409）。
6. **職責分離**：送審人不可審批自己送審的單據（422 `SYS.APPROVAL.SELF_APPROVAL`），流程可設「允許自審」例外；自己送審的單據不出現在自己的待辦。
7. **代理**：被代理人在起訖日期內（含頭尾，業務日期 `IClock.Today`）把審批工作交給代理人，可處理被代理人的用戶步驟與角色步驟；步驟記錄同時保存實際處理人（`acted_by`）與被代理人（`on_behalf_of_user_id`）。代理不連鎖；同一被代理人的啟用期間不可重疊（409）。停用的用戶、角色或公司授權不能處理步驟。
8. **稽核**：審批實例的變更以新增的業務操作 `REJECT`（加入 `AuditActions.BusinessActions`）與既有的 `APPROVE` 經 `IAuditTrail.MarkAction` 記入 `sys_audit_log`，與審批動作同一交易。時間一律用 `IClock`。
9. **權限**：`SYS.APPROVAL_FLOW.*`、`SYS.APPROVAL_DELEGATION.*` 維護設定；`SYS.APPROVAL.PROCESS` 看待辦與核准／駁回（另須是目前步驟的審批人或其代理人）；`SYS.APPROVAL.VIEW` 看歷史與明細。

## 影響

- 單據模組送審：`var state = await approvals.SubmitAsync(new("PUR.ORDER", order.Id, order.No, order.AmountBase, order.SupplierName)); order.Status = state.Status == ApprovalStatus.Approved ? Approved : Submitted;`，並實作 `IApprovalResultHandler` 處理核准／駁回。
- BlueWhale 各單據的 Approve 功能將由各模組經本引擎實現，不各自實作審核欄位邏輯。
- 待辦查詢以 `(company_id, status, user_id)`、`(company_id, status, role_id)` 索引支援；用戶的角色與代理每次請求即時計算，不快取。
- 前端流程、代理、待辦頁面（介面 8.68–8.70）留待 WU-SYS-009 第二段。
