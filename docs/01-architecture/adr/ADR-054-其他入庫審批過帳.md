# ADR-054：其他入庫審批與過帳契約

- 日期：2026-10-13T17:42:52+08:00
- 狀態：Accepted（設計；程式待實作）
- 工作單元：WU-INV-004

## 情境

BlueWhale 的 Other Inbound 包含查看、建立、編輯、核准、駁回、刪除六項。MyERP 已有 SYS 單號及審批服務，INV 已有不可改寫異動帳與唯一過帳入口。需要明確規定核准與入庫的原子性及駁回後再送審。

## 決策

1. 建立 `inv_other_receipt` 與 `inv_other_receipt_line`。草稿不預留 `inv_reference`、不寫異動帳；建立及編輯時驗證 MD 引用與正數六位精度，最終過帳時由 `IInventoryPostingService` 再次驗證並持有 MD 共享鎖。單據明細保存提交時的 ID、數量、單價；已送審明細不可變。
2. 單號類型與審批類型均為 `INV.OTHER_RECEIPT`，庫存來源類型為 `OTHER_RECEIPT`。建立單據與 `INumberGenerator.NextAsync` 同交易，失敗回滾號段。沒有啟用規則時按 SYS 契約回業務錯誤，不自行拼單號。
3. 建立、編輯、軟刪除只接受草稿及相符版本。SYS 駁回後為 `Rejected`；編輯時轉回 `Draft`，保留原審批歷史。待審、已核准或已過帳不得改寫。單據端不直接提供核准或駁回端點。
4. 送審在交易內呼叫 `IApprovalWorkflowService.SubmitAsync`。若工作流立即核准，呼叫端在同一交易轉核准並過帳；若待審，後續 SYS 最終核准透過 `IApprovalResultHandler` 在 SYS 交易內過帳，駁回只改狀態。過帳失敗使 SYS 決定、單據狀態與庫存異動全部回滾。來源唯一與明細快照由 ADR-053 防重放。
5. 單據金額為各行基本單位數量乘入庫單價之和；輸入及合計範圍須驗證，金額提供 SYS 審批門檻使用。成本估值法於 WU-INV-014 決定，不在此改動異動帳成本。
6. 列印與 Excel 匯出讀已保存資料並受查看權限與公司篩選約束。三語、暗色模式與 E2E 按 INV UI 規格實作。介面次序按 MyERP 對照表固定為建立、查看、編輯。

## 後果

單據服務需要在同一 DbContext 交易內協調單號、SYS 審批、INV 過帳與單據狀態。正式上線前要有 SQL 並發與回滾測試，包括立即核准、多級核准、駁回、重送及軟刪除。`INV.OTHER_RECEIPT` 單號規則須由管理員建立或種子資料提供。
