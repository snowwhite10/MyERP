# ADR-059：物料期初庫存批次與冪等過帳

- 日期：2026-10-13T19:50:22+08:00
- 狀態：Accepted
- 工作單元：WU-INV-007

## 背景

BlueWhale 4.4.1.8.14 Product Initial Stock Interface 讓使用者按物料、倉庫輸入期初數量與單價。舊系統直接寫入可刪改的期初數量；MyERP 規定庫存只能經不可改寫的異動帳過帳（ADR-053），MD 不得保存數量。期初資料常一次大量輸入，網絡逾時後重送不可重複入庫。WU-INV-007 同時含 SQL、API、三語頁與 E2E，超過單輪 90 分鐘上限。

## 決策

1. 拆為 007a（資料表、預覽、冪等提交、API、真實 SQL／HTTP 測試）與 007b（三語頁、批次輸入、預覽錯誤顯示、列印／CSV、Playwright）。兩段完成才關閉 007。
2. 期初庫存是設定作業，不走 SYS 審批：有 `INV.OPENING_STOCK.CREATE` 的使用者提交後立即在同一交易保存批次並以來源類型 `OPENING_STOCK`、來源 ID = 批次 ID 呼叫 `IInventoryPostingService` 入庫。`INV.OPENING_STOCK.VIEW` 可查批次。
3. 新表 `inv_opening_stock`（批次表頭：請求鍵、啟用日期、備註、過帳時間）與 `inv_opening_stock_line`（物料、倉庫、可選儲位、基本單位數量、單價、金額）。批次與明細不提供修改或刪除；錯誤以其他入庫／出庫調整。
4. 每個公司的物料＋倉庫＋儲位（無儲位視為一個鍵）只能有一筆期初：服務檢查，資料庫以不帶篩選的唯一索引最後防線（SQL Server 唯一索引視 NULL 為相同值）。
5. 啟用日期不可晚於今天（`IClock`），也不可晚於該結存鍵已存在的最早異動業務日期，確保期初是該鍵的第一筆。並發的其他入庫不取結存鍵鎖，若在檢查後才提交，視為使用者同時操作；後續盤點可校正，記入 007a 已知限制。
6. 冪等：用戶端每次批次產生 `requestKey`（1–64 個英數、`-`、`_`，建議 GUID），公司內唯一。相同鍵相同內容重送回原批次（`replayed = true`）；內容不同回 409 `INV.OPENING_STOCK.REQUEST_CONFLICT`。提交先取公司級 `inv_opening_stock` 排他應用鎖，序列化同公司期初提交。
7. 逐行錯誤：格式錯誤（行號、ID、數量／單價精度）沿用 400 欄位路徑 `lines[i].field`；業務錯誤（MD 不存在／停用、儲位不屬倉庫、批次內重複、已有期初、晚於既有異動）由 `POST /preview` 逐行回報錯誤碼且不寫資料。提交時重新驗證，任一行有錯回 422 `INV.OPENING_STOCK.HAS_ERRORS`，與 MD 匯入的預覽／提交模式一致。

## 影響

期初金額只作為入庫單價快照，估值法仍由 WU-INV-014 決定。沒有刪除功能，若輸入錯誤需以其他出庫／入庫沖正，保留完整審計軌跡。
