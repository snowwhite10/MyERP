# ADR-043 — 客戶聯絡人與地址

- 日期：2026-10-12
- 狀態：Accepted
- 工作單元：WU-MD-004（客戶聯絡人與地址），沿用於 WU-MD-008（供應商聯絡人）

## 背景

BlueWhale 沒有聯絡人的 REQ_F，只有介面 **Client Contact Management Interface**（4.4.1.8.4）、**Supplier Contact Management Interface**（4.4.1.8.9），以及資料表 `ClientAddress`（REQ_DS43.6）、`ClientContact`（REQ_DS43.7）、`VendorLinkman`（REQ_DS43.77）。

舊系統（只參考業務規則）：

- 客戶聯絡人有姓名、手機、座機、QQ、送貨地址、首要聯絡人旗標；資料庫全部欄位可空，畫面沒有驗證。設為首要時先把同客戶其他聯絡人的旗標清除，所以最多一位首要，但不強制至少一位。
- 姓名只在新增時檢查同客戶不重複，修改時不檢查（供應商的檢查被註解掉）。
- 聯絡人在獨立頁面逐筆新增、修改、刪除，不與客戶一併保存；刪除是實體刪除，不檢查引用。
- 客戶列表以首要聯絡人帶出電話與地址。
- 客戶地址是另一張表（省市區、郵遞區號、收件人、電話、詳細地址、預設旗標，同樣最多一筆預設），由商城與報價單使用，沒有基礎設定畫面。
- 供應商聯絡人結構相同但沒有地址；沒有供應商地址表。

## 決定

1. **兩張客戶子表。** `md_customer_contact`（REQ_DS43.128，對應 REQ_DS43.7）與 `md_customer_address`（REQ_DS43.129，對應 REQ_DS43.6）。兩者有完整主檔欄位（啟用、軟刪除、版本、審計），以 `(company_id, customer_id)` 複合外鍵參照 `md_customer` 的 `(company_id, id)` 唯一約束，所以子資料不會掛到別公司客戶。
2. **聯絡人欄位。** 姓名必填（最多 100）；職稱（100）、手機（50）、電話（50）、電郵（200，須為單一合法地址，不接受顯示名稱或多個地址）、通訊軟體帳號 `messaging_id`（100，取代舊系統 QQ，可填 LINE／WeChat／WhatsApp）、備註（500）選填。不保存地址：送貨地址改由地址子表管理。姓名可重複（同名不同人），與舊系統修改時不檢查的實際行為一致。
3. **地址欄位。** 地址必填（最多 300，自由文字）；郵遞區號（20）、收件人（100）、電話（50）選填。不拆省市區：MyERP 面向台灣／香港，省市區結構不通用，且單據只需要完整地址文字。地址目前只作送貨用途；如需帳單地址，SD 開始時另行擴充用途欄位。
4. **唯一預設。** 每位客戶最多一位預設聯絡人、一筆預設地址，不強制至少一筆。新增或修改時設為預設，會先取消同客戶的原預設（舊系統行為）。這兩步在同一交易內，以公司級 applock 序列化；資料庫以篩選唯一索引 `ux_*_default`（`is_default = 1`）作最後防線。CHECK 保證預設必為啟用且未刪除：停用時若仍要求預設回 400 `isDefault`；刪除時自動取消預設。
5. **逐筆維護。** 子資料以 `/api/v1/md/customers/{customerId}/contacts|addresses` 逐筆新增、修改（帶版本）、軟刪除，不與客戶主檔一起保存，避免整批覆寫時的版本衝突。前端在客戶對話框以子表呈現。列表回傳全部未刪除資料（含停用），預設排第一，其餘按建立順序；每位客戶的資料量小，所以不分頁。
6. **權限。** 查看用 `MD.CUSTOMER.VIEW`，維護用 `MD.CUSTOMER.EDIT`（與儲位依附倉庫的做法相同，ADR-036），不另設權限。停用的客戶仍可維護聯絡人與地址；客戶不存在、已刪除或屬別公司時回 404 `MD.CUSTOMER.NOT_FOUND`，子資料不屬路徑上的客戶時回 404 `MD.CUSTOMER_CONTACT.NOT_FOUND`／`MD.CUSTOMER_ADDRESS.NOT_FOUND`。
7. **單據快照。** SD 單據帶出預設聯絡人與地址後，要保存姓名、電話與地址文字的快照，修改或刪除聯絡人不回溯，因此刪除不檢查引用。SD 讀取客戶聯絡人的契約，在 SD 開始時與客戶查詢契約一起加入 MD.Contracts。
8. **共用實作。** Domain 的 `PartnerChild`／`PartnerContact` 與 Application 的 `PartnerChildService<TPartner, TChild>` 是往來對象共用的；WU-MD-008 只需加 `SupplierContact`、`md_supplier_contact` 與 `md_supplier` 的 `(company_id, id)` 唯一約束。供應商不設地址表（舊系統與 BlueWhale 都沒有）。
9. **編號。** BlueWhale 沒有對應 REQ_F，所以追加 REQ_F4118.41.1–4（客戶聯絡人）與 REQ_F4118.42.1–4（客戶地址）；介面沿用 8.4。

## 影響

- WU-MD-004 拆為 004a（後端）與 004b（前端：客戶對話框的聯絡人與地址子表、三語、E2E、docgen）。
- 客戶列表顯示預設聯絡人電話留給 004b 決定（列表 API 可加欄位，不需改表）。

## 補充（WU-MD-004b，2026-10-12）

- **獨立對話框，不放在客戶編輯對話框內。** 客戶列表每列加「聯絡人」按鈕，開啟 `CustomerContactDialog`（上段聯絡人、下段送貨地址）。原因：子資料逐筆即時保存，若放在客戶編輯對話框內，使用者會以為按「取消」可撤銷子資料變更；而且只有 `MD.CUSTOMER.VIEW` 的用戶看不到編輯按鈕，但仍需查看聯絡人（唯讀）。做法與倉庫的儲位對話框相同（ADR-036）。
- **保存後重新讀取該段列表。** 設為預設會讓後端取消他筆預設並遞增其版本，所以不在前端自行調整，直接重讀，避免下一次修改用到舊版本。
- **停用不可勾預設** 在前端以表單驗證先擋（不送出），後端 400 `isDefault` 仍為最後防線。
- **客戶列表暫不顯示預設聯絡人電話。** 目前沒有使用情境需要在列表看電話；SD 開單會直接讀聯絡人契約。日後需要時在列表 API 加欄位即可，不需改表。
- `PartnerPage.contacts` 旗標控制是否顯示按鈕；WU-MD-008 供應商聯絡人可沿用同一對話框結構（只有聯絡人段）。
