# ADR-046：客戶主檔審批與刪除

- 日期：2026-10-13
- 狀態：Accepted
- 工作單元：WU-MD-023

## 情境

BlueWhale 客戶有核准、駁回、刪除操作；MyERP 已有 SYS 通用審批流程，但客戶主檔只有啟用狀態。停用不能表達審核結果，單據模組也不能直接讀 MD 或 SYS 資料表。

## 決策

1. `md_customer.review_status` 保存 Pending／Approved／Rejected。新客戶（含匯入）為 Pending；遷移前已存在的客戶設 Approved，避免升級後中斷既有交易。
2. `MD.CUSTOMER.APPROVE` 送審時以 `MD.CUSTOMER` 呼叫 `IApprovalWorkflowService`。沒有適用步驟時立即 Approved；有步驟時 SYS 審批人使用既有待辦 API，最終結果在同一交易內透過 `IApprovalResultHandler` 更新客戶狀態。Rejected 可再次送審，Approved 不可重送。
3. 客戶啟用與審核分開。交易使用方只經 MD Contracts 的 `ICustomerLookup.RequireApprovedAsync` 取得啟用且 Approved 的客戶，不直接讀表。客戶名稱或分類編輯不重啟審批；業務單據須保存客戶快照，主檔修改不回溯。
4. `MD.CUSTOMER.DELETE` 使用版本號軟刪除。Pending 不可刪，避免未完成審批回呼落到已刪記錄。單據使用方實作 `ICustomerUsage`，回報已引用時回 409；MD 不查詢其他模組資料表。被引用者只可停用。
5. Codex 環境的 TDD／Playwright Claude Skills 已由 ADR-011 記錄替代法；本單元直接使用 xUnit、Vitest、Playwright 及手動審查。

## 影響

SYS 流程未設定時，送審會立即核准。未來 SD 等模組加入客戶引用時，必須實作 `ICustomerUsage` 並在建立單據時呼叫 MD 的核准檢查；其併發一致性須在單據實作時以交易驗證。
