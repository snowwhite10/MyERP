# ADR-031 — 站內通知發布與隔離

- 日期：2026-10-11
- 狀態：Accepted
- 工作單元：WU-SYS-012a

## 背景

審批與後續業務模組需要向用戶發送站內通知，但模組不能直接讀寫 SYS 表。通知必須按公司及收件人隔離，且工作流程重試不能重複顯示訊息。

## 決定

1. SYS Contracts 提供 `INotificationPublisher`，由 SYS 實作及持久化。呼叫端提供目前公司可存取用戶、內容、站內路徑與穩定 `SourceKey`。
2. `sys_notification` 每列一位收件人，以 `(company_id, recipient_user_id, source_key)` 唯一索引去重。收件人須在公司中啟用；公司和用戶也須啟用。
3. 預設未讀，保留 90 天。012b 將加入本人收件箱、已讀 API 與清理策略。資料表由 migration `System_Notification` 建立。
4. 發布服務與呼叫端共用 scoped `MyErpDbContext`；呼叫端已有交易時，通知寫入參與同一交易。這能讓業務操作失敗時通知隨之回滾。

## 取捨

目前是資料庫站內通知，沒有即時推送。012b 先以讀取未讀數實現頂列徽章；後續如需即時傳送，再評估推送機制。並發使用相同來源鍵時，唯一索引防止重複列；衝突後呼叫端可重試以讀取原 Id。
