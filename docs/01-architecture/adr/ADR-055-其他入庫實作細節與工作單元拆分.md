# ADR-055：其他入庫實作細節與工作單元拆分

- 日期：2026-10-13T18:05:22+08:00
- 狀態：Accepted
- 工作單元：WU-INV-004a（補充 ADR-054）

## 情境

ADR-054 定下其他入庫的審批與過帳契約。實作後端時需要補充幾項細節：單號欄位長度、明細金額取整、狀態集合、駁回單據能否直接送審或刪除，以及失敗後的 DbContext 狀態。另外，整個 WU-INV-004（後端、三語頁、列印／匯出、E2E）超過單輪 90 分鐘上限。

## 決策

1. **拆分**：WU-INV-004 拆為 004a（資料表、服務、SYS 審批處理器、HTTP API、SQL 與 API 整合測試）及 004b（三語建立／查看／編輯頁、列印、Excel 匯出、Playwright）。列印與匯出隨前端交付，後端暫不提供 `/print`、`/export` 端點；004b 再決定是否在前端產生（沿用列表 API 篩選）。
2. **單號長度**：`document_no` 用 `VARCHAR(30)`，與 SYS 單號最長 28 字的約定一致（取代 ADR-054 設計稿的 40）。
3. **明細金額**：`inv_other_receipt_line.amount DECIMAL(19,4)` = `ROUND(quantity × unit_cost, 4)`（遠離零取整），在明細行保存；表頭金額 = 明細加總，不另存。入庫單據沒有幣別，單價以公司本位幣理解，因此不呼叫需要幣別的 `Money.Round`，固定取到金額欄位精度 4 位。整張單據金額須小於 10^15。
4. **狀態**：表 CHECK 只允許 `Draft`、`PendingApproval`、`Rejected`、`Posted`。核准與過帳同交易完成，不保存中間的 `Approved`；`posted_at` 只在 `Posted` 時有值。
5. **駁回單據**：`Rejected` 只能編輯（編輯後回 `Draft`）再送審，不能直接送審或刪除，以保證送審內容一定經過修訂步驟，審批歷史留在 SYS。
6. **軟刪除**：除 ADR-054 的 `deleted_at` 外，加上 `is_deleted` 以沿用共用軟刪除篩選；CHECK 保證只有草稿可被刪除且兩欄一致。單號不重用。
7. **交易與失敗**：服務自行開交易；失敗時回滾並 `ChangeTracker.Clear()`，避免已回滾的單據、SYS 審批實例或異動被同一 DbContext 誤存；版本衝突一律回 409。草稿保存時對不同的物料／倉庫／儲位組合各呼叫一次 MD guard，共享鎖持有至交易提交。

## 後果

- 004a 完成後，API 已可供 SYS 審批頁與日後前端使用；004b 需要在 UI 補上物料／倉庫名稱顯示（API 只回 ID，名稱由前端經 MD API 取得）。
- 如日後需要多幣別入庫成本，需另寫 ADR 加入幣別與匯率欄位，並改用 `Money.Round`。
