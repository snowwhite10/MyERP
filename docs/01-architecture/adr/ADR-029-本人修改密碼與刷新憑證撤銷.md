# ADR-029 本人修改密碼與刷新憑證撤銷

- 日期：2026-10-11
- 狀態：已採用
- 範圍：WU-SYS-011a、REQ_F4111.1.2

## 背景

登入密碼到期時不會發 Access Token，因此只提供需登入的修改密碼端點會令用戶無法自行恢復。Refresh Token 原存於 Redis，值只有用戶 Id；修改密碼時無法依用戶列出及撤銷所有工作階段。Access Token 是 15 分鐘無狀態 JWT。

## 決定

提供已登入的 `change-password` 與需帳密、一次性 Captcha 的匿名 `change-expired-password`。兩者共用密碼政策、舊密碼驗證及失敗鎖定；匿名入口在發 Token 前也檢查用戶與角色 IP 白名單。修改成功寫 `PASSWORD_CHANGE` 安全稽核，不記錄明文密碼。

Redis Refresh Token 值改為 `{userId}:{issuedTicks}`。刷新時以資料庫 `password_changed_at` 比較簽發時間，較早者拒絕。因此本人修改或管理員重設密碼後，先前簽發的全部 Refresh Token 失效，無須掃描 Redis。已登入入口可帶目前 Refresh Token，服務只在擁有者相符時原子刪除，再回傳新的一組 Token。

## 結果與限制

舊格式 Redis Token 在部署後無法刷新，用戶需重新登入。既有 Access Token 仍可使用至最多 15 分鐘到期；若要即時撤銷 Access Token，須另設版本／撤銷檢查並增加每次請求的查詢成本。密碼修改與稽核同次資料庫儲存，Refresh Token 撤銷由簽發時間判斷。
