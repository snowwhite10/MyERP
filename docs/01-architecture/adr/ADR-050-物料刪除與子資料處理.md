# ADR-050：物料刪除與專屬換算、圖片、屬性值的處理

- 日期：2026-10-13
- 狀態：Accepted
- 工作單元：WU-MD-028（REQ_F4118.3.4）

## 情境

WU-MD-022e 核對 BlueWhale 對照表時發現 `REQ_F4118.3.4`（delete product）沒有實作。物料目前有三類只屬於該物料的子資料：專屬換算（`md_item_uom_conversion`，可軟刪除）、圖片（`md_item_image`，內容存資料庫，實體刪除）、屬性值（`md_item_attribute_value`，隨整批取代實體刪除）。客戶／供應商刪除（ADR-046）與倉庫刪除（ADR-049）的做法是軟刪除、代碼保留、被引用時回 409。需要決定：有子資料時擋下刪除，還是一併刪除；以及與子資料寫入的併發處理。

## 決策

1. **軟刪除物料，代碼永久保留。** `DELETE /api/v1/md/items/{id}?version=`（`MD.ITEM.DELETE`）設 `is_deleted = 1`、`is_active = 0`。建立時以 `IgnoreQueryFilters` 檢查代碼，所以刪除後同代碼回 409 `MD.ITEM.DUPLICATE_CODE`；匯入把已刪除代碼視為「已存在」而略過。停用物料也可刪除。
2. **使用方回報使用中時擋下。** 在鎖內逐一詢問 `IItemUsage`（ADR-049）；任一回報有庫存、交易或單據時回 409 `MD.ITEM.IN_USE`，資料不變。訊息提示改為停用。
3. **子資料一併處理，不擋下。** 換算、圖片、屬性值只描述該物料本身，不是其他業務資料引用物料；要求使用者逐筆刪除才能刪物料沒有業務意義（圖片最多 10 張、屬性最多 50 個）。所以在同一交易內：
   - 專屬換算軟刪除（與換算刪除 API 一致，保留稽核軌跡）；
   - 屬性值實體刪除（與 `ReplaceAsync` 移除屬性值一致）；刪除後屬性定義不再被使用，可以刪除定義；
   - 圖片實體刪除，釋放資料庫空間；以中繼資料附加實體後刪除，不讀取最大 2 MB 的內容（沿用 MD-B08 做法），稽核記錄以 `size_bytes` 表示大小。
   確認對話框文字說明子資料會一併刪除、代碼不可再使用。
4. **鎖。** 刪除在交易內依名稱順序取得 `md_item`、`md_item_attribute`、`md_item_image`、`md_item_uom_conversion` 的公司排他鎖（`CompanyLock.RunAsync` 多表多載）。其他寫入端只持有其中一把排他鎖（新增換算、改基本單位：換算鎖；圖片：圖片鎖；屬性：屬性鎖），不會形成循環等待。新增圖片與取代屬性值改在鎖內再確認物料存在，避免檢查後、保存前物料被刪而產生孤兒資料；新增換算原本就在鎖內讀物料。修改／刪除換算與圖片都以版本或既有資料為準，物料刪除後回 404 或 409。
5. **`md_item` 鎖預留給使用方。** INV／SD／PUR 寫入引用物料的資料時，應在驗證到保存期間取 `md_item` 共享鎖（經 Contracts 提供的 Lookup），與物料刪除互斥；與 ADR-049 第 6 點一樣由第一個使用方設計（WU-MD-026）。

## 後果

- 新增權限 `MD.ITEM.DELETE`、錯誤碼 `MD.ITEM.IN_USE`（三語）；種子角色依權限目錄規則展開。
- 物料頁新增刪除鈕：確認對話框、刪除中停用按鈕、404／版本衝突後重新查詢（沿用倉庫頁 MD-F05／F06 做法）。
- 測試：MD-ITEM-DEL-001～005（整合）、MD-ITEM-DEL-UI（Vitest、Playwright）。
