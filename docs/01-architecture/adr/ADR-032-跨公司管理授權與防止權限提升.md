# ADR-032 — 跨公司管理授權與防止權限提升

- 日期：2026-10-11
- 狀態：Accepted
- 工作單元：WU-SYS-016a（SYS 模組代碼審查 SYS-B01、SYS-B02、SYS-B04）

## 背景

`[RequirePermission]` 只檢查 `X-Company-Id` 指定的公司（ADR-014）。SYS 模組代碼審查發現三類動作會影響其他公司，但只檢查了目前公司：

1. 用戶權限對話框可替用戶設定**其他公司**的角色（ADR-017），之前只要求操作者「獲授權」該公司，未要求在該公司有 `SYS.USER.EDIT`。
2. 修改公司（`PUT /companies/{id}`）可修改任何獲授權的公司，未要求在該公司有 `SYS.COMPANY.EDIT`。
3. 用戶帳號（啟用狀態、密碼、鎖定）是全系統一份。公司 A 的管理員可重設同時屬於公司 B 的集團管理員密碼，從而取得其在 B 的權限。

另外，任何有 `SYS.USER.EDIT` 的人都可把全權角色指派給別人（或請同謀者指派給自己），等於權限提升。

## 決定

新增 `AuthorityGuard`（SYS Application 層）：

1. **目標公司權限**：影響其他公司的動作，操作者在目標公司（含已停用公司，以便重新啟用）必須有相應權限，否則 403 `COMMON.PERMISSION.DENIED`。用於指派角色（`SYS.USER.EDIT`）和修改公司（`SYS.COMPANY.EDIT`）。
2. **角色上限**：指派時**新增或移除**的角色都必須在操作者權限之內，否則 403 `SYS.ROLE.BEYOND_AUTHORITY`。具體規則：
   - 全權角色只可由在該公司全權的操作者處理；
   - 一般角色的每個權限，操作者都必須擁有，而且資料範圍不窄於角色的範圍。

   移除也受限，因此低權限管理員不能降級高權限管理員。
3. **不可變更自己的角色**：回 422 `SYS.USER.SELF_ROLE_CHANGE`。角色集合不變時，仍可修改自己的組織歸屬與預設公司。
4. **管理多公司用戶**（停用／啟用、重設密碼、解除鎖定）：
   - 用戶必須屬於目前公司，否則 404，維持 ADR-016 不透露他公司用戶的做法；
   - 操作者在用戶每間**已啟用關聯**的公司都必須有該動作的權限，且用戶在該公司的角色不超出操作者權限；
   - 操作者處理自己的帳號時不做此檢查；自我停用仍由服務以 422 拒絕。

## 取捨

- 角色與 IP 白名單目前仍是全系統資源，任何公司的角色／白名單管理員都可修改（審查 SYS-B03）。這需要另立「系統層權限」的設計，已排入 WU-SYS-016b，本 ADR 不處理。
- 「範圍不窄於」以 `DataScope` 數值比較（Self < Department < Branch < Company）。
- 已不在權限目錄的舊權限代碼仍參與比較。操作者不可能擁有這些代碼，所以含這類代碼的角色只有全權操作者可以處理。這是偏保守的選擇。
- 檢查需要多次查詢：每間受影響公司查一次授權，再查一次角色權限。管理動作頻率低，可接受。
