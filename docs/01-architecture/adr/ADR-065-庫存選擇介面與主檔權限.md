# ADR-065：庫存選擇介面與主檔權限

- 日期：2026-10-14T15:18:56+08:00
- 狀態：已接受
- 工作單元：WU-INV-016d

## 背景

BlueWhale SRS 4.4.1.5.20 有 Select Data Interface。現有 INV 單據以各自的下拉欄位預載 MD 物料、倉庫與儲位；MD 列表 API 要求 `MD.ITEM.VIEW` 或 `MD.WAREHOUSE.VIEW`。只持 INV 單據權限的使用者無法取得選項。共用 `ErpDialogService.select()` 已有搜尋、分頁、單／多選與跨頁保留能力，但 INV 尚未使用。一次載入全部主檔亦無法適應大量資料。

## 決定

1. 以 5.20 Select Data Interface 作為 INV 的共用彈窗，提供物料、倉庫、儲位三種模式。沿用 `ErpDialogService.select()`；各模式提供代碼、名稱和穩定 ID，不複製 MD 主檔或新建 INV 主檔表。
2. INV 提供三個唯讀分頁選項端點，通過 MD Contracts 的應用介面取得資料，不能由 INV DbContext 直接查 MD 表。`INV.*.VIEW` 單獨不構成編輯權限；端點只接受現行 INV 表單的 CREATE／EDIT 權限之一。後端逐一宣告允許的權限政策；前端路由維持既有表單權限。這些端點不要求 MD 主檔 VIEW，亦不能取得停用、軟刪除或他公司資料。
3. 物料與倉庫可按代碼／名稱搜尋；儲位必須先給目前公司啟用倉庫 ID，只查其下屬啟用儲位。結果按代碼、ID 穩定排序，採伺服器分頁，搜尋時回第一頁；快速改關鍵字或切換倉庫時丟棄舊回應。
4. 選項只供輸入便利。保存及送審仍由既有 `IInventoryReferenceGuard` 在交易內驗證並鎖定 MD 引用。編輯既有單據若引用已停用主檔，應顯示已保存代碼／名稱或 ID 與「停用」狀態，不把它列入新選項；再次提交時由後端拒絕。
5. 016a 先交付 API 與真實 SQL／HTTP 測試；016b 接入 INV 單據及三語、暗色與 E2E。每張表單不再預載全部主檔，避免選項數隨主檔量放大。

## 考量

直接開放 MD 主檔 VIEW 會讓單據使用者看到主檔管理列表及較多欄位，權限過寬。INV 專用端點僅回選擇所需欄位，同時由 MD 模組維持資料擁有權。現有 `IValuationItemScope` 只服務估值，包含停用物料的歷史查詢語意，不適合用於新增單據選項。

## 驗收

對應 REQ_F4115.20.1–3、REQ_IO_A5.20.1–6、INV-SEL-001–006。API 必須有 Swagger 說明、ProblemDetails、公司隔離與分頁邊界；前端需在建立／編輯單據驗證搜尋、取消、確認、倉庫變動清空儲位、三語及暗色。此 ADR 只定契約，不宣稱實作完成。
