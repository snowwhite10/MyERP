# ADR-066：組裝單與 PP BOM 的邊界

- 日期：2026-10-15
- 狀態：Accepted
- 工作單元：WU-INV-011d

## 背景

BlueWhale 將 Product Assembly 列在 Inventory，BOM List 列在 Production。MyERP 的 PP 尚未開始；若組裝入庫必須先有 PP BOM，INV 的現場簡單組裝便無法獨立交付。舊系統 schema 也把 BOM 與生產單分開；此處只取業務分工，不複製表或程式。

## 決定

INV 擁有組裝單、已保存的成品與耗料明細、審批狀態及庫存過帳。建立單據時手動輸入一個成品和一至多個組件，不要求 PP BOM。PP 日後可透過自己的 Application 契約提供已核准 BOM 的唯讀建議；INV 只保存被選定時的 BOM ID／版本作來源註記及展開後的明細快照，絕不直接讀寫 PP 表。BOM 之後變更不會改寫組裝草稿或已過帳單；用戶須明確重新套用並確認差異。這項建議功能由 PP 工作單元另行設計，不在 WU-INV-011 交付範圍。

每張組裝單恰有一個成品行與至少一個耗料行。INV 最終核准時以同一交易對耗料 Out、成品 In 過帳，來源固定 `ASSEMBLY`，兩類異動行號不重用。耗料按核准時 INV 移動平均估值取得成本；無可靠成本時拒絕核准，成品入庫單價由耗料總值除以成品數量得出，按現有估值精度及四位行金額取整。成本計算與異動必須使用一致的已鎖定快照；完整算法在後端切片以真實 SQL 測試固定。不得自行 UPDATE 庫存彙總或改已過帳異動。

## 後果

組裝可先於 PP BOM 使用，PP 的 BOM 主檔與審批規則仍屬 PP。組裝成本轉移需要新增 INV 內部原子估值契約，不能讓 HTTP 用戶端提供最終成本。批序號、公司隔離與審批沿用既有 INV／SYS 契約。
