# ADR-053：庫存異動帳過帳與結存

- 日期：2026-10-13
- 狀態：Accepted
- 工作單元：WU-INV-003

## 情境

ADR-051 確立不可改寫異動帳與禁止負庫存。各來源單據會分別實作審批，但必須共用防重放、引用安全及結存判斷，否則並發出庫可能超賣。

## 決策

1. 以進程內 `IInventoryPostingService` 作唯一寫入入口。來源單據服務須在同一交易確認其公司與核准狀態，再呼叫過帳服務。過帳服務不直接讀其他模組的單據表。HTTP 端點由具體單據與 WU-INV-006 提供。
2. `inv_stock_movement` 每行保存來源類型、ID、行號、方向、物料／倉庫／儲位、基本單位正數數量、可選入庫單價、業務日期、過帳時間及引用 ID。同公司複合外鍵連到 `inv_reference`，跨模組主檔不建外鍵。資料庫來源行唯一鍵、防非法值 CHECK 及不可 UPDATE／DELETE 的 trigger 作最後防線。
3. 過帳先取公司來源排他鎖，查已有完整來源；相同內容回既有 ID，任何日期或行明細差異回 409。然後依行取得 MD 共享鎖並保存引用，再依排序後的出庫結存鍵取得排他鎖。相同結存鍵的出庫在鎖內用異動帳已提交總量加本次淨額檢查非負。引用與異動同交易提交；若呼叫端已有交易則由呼叫端提交。
4. 結存即時由不可改寫異動帳按方向加總，不建可被直接修改的彙總表。公司、物料、倉庫、儲位索引 INCLUDE 方向與數量，支援目前規模；報表大量資料效能於 WU-INV-017 驗證。估值成本法仍由 WU-INV-014 決定。
5. 基本單位數量與入庫單價最多六位小數，超過資料庫精度時拒絕，不隱式四捨五入。出庫單價不由呼叫端決定。過帳服務信任呼叫端已完成基本單位換算，並自行再次驗證數值範圍。

## 後果

各單據服務要把核准狀態檢查與 `PostAsync` 放在同一交易。只有服務介面可供跨模組呼叫；直接改異動帳被資料庫拒絕。尚未建立對外 HTTP 查詢頁，WU-INV-006 補充權限、Swagger、三語介面與 E2E。
