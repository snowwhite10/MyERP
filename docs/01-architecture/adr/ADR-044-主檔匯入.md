# ADR-044 — 主檔匯入（客戶匯入起）

- 日期：2026-10-12
- 狀態：Accepted
- 工作單元：WU-MD-005（客戶匯入），沿用於 WU-MD-009（供應商匯入）、WU-MD-014（物料匯入）

## 背景

BlueWhale 有 REQ_F4118.1.7「System should enable user to import records of clients from excel spreadsheets」與介面 **Client Import Interface**（4.4.1.8.5）。

舊系統（只參考業務規則）：

- 提供空白範本與範例檔下載；只接受 `.xls`／`.xlsx`，以固定工作表名稱讀取，欄名是中文。
- 一列一位客戶：編號、名稱、類別（以名稱找類別，找不到就留空）、稅號、銀行、地址、備註，以及期初應收／預收款與餘額日期；同列可帶一位聯絡人（姓名、手機、座機、QQ、送貨地址、是否首要）。編號與名稱都空白、只有聯絡人的列，視為上一位客戶的追加聯絡人。
- 編號或名稱已存在的客戶直接略過，不更新，也不報錯；最後只回報「匯入了 N 位客戶、M 位聯絡人」，沒有逐列錯誤，也沒有預覽。
- 每列各自寫入，沒有整批交易：中途失敗時前面的列已寫入。

## 決定

1. **檔案格式。** 接受 `.xlsx`（讀第一個工作表）與 `.csv`（UTF-8，可有 BOM，逗號分隔，RFC 4180 引號規則）。依內容判斷格式，不信任副檔名：ZIP 簽章視為 xlsx；舊式 `.xls`（OLE 簽章）或含 NUL 的二進位檔回 422 `COMMON.IMPORT.UNSUPPORTED_FORMAT`；不是合法 UTF-8 的 CSV（例如 Big5）回 422 `COMMON.IMPORT.INVALID_ENCODING`，提示另存為「CSV UTF-8」；損壞的 xlsx 回 422 `COMMON.IMPORT.INVALID_FILE`。讀取器 `TabularFileReader` 與範本產生器 `TabularTemplate` 放在 `MyERP.Shared.Infrastructure.Import`，供供應商與物料匯入沿用；xlsx 用已在 ADR-001 固定的 `DocumentFormat.OpenXml`。
2. **上限。** 檔案最大 2 MB（超過回 422 `COMMON.IMPORT.TOO_LARGE`），資料列最多 1,000 列（`COMMON.IMPORT.TOO_MANY_ROWS`）；xlsx 每個部件解壓後最多 2,000 萬字元，防止壓縮炸彈。整列空白的列略過，不計入。
3. **欄位以固定英文鍵為表頭。** 第一列是表頭，比對時不分大小寫、去前後空白；未知欄位忽略（使用者可加備註欄），同名欄位重複回 422 `COMMON.IMPORT.DUPLICATE_COLUMN`，缺少必填欄位回 422 `COMMON.IMPORT.MISSING_COLUMN`。表頭不翻譯，三語畫面列出各欄說明；這樣同一個檔案在三種語言介面都可以匯入。客戶欄位：`code`*、`name`*、`categoryCode`、`contactName`、`contactMobile`、`contactPhone`、`contactEmail`、`address`、`postalCode`、`recipient`、`addressPhone`。
4. **一列一位客戶，最多帶一位聯絡人與一筆地址。** 不採用舊系統「空白列追加聯絡人」：列的意義會依前一列而變，排序或篩選後就錯。聯絡人與地址都設為預設；有其他聯絡人或地址的需求，在聯絡人對話框維護。類別以**代碼**對應同公司**啟用**的客戶分類（名稱可能重複），找不到時報錯，不默默留空。稅號、銀行等欄位 MyERP 客戶主檔目前沒有；期初應收／預收屬 FI 期初，不在 MD 匯入。
5. **先預覽，再整批提交（無狀態）。** `POST /api/v1/md/customers/import/preview` 只驗證不寫入，回傳逐列結果；`POST /api/v1/md/customers/import` 重新上傳同一檔案，重做全部驗證後在單一交易內寫入。伺服器不暫存檔案（沒有暫存表、沒有清理排程），兩次上傳之間資料變更也會在提交時重新檢查。只要有任何錯誤列，提交整批拒絕：422 `MD.CUSTOMER_IMPORT.HAS_ERRORS`，不寫入任何資料。
6. **逐列結果。** 每列為 `Create`（將新增）、`Skip`（代碼已存在）或 `Error`；錯誤以 `(field, code)` 表示，code 為 `REQUIRED`、`INVALID`、`DUPLICATE_IN_FILE`、`NOT_FOUND`，前端依欄位與代碼組三語訊息。列號是檔案的實際列號（表頭為第 1 列），方便使用者對照。驗證規則直接重用客戶、聯絡人、地址的維護驗證（ADR-043），不另寫一套。
7. **冪等：以代碼判斷，已存在就略過，不更新。** 代碼已存在於本公司（含停用與已刪除）的列為 `Skip`，其他欄位不再驗證，所以同一檔案重複匯入結果不變（第二次全部略過）。不提供「更新現有客戶」：整批覆寫會繞過版本檢查，還可能把已在使用中的客戶改名或改分類；修改請在畫面逐筆進行。同一檔案內代碼重複時，第一列有效，後續列為 `DUPLICATE_IN_FILE` 錯誤。名稱可以與現有客戶重複（主檔本來就允許同名）。
8. **併發。** 提交以公司級 applock `md_customer_import:{companyId}` 序列化並在交易內重做驗證；若同時有人以畫面新增相同代碼，唯一索引擋下後整批回滾，回 409 `MD.CUSTOMER.DUPLICATE_CODE`。
9. **權限與稽核。** 新增 `MD.CUSTOMER.IMPORT`（範本下載、預覽、提交都需要；舊系統也是獨立權限），種子資料只有 ADMIN 有。每筆新增由 SaveChanges interceptor 寫稽核日誌；另寫一筆 Information 應用程式日誌（新增數、略過數）。
10. **範本。** `GET /api/v1/md/customers/import/template?format=xlsx|csv` 只產生表頭列；CSV 帶 UTF-8 BOM，讓 Excel 正確顯示。
11. **編號。** 使用 BlueWhale 的 REQ_F4118.1.7；介面沿用 8.5。

## 影響

- WU-MD-005 拆為 005a（共用 xlsx／CSV 讀取器、範本與單元測試）、005b（客戶匯入服務、API、權限與整合測試）與 005c（匯入對話框、預覽表、三語、E2E、docgen）。拆分讓每輪能獨立建置與驗收。
- 供應商匯入（WU-MD-009）沿用讀取器、結果型別與流程；物料匯入（WU-MD-014）同樣不含期初庫存。

## 補充（2026-10-12，WU-MD-009 供應商匯入）

- 第 3–10 點全部套用於供應商，差異只有：權限 `MD.SUPPLIER.IMPORT`、路徑 `/api/v1/md/suppliers/import`、鎖 `md_supplier_import:{companyId}`、錯誤碼 `MD.SUPPLIER_IMPORT.HAS_ERRORS`／`MD.SUPPLIER.DUPLICATE_CODE`。
- 供應商沒有地址子表（ADR-043），範本欄位只有 `code`*、`name`*、`categoryCode`、`contactName`、`contactMobile`、`contactPhone`、`contactEmail`。檔內若有 `address` 等欄位，依第 3 點當作未知欄位忽略，不報錯（使用者可能直接拿客戶檔改用）。
- 後端抽出 `PartnerImportService<TPartner,TCategory>`，客戶／供應商子類只提供建立主檔、聯絡人（客戶另有地址）的方法與欄位清單；結果型別改名 `PartnerImportRow`／`PartnerImportResult`，JSON 不變。前端對話框改為 `PartnerImportDialog`，以 `kind` 決定路徑、錯誤碼、標題與 data-testid。
