# ADR-045 — 物料圖片與屬性

- 日期：2026-10-12
- 狀態：Accepted
- 工作單元：WU-MD-013（物料圖片與屬性），拆為 013a（圖片後端）、013b（屬性後端）、013c（三語頁面）

## 背景

BlueWhale 沒有物料圖片或屬性的 REQ_F，只有介面 **Product Image Interface**（4.4.1.8.15）、**Product Details Interface**（4.4.1.8.16），以及資料表 `GoodsImages`（REQ_DS43.60）、`GoodsAttribute`（REQ_DS43.32）；SDS 另有物料與屬性的連結表 `GoodsAttributeList`。

舊系統（只參考業務規則）：

- 圖片存到網站目錄，資料庫只存檔名；檔名改成時間戳，另存一份 500×500 以內的縮圖。只看副檔名（JPG／GIF／PNG），大小以整數 MB 粗略判斷約 1 MB。
- 每個物料圖片數量不限；最多一張「預設圖」，設新預設時先清除舊的。列表以預設圖排第一，沒有其他排序欄位；商品列表顯示預設圖，沒有時顯示「無圖片」。
- 刪除圖片只刪資料列，檔案留在磁碟，也不會改指定其他預設圖。
- 「輔助屬性」只是一份名稱清單（名稱唯一、顯示順序），列表顯示使用的物料數；被物料使用時不可刪除。連結表沒有「值」欄位，程式也從未新增連結，所以實際上規格只寫在物料的自由文字規格欄。

## 決定

### 圖片（WU-MD-013a）

1. **存在資料庫。** 新增 `md_item_image`（REQ_DS43.131，對應 REQ_DS43.60），內容為 `varbinary(max)`，連同類型、原始檔名、大小、寬高、排序號、主圖旗標與 6.4 節必備欄位（沒有 `custom_fields`／軟刪除：圖片是物料的附屬內容，不是主檔）。理由與 ADR-028 相同：與資料一起備份與公司隔離，部署不必設定共用目錄，沒有路徑穿越或檔案殘留問題。列表 API 只投影中繼欄位，不讀取內容。
2. **以內容判斷類型。** 沿用 ADR-028 的檢查：只接受 PNG 與 JPEG，由檔頭簽章判斷，不看副檔名或 Content-Type；GIF、WebP、SVG 拒絕。檢查程式由 SYS 移到 `MyERP.Shared.Infrastructure.Imaging.ImageInspector`，SYS 公司圖片與 MD 物料圖片共用（模組之間不可互相引用實作）。
3. **上限。** 每張 1 B–2 MB（商品照片比 Logo 大）；寬、高各 16–4096 像素；每個物料最多 10 張。超過時回 422 `MD.ITEM_IMAGE.TOO_LARGE`／`INVALID_DIMENSIONS`／`LIMIT_REACHED`，類型不符 422 `MD.ITEM_IMAGE.UNSUPPORTED_TYPE`；沒有檔案或空檔 400 `file`。上傳端點以 `RequestSizeLimit` 限制整個請求（2 MB + 表單欄位）。
4. **不產生縮圖。** 伺服器不解碼影像（沒有跨平台影像函式庫，System.Drawing 只支援 Windows），前端以 CSS 縮放顯示。每張最多 2 MB、每物料 10 張，列表只載入主圖，影響可接受。
5. **主圖與排序。** 有圖片的物料恰好有一張主圖：第一張上傳的圖片自動成為主圖；上傳或修改時可指定為主圖，會在同一交易內取消原主圖；不可直接取消主圖（400 `isPrimary`，請把另一張設為主圖）；刪除主圖時，由排序號最小（相同時 id 最小）的圖片接任。排序號 0–9999，上傳時預設為目前最大值 + 1，可帶版本修改；列表按主圖、排序號、id。資料庫以篩選唯一索引 `ux_md_item_image_company_id_item_id_primary`（`is_primary = 1`）作最後防線。
6. **序列化。** 上傳、修改、刪除以公司級 applock `md_item_image` 序列化，確保張數上限與主圖接任在併發下仍正確。
7. **實體刪除。** 刪除帶版本，直接刪除資料列；稽核日誌記錄 DELETE，內容欄位記為 `(binary N bytes)`。物料目前不可刪除（REQ_F4118.3.4 未實作），日後實作時一併刪除圖片。
8. **下載。** `GET …/images/{id}/content` 回傳儲存的類型，`Content-Disposition: inline`、`ETag` 為版本號、`Cache-Control: private, no-cache`，帶 `If-None-Match` 且未變更時只查版本並回 304。前端以 HttpClient 取得 Blob 再轉成 `data:` URL（與 ADR-028 相同，前端 CSP 不必加 `blob:`）。
9. **權限與路徑。** `/api/v1/md/items/{itemId}/images`；查看用 `MD.ITEM.VIEW`，上傳、修改、刪除用 `MD.ITEM.EDIT`（與物料專屬換算相同，不另設權限）。停用物料仍可維護圖片；物料不存在或屬別公司 404 `MD.ITEM.NOT_FOUND`；圖片不屬路徑上的物料 404 `MD.ITEM_IMAGE.NOT_FOUND`；舊版本 409。
10. **其他模組。** 目前沒有使用方；SD 列印或商城需要主圖時，再於 MD.Contracts 加讀取介面，不讀 `md_` 表。

### 屬性（WU-MD-013b）

11. **屬性定義加物料屬性值。** 舊系統的屬性只有名稱、沒有值，無法表達「顏色＝紅」。MyERP 改為兩張表：
    - `md_item_attribute`（REQ_DS43.132，對應 REQ_DS43.32）：公司級屬性定義，沿用分類基底（代碼、名稱、啟用、軟刪除）加排序號；
    - `md_item_attribute_value`（REQ_DS43.133，對應 SDS 的 `GoodsAttributeList`）：物料、屬性、值（nvarchar(200) 自由文字），同一物料同一屬性只有一個值。
12. **維護方式。** 物料的屬性值以 `PUT /api/v1/md/items/{itemId}/attributes` 整批取代（請求帶完整的屬性集合，以公司級 applock 序列化），每物料最多 50 個；新設定的屬性必須啟用，原有值的屬性停用後仍可保留。屬性定義被物料使用時不可刪除（409 `MD.ITEM_ATTRIBUTE.IN_USE`），只可停用；列表帶使用的物料數（舊系統規則）。
12a. **實作補充（WU-MD-013b，2026-10-12）。** 實體類別命名為 `ItemAttributeDefinition`（程式碼分析 CA1711 不允許型別以 Attribute 結尾；表名仍為 `md_item_attribute`），migration 為 `MasterData_ItemAttributes`。整批取代的請求錯誤一律 400 並帶索引鍵：集合缺少或超過 50 個為 `attributes`，屬性缺少／重複／不存在／停用的新屬性為 `attributes[i].attributeId`，值為 `attributes[i].value`；屬性刪除與整批取代共用公司鎖 `md_item_attribute`，物料屬性取代不帶物料版本（最後寫入為準）。需求 REQ_F4118.45.1–6。
13. **不做 SKU 變體。** 屬性只是描述性規格，不產生子物料或變體矩陣；需要時另立工作單元。

### 編號與拆分

14. BlueWhale 沒有對應 REQ_F，追加 REQ_F4118.44.1–4（物料圖片：查看、上傳、修改主圖與排序、刪除）與 REQ_F4118.45.x（物料屬性，013b 分配）；介面沿用 8.15（Product Image）與 8.16（Product Details，013c 決定內容）。
15. 013a 只做圖片後端；013b 做屬性後端；013c 做物料頁面的圖片與屬性三語對話框、E2E、docgen。

## 影響

- SYS `CompanyImageService` 改用共用的 `ImageInspector.ReadLimitedAsync`／`SafeFileName`，行為不變。
- 資料庫備份含物料圖片，最大約為物料數 × 20 MB；實際商品照片通常數百 KB。
