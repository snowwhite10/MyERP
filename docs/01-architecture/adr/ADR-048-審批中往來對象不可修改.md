# ADR-048：審批中的往來對象不可修改

- 日期：2026-10-13
- 狀態：Accepted
- 工作單元：WU-MD-022a（MD 模組審查發現 MD-B01）

## 情境

ADR-046 讓客戶與供應商經 SYS 審批引擎核准。送審時，MD 把代碼與名稱作為 `DocumentNo`／`Summary` 快照交給 SYS，審批人在待辦清單看到的是這份快照。模組審查發現，`BusinessPartnerService.UpdateAsync` 沒有檢查審批狀態：送審後、審批人決定前，具 EDIT 權限的人仍可修改名稱、分類、預設付款條件與結算方式，審批人因此會核准一份與主檔不符的資料。

主檔的 `ReviewStatus = Pending` 同時代表「從未送審」與「審批中」（審查發現 MD-B02，排入 022b），所以不能只看主檔狀態。

## 決策

1. **審批中不可修改。** 修改客戶／供應商前，若主檔為 `Pending`，經 Shared 的 `IApprovalWorkflowService.GetStateAsync(單據類型, id)` 查詢最近一次審批；狀態為 `Pending` 時回 422 `MD.CUSTOMER.APPROVAL_PENDING`／`MD.SUPPLIER.APPROVAL_PENDING`（沿用刪除的錯誤碼，前端已有三語訊息）。從未送審、已撤回的資料仍可修改；駁回後主檔轉 `Rejected`，可修改後再送審。
2. **只在 `Pending` 時查 SYS。** 已核准或已駁回的資料不需查詢，修改不多一次往返。
3. **核准後的維護不需重審。** BlueWhale 的需求只要求新增的往來對象須經核准（REQ_F4118.1.4、2.4–2.5 "records … to be added"）。代碼不可修改；名稱、分類、預設值的修改受 EDIT 權限控制，並由資料稽核記錄前後值。若日後需要「變更重審」，以新需求處理，不在本決定範圍。
4. **服務以可選參數取得審批服務。** `CustomerService`／`SupplierService` 建構子加 `IApprovalWorkflowService? workflow = null`（放在最後，不影響既有呼叫）。API 主機以 DI 解析，SYS 模組必定註冊該服務；直接建構服務的整合測試不傳時不檢查。

## 後果

- 審批人看到的快照與主檔一致；要修改審批中的資料，須等審批人駁回後再改、再送審。SYS 目前沒有給 MD 的撤回 API，日後加入時，撤回後即可修改（狀態為 `Cancelled`，不擋）。
- 新增整合測試 `SupplierInOpenApprovalCannotBeEditedUntilDecided`、`CustomerInOpenApprovalCannotBeEditedButApprovedCustomerCan`（MD-PARTNER-REV-003）；經真實 SYS 審批引擎的端到端驗證放在 WU-MD-022c 的真實 API E2E。
