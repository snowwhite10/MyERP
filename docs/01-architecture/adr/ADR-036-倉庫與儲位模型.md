# ADR-036 — 倉庫與儲位模型

- 日期：2026-10-12
- 狀態：Accepted
- 工作單元：WU-MD-015（倉庫與儲位）

## 背景

BlueWhale 4.1.1.8.4 Warehouse Management 只有倉庫的查看、新增、修改、刪除（REQ_F4118.4.1–4，介面 4.4.1.8.17–19）；舊系統 `cangku` 表也只有代碼、名稱與停用旗標，沒有儲位。MyERP 的 INV 需要可選的儲位（貨架／格位）記錄庫存位置，所以 MD 要先提供倉庫與儲位主檔，並決定：

1. 倉庫與儲位是否同表、儲位分幾層。
2. 停用與刪除規則，並發時如何保持一致。
3. 庫存數量放在哪裡。
4. 權限與 API 形狀。

## 決定

1. **兩張表，儲位一層。** `md_warehouse`（REQ_DS43.115）沿用分類基底（代碼、名稱、啟用、自訂欄位），另加地址（300）、聯絡人（100）、電話（50）。`md_storage_location`（REQ_DS43.116）屬於一個倉庫，只有代碼、名稱、啟用。儲位不再分層：區／排／層等以代碼表達（例如 `A-01-03`），避免多層樹的搬移與深度規則；若日後真的需要分層，再加上層欄位。倉庫與儲位不同表，因為兩者的欄位、權限與被 INV 引用的方式都不同。
2. **代碼。** 倉庫代碼在公司內唯一；儲位代碼在同一倉庫內唯一（不同倉庫可重複）。兩者都是 1–30 位大寫 ASCII 字母、數字、`-`、`_`，建立後不可修改，軟刪除後仍保留（與其他主檔相同）。
3. **公司隔離。** `md_warehouse` 加唯一約束 `(company_id, id)`，儲位以 `(company_id, warehouse_id)` 複合外鍵參照，資料庫層阻止把儲位掛到別公司的倉庫。
4. **停用與刪除。**
   - 只能在啟用的倉庫新增儲位（422 `MD.STORAGE_LOCATION.WAREHOUSE_INACTIVE`）；既有儲位可在倉庫停用後繼續修改或刪除。
   - 倉庫停用不會連帶修改儲位狀態；某儲位可用 = 倉庫啟用且儲位啟用，由日後的查詢契約判斷。
   - 倉庫仍有未刪除的儲位時不可刪除（409 `MD.WAREHOUSE.HAS_LOCATIONS`），要先刪除儲位。
   - 新增儲位與刪除倉庫在公司級 applock `md_warehouse:{companyId}` 內檢查，避免並行時儲位掛到剛刪除的倉庫。
5. **庫存數量不在 MD。** 兩張表都沒有數量或金額欄位；庫存只由 INV 異動帳維護（MASTER_PROMPT 第 6 節）。INV 開始後，倉庫／儲位被庫存或單據引用時不可刪除；做法是 MD.Contracts 定義引用檢查介面、由 INV 實作，在 EP-INV 拆分時寫 ADR 決定，MD 不讀 INV 的表。儲位是否必填（按倉庫設定）也在 EP-INV 決定。
6. **權限與 API。** 新增 `MD.WAREHOUSE.VIEW／CREATE／EDIT／DELETE`。儲位是倉庫主檔的一部分：查看需要 `MD.WAREHOUSE.VIEW`，新增、修改、刪除需要 `MD.WAREHOUSE.EDIT`，不另設權限代碼（同 ADR-035 第 5 點）。API：`/api/v1/md/warehouses`（分頁，可依代碼、名稱、地址搜尋）與 `/api/v1/md/warehouses/{warehouseId}/locations`（分頁，依代碼或名稱搜尋）。

## 影響

- BlueWhale 沒有儲位需求；儲位按 ADR-002 追加為 `REQ_F4118.4.5`（查看、新增、修改、刪除儲位），介面追加 8.78。
- 前端倉庫頁沿用列表頁範本；儲位在倉庫列的對話框中維護（同物料專屬換算）。
