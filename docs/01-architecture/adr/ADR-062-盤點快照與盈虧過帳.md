# ADR-062：盤點快照與盈虧過帳

- 日期：2026-10-14T00:59:41+08:00
- 狀態：Accepted
- 工作單元：WU-INV-010（拆為 010d 設計、010a 後端、010b 前端）

## 背景

BlueWhale 4.1.1.5.7 只有兩個需求：建立盤點（REQ_F4115.7.1，原文誤寫為 inventory transfer）與產生盈虧報表（REQ_F4115.7.2）。介面 4.4.1.5.18 讓使用者多選倉庫、物料類別、物料後查詢，逐行輸入盤點數量（最多六位），填備註，再按「Generate Inventory Gain and Loss Document」。

舊系統（`store/Pandian`）的做法有三個問題：

- 帳面數量取自查詢當下、由瀏覽器送回，存檔時不重新核對。
- 盤盈、盤虧分別產生一張未核准的其他入庫單、其他出庫單，單價為 0，而且不在同一交易內完成。
- `pandian`／`pandianItem` 兩張表從未寫入，盤點過程沒有歷史。

WU-INV-010 的範圍包括快照、實盤輸入、差異報告、SYS 審批、盈虧異動、批序號與三語頁，超過單輪上限。

## 決策

1. **拆分。** 分為 010d（需求、資料、API、介面、測試設計）、010a（migration、MD 類別範圍契約、服務、API、真實 SQL／HTTP 測試）、010b（三語頁、差異報告列印／CSV、Vitest／Playwright）。父單元在 010b 驗收後關閉。

2. **單據與流程。** 盤點本身是一張 INV 單據 `inv_stocktake`，不像舊系統那樣另外產生其他入庫／出庫單。生命週期沿用 ADR-051 的 Draft → PendingApproval → Approved → Posted 與 Rejected。
   - 建立時，在同一交易內取 `INV.STOCKTAKE` 單號並寫入快照。
   - 使用者在草稿上輸入實盤數量，送 SYS 工作流。
   - 最終核准與 Posted 在同一交易完成：依「實盤 − 帳面」的差異，盤盈寫 `In`、盤虧寫 `Out`，過帳來源為 `STOCKTAKE` + 單據 ID。
   - 介面的 Generate Inventory Gain and Loss Document 按鈕對應「保存實盤並送審」。
   - 理由：盤點與盈虧異動共用同一份審批與同一個交易，不會出現「盤點已確認，但盈虧單被改數量或遺漏」的情況。

3. **快照範圍與粒度。**
   - 範圍：1–20 個倉庫（必填）、0–50 個物料類別（含下層類別）、0–500 個物料。範圍以 `scope_json` 保存，重新快照時沿用。
   - 物料類別屬 MD。010a 新增唯讀契約 `IItemCategoryScope`，依目前公司把類別展開成啟用中的物料 ID；INV 不 JOIN MD 資料表。
   - 快照只讀不可改寫的異動帳：每個「物料＋倉庫＋儲位」結存鍵取一行帳面數量，只收結存大於 0 的鍵。批號／序號物料另外按號碼記錄帳面數量（BR-INV-023 的同一個查詢來源）。
   - 同時記下快照時間 `snapshot_at`，以及當時公司內最大的異動 ID `snapshot_movement_id`。
   - 一張單最多 5,000 行、20,000 個批序號；超過時回 422 `INV.STOCKTAKE.TOO_MANY_LINES`，要求縮小範圍。

4. **快照後的異動（本 ADR 的核心）。** 盤點期間不凍結倉庫，其他單據仍可正常過帳。
   - **送審時：** 在送審交易內，依範圍重新計算現存量，與快照逐鍵比較（含批序號）；同時檢查範圍內是否有 ID 大於 `snapshot_movement_id` 的異動。任一不同即拒絕送審，回 422 `INV.STOCKTAKE.SNAPSHOT_STALE`，並列出最多 50 個變動的鍵。比較現存量，是為了涵蓋「ID 較小但較晚提交」的並發異動；檢查異動 ID，是為了涵蓋「進出淨額為零」的情況。
   - **重新快照：** 使用者以 `refresh-snapshot` 處理（只限草稿，帶版本）：
     - 更新帳面數量。
     - 保留已輸入的實盤數量；帳面數量有變的行標記 `recount_required`。
     - 加入範圍內新出現的鍵。
     - 移除帳面為 0、又沒有實盤數量的鍵。
   - **不採用「送審時自動重算差異」：** 系統不知道使用者在點數時是否已計入該筆異動，自動重算會把錯誤藏起來。
   - **送審之後：** 視為實地點數已完成。最終核准過帳的是送審時固定下來的差異，套用在當下的結存上；送審後才發生的異動屬點數以後的業務，會自然疊加。若盤虧在當下會令結存為負，過帳服務回 `INV.STOCK.INSUFFICIENT`（或批序號不足），SYS 決定與所有異動一起回滾；審批人須駁回，由盤點人重新快照。

5. **過帳細節。**
   - 每行的批序號差異分開計算：正數合計為一筆 `In`，負數合計為一筆 `Out`，兩筆同 `lineNo`。所以同一行可同時有盤盈批號 A、盤虧批號 B。
   - 無追蹤的物料，每行只有一個方向。差異為 0 的行不產生異動；全部行差異都為 0 時，仍可核准並轉 Posted，只是沒有異動。
   - 盤盈新批號沿用 ADR-060 規則，不填日期。盤盈序號須符合全公司結存 ≤ 1，所以已在他處現存的序號不可盤盈。
   - 盤盈與盤虧的成本都留空，由 WU-INV-014 估值處理；SYS 審批金額為 0，按文件類型設定流程。

6. **實盤輸入。**
   - 數量為 0 至最多六位小數的基本單位數量；序號只能是 0 或 1。
   - 草稿可暫缺；送審時每行與每個批序號都必須已輸入，否則回 422 `INV.STOCKTAKE.COUNT_MISSING`。前端提供「未盤行以帳面數量填入」的輔助功能。
   - 可新增實地找到的行（帳面 0，`is_added`）。新增行的倉庫必須在範圍內，物料須通過 MD guard 驗證；批序號物料可新增帳面 0 的號碼。
   - 實盤以整組替換保存，帶版本；版本衝突回 409。

7. **範圍互斥。** 同公司內，同一「物料＋倉庫」只能出現在一張未結（Draft／PendingApproval／Approved／Rejected）的盤點單。在建立、重新快照、新增行時，於公司級 `inv_stocktake:{公司}` 排他鎖內檢查，衝突回 422 `INV.STOCKTAKE.SCOPE_IN_USE`。這樣可以避免兩張單對同一份庫存重複盈虧。

8. **差異報告（REQ_F4115.7.2）。** `GET /{id}/variance` 只讀已保存的單據，回每行的帳面、實盤、差異、類型（Gain／Loss／Match／Uncounted），以及總盤盈、總盤虧數量與行數，可只看有差異的行。金額待 WU-INV-014 估值後再加，本單元不虛構成本。列印與 CSV 由前端依此報告輸出。

9. **介面編號。**
   - 4.4.1.5.18 Stocktake Create Interface 包含範圍查詢與實盤表格：`/inv/stocktakes/new`；建立後改為 `/inv/stocktakes/:id/count`，草稿與駁回修訂也使用此頁。
   - 列表、詳情、差異報告是新增介面 Stocktake View Interface。
   - 檢查時發現：既有擴充介面 5.8／5.9（期初）與 5.10（批序號追溯）和 BlueWhale 的 5.8 Sales Outbound (Approval)，以及 ADR-002 重排後的 5.9／5.10 Product Assembly 衝突。因此預留 5.21–5.23 給這三個介面重新編號（backlog WU-INV-019），盤點 View 編為 5.24。
   - REQ_F 依 ADR-002 規則 3 在 7.2 之後追加：7.3 view、7.4 edit、7.5 approve、7.6 reject、7.7 delete。

10. **資料表。** `inv_stocktake`、`inv_stocktake_line`、`inv_stocktake_line_tracking`，編號 REQ_DS43.151–153，對應 BlueWhale REQ_DS43.42 Stocktake。INV 子表用含 `company_id` 的複合 FK；MD ID 不建 FK。

## 影響

- 盤點不凍結業務。快照過期由送審檢查攔下，代價是點數期間範圍內有異動時，使用者必須重新快照並複核標記的行。
- 盈虧數量經 SYS 審批與異動帳過帳，不直接修改庫存彙總。
- 舊系統以兩張未核准單據處理盈虧，MyERP 不沿用。
- 010a 須先寫失敗測試再實作，涵蓋：快照粒度、過期偵測（含淨額為零及並發提交）、重新快照保留實盤、批序號盈虧、核准回滾、範圍互斥、重放。
