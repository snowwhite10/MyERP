# ADR-033 — 全系統資源變更須在受影響公司全權

- 日期：2026-10-11
- 狀態：Accepted
- 工作單元：WU-SYS-016b（SYS 模組代碼審查 SYS-B03）

## 背景

角色（`sys_role`）與 IP 白名單（`sys_ip_whitelist`）是全系統資源，不屬於任何公司（ADR-014、ADR-025）。但 `[RequirePermission]` 只檢查 `X-Company-Id` 指定的公司，所以：

1. 公司 B 的管理員有 `SYS.ROLE.EDIT` 就能修改公司 A 正在使用的角色，例如替 A 的角色加權限或停用 A 的管理員角色。
2. 有 `SYS.ROLE.EDIT` 的非全權用戶可以修改**自己被指派的角色**，加入自己沒有的權限，繞過 ADR-032 的角色上限。
3. 任何公司的白名單管理員新增第一條「系統層級」規則，就會令所有公司只能從該網段登入（等於鎖住其他公司）。

選項：

- A. 新增 `SYS.SYSTEM.*` 權限代碼。權限仍按公司授予，而全權角色涵蓋所有權限，結果仍是「任何一間公司的全權管理員」就能改，問題 1、3 不能解決；若令全權不涵蓋這些代碼，又要改 ADR-014 的全權定義。
- B. 只限「在目前公司全權」：同樣不能解決問題 1、3。
- C. 只限「在所有公司全權」：最安全，但一個未使用的角色也要集團管理員處理；而且任何人新增公司後，集團管理員未加入該公司前都不能改角色。
- D. **按影響範圍檢查**：變更影響哪些公司，操作者就要在這些公司都全權。

## 決定

採用 D。`AuthorityGuard.EnsureFullAccessAsync` 檢查操作者在每間受影響公司（含已停用公司）都有啟用中的全權角色（用戶與用戶公司關聯也須啟用），否則 403 `SYS.AUTHORITY.FULL_ACCESS_REQUIRED`。受影響公司：

| 動作 | 受影響公司 |
|---|---|
| 修改角色（`PUT /roles/{id}`） | 角色已指派給用戶的每間公司 |
| 新增角色、刪除角色 | 無（新角色未被使用；刪除使用中的角色本來就回 422 `SYS.ROLE.IN_USE`） |
| 新增／修改系統層級白名單 | 全部公司 |
| 新增／修改角色層級白名單 | 角色已指派的每間公司 |
| 新增／修改用戶層級白名單 | 用戶有關聯的每間公司（含已停用關聯） |

檢查放在 Controller（同 ADR-032 的 `UsersController`、`CompaniesController`），服務維持可供種子與測試直接呼叫。目標缺漏或層級無效時不做檢查，交由服務回 400。

## 取捨

- 未被使用的角色仍可由有 `SYS.ROLE.EDIT` 的非全權用戶修改；之後指派該角色時受 ADR-032 角色上限保護，所以不會造成權限提升。
- 系統層級白名單需要在全部公司（含已停用）全權。單一公司部署時就是該公司的管理員；多公司部署時是集團管理員。種子管理員（`admin`）在所有種子公司都是 `ADMIN` 全權角色。
- 新增公司後，集團管理員須先加入新公司（建立者會沿用其角色，ADR-015）才能再改系統層級規則。這是刻意的保守選擇。
- 每次檢查兩次查詢（受影響公司、操作者全權公司），管理動作頻率低，可接受。
- 前端沒有預先隱藏按鈕（需要額外的授權 API），被拒時以三語錯誤訊息說明。
