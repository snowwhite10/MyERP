# ADR-001 技術版本固定

- 狀態：Accepted
- 日期：2026-10-10
- 工作單元：WU-P0-004
- 相關風險：R-014（無 Python）、R-015（版本相容）、R-016（本機 Node 版本過低）

## 背景

MASTER_PROMPT 第 4 節固定技術棧，並要求實際版本與主要套件版本在本 ADR 固定：後端 .NET 10（LTS）；前端使用 ng-zorro-antd 已正式支援的最新 Angular 主版本。日後升級須另寫 ADR，並先通過全部測試。

## 查證方法（2026-10-10 11:00，於 VM 本機執行）

- `dotnet --list-sdks` / `dotnet --list-runtimes`
- `node -v`、`npm -v`、`npm view <pkg> version|peerDependencies|engines`
- NuGet：`https://api.nuget.org/v3-flatcontainer/<id>/index.json`（只取穩定版）與 `.nuspec` 相依性
- 腳本：`tools/versions/Get-LatestVersions.ps1`（日後升級評估可重跑）

## 決定

### 1. 後端（.NET）

1. Target Framework：`net10.0`；SDK 以 repo 根目錄 `global.json` 固定：`"version": "10.0.301", "rollForward": "latestPatch"`（同一 feature band 的修補版可自動採用；換 feature band 須另寫 ADR）。
2. NuGet 版本以 `src/backend/Directory.Packages.props`（Central Package Management）集中管理，於 WU-P0-006 建立；專案檔不得自行寫版本號。
3. 套件與版本：

| 用途 | 套件 | 版本 | 備註 |
|---|---|---|---|
| ORM | Microsoft.EntityFrameworkCore.SqlServer | 10.0.12 | |
| Migration 工具 | Microsoft.EntityFrameworkCore.Design | 10.0.12 | `dotnet-ef` 全域 / 本機工具同版 |
| 命名規則 | EFCore.NamingConventions | 10.0.1 | Apache-2.0；相依 EF Core [10.0.1, 11) |
| SQL 驅動 | Microsoft.Data.SqlClient | 6.1.7 | 與 EF Core SqlServer 10.0.12 的相依（≥ 6.1.6）同主版本；**不採用 7.x**，避免越過 EF 測試過的主版本。禁止 System.Data.SqlClient |
| 驗證 | FluentValidation、FluentValidation.DependencyInjectionExtensions | 12.1.1 | 不使用已棄用的 FluentValidation.AspNetCore 自動驗證，改為端點 / 服務內明確驗證 |
| 日誌 | Serilog.AspNetCore | 10.0.0 | |
| 日誌 | Serilog.Sinks.File | 7.0.0 | |
| 日誌 | Serilog.Sinks.ApplicationInsights | 5.0.1 | 可選；無連線字串時不啟用。相依 Microsoft.ApplicationInsights 2.23.0（ADR-008） |
| 遙測 | Microsoft.ApplicationInsights.AspNetCore | 3.2.0 | **暫不使用**：3.x 與上列 sink 的 2.x 相依衝突（ADR-008） |
| OpenAPI 文件 | Microsoft.AspNetCore.OpenApi | 10.0.12 | .NET 10 內建產生 OpenAPI 文件 |
| Swagger UI | Swashbuckle.AspNetCore.SwaggerUI | 10.3.0 | 只用 UI 指向內建 OpenAPI 文件；非 Development 預設關閉 |
| 驗證 | Microsoft.AspNetCore.Authentication.JwtBearer | 10.0.12 | |
| 密碼雜湊 | Microsoft.AspNetCore.Identity（PasswordHasher） | 隨 ASP.NET Core 10 共用框架 | 只用 PasswordHasher，不引入完整 Identity UI |
| 快取 | StackExchange.Redis | 3.4.0 | |

| 測試框架 | xunit.v3 | 4.0.2 | |

| Mock | Moq | 4.20.72 | 不採用 4.21.0（新釋出，待觀察）；4.20.2 起已移除 SponsorLink |
| 覆蓋率 | coverlet.collector | 10.1.0 | |

4. **FluentAssertions 固定 7.x**：8.x 起改為 Xceed 商業授權（nuspec 註明「commercial use requires a paid license」，且 `requireLicenseAcceptance=true`）。MyERP 為企業用途，固定 Apache-2.0 授權的最後版本 7.2.2，以遵守 MASTER_PROMPT「使用 FluentAssertions」又不引入授權風險。如將來需要 8.x 功能，可改用其 Apache-2.0 分支 AwesomeAssertions（另寫 ADR）。
5. 若 WU-P0-006 實測 xunit.v3 4.x 與 `dotnet test` / CI 有相容問題，可退回 xunit 2.9.3 + xunit.runner.visualstudio 3.1.5，須在 optimization-log 記錄原因並補 ADR。

### 2. 前端（Angular）

1. **Node.js 固定 24 LTS（24.21.0，Krypton）**。Angular 22 的 `engines.node` 為 `^22.22.3 || ^24.15.0 || >=26.0.0`，本機 22.16.0 不符合。WU-P0-010 開始時以 nvm-windows 安裝並切換（`nvm install 24.21.0`、`nvm use 24.21.0`），並在 `src/frontend/package.json` 寫 `engines`、repo 根目錄寫 `.nvmrc`。如 `nvm use` 需要系統管理員權限而無法切換，寫 BLOCKED 前先採用退路（決定 2.4）。
2. 套件與版本：

| 用途 | 套件 | 版本 | 備註 |
|---|---|---|---|
| 框架 | @angular/core 等 @angular/* | 22.2.x（查證時 22.2.2） | standalone、zoneless 優先 |
| CLI / 建置 | @angular/cli、@angular/build | 22.2.x | |
| CDK | @angular/cdk | 22.2.x | ng-zorro 相依 |
| UI | ng-zorro-antd | 22.1.1 | peerDependencies `@angular/* ^22.0.0`；ng-zorro 主版本 = Angular 主版本 |
| 圖示 | @ant-design/icons-angular | 22.1.x | ng-zorro 相依 |
| 圖表 | @antv/g2 | 5.4.8 | 馬卡龍主題由共用元件封裝 |
| i18n | @ngx-translate/core、@ngx-translate/http-loader | 18.0.0 | 執行期切換 zh-Hant / zh-Hans / en（Angular 內建 i18n 需按語言分別建置，不適合執行期切換） |
| TypeScript | typescript | ~6.0.3 | @angular/build 22 要求 `>=6.0 <6.1`；**不得**使用 TypeScript 7 |
| 單元測試 | vitest（Angular CLI 預設 runner） | 依 @angular/build 22 peer（^4.0.8 或 ^5） | WU-P0-010 按 CLI 產生的設定固定 |
| E2E | @playwright/test | 1.64.0 | |

3. 版本以 `package-lock.json` 鎖定，安裝一律 `npm ci`。
4. 退路：如 Node 24 無法安裝，改用 Angular 21.2.x + ng-zorro-antd 21.2.x（Angular 21 支援 Node `^22.12.0`），另寫 ADR 記錄，Node 問題解決後再升級。

### 3. 文件產生（docgen，R-014）

VM 沒有 Python。docgen 使用 **.NET 10 console + DocumentFormat.OpenXml 3.5.1** 產生 docx / xlsx，理由：與後端同一技術棧、可共用測試框架、OpenXML SDK 可精確控制 BlueWhale 版面（表格框線、欄寬、樣式）。Node 方案（docx 9.9.0、exceljs 4.4.0）只作為備選，不同時引入。

### 4. 資料庫與其他

| 項目 | 版本 / 設定 |
|---|---|
| SQL Server | 2022，實例 `localhost\MSSQLSERVER2022`，Windows 驗證 |
| Redis | Memurai（Redis 相容）或同等方案，版本於 WU-SYS-003 確認並補記 |
| CI | GitHub Actions `windows-latest`，`actions/setup-dotnet` 用 global.json、`actions/setup-node` 用 `.nvmrc` |

## 影響

- WU-P0-006：建立 `Directory.Packages.props`，套用上表版本；確認 xunit.v3 可跑。
- WU-P0-009：驗證 Serilog.Sinks.ApplicationInsights 與 Microsoft.ApplicationInsights 3.x 相依。（已完成：不相容，只用 sink + 2.23，見 ADR-008）
- WU-P0-010：先處理 Node 24 切換，再 `ng new`。
- WU-P0-013：docgen 用 .NET + OpenXML。
- 升級流程：重跑 `tools/versions/Get-LatestVersions.ps1` → 另寫 ADR → 全部測試通過才 merge。修補版（patch）升級可只在 optimization-log 記錄，不必新 ADR。
