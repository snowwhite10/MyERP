# ADR-010 文件產生器骨架與 Codex 工具對應

- 狀態：Accepted
- 日期：2026-10-10
- 工作單元：WU-P0-013

## 背景

`MASTER_PROMPT.md` 第 15 節要求從 Markdown 單一來源產生 SRS、SDS、Excel，並檢查與資料庫及 BlueWhale 基線的一致性。第 16 節列的 `docx`、`xlsx`、`Mermaid` 等 Claude Skills 在本輪 Codex 環境不存在；依入口指令，首次遇到時記錄替代方法。ADR-001 已固定使用 .NET 10 與 DocumentFormat.OpenXml 3.5.1。

## 決定

1. 使用 OpenXML SDK 直接建立 Word 與 Excel；章節標題、表格欄寬、邊框、字型、頁面尺寸照 `reference-notes.md` 的 BlueWhale 版面資料。由單一介面清單產生 SRS 4.4、4.5 與 SDS 4.2，降低次序漂移。
2. 使用 Markdown 解析器讀取模組需求、資料結構、介面、測試計劃；缺少的敘述來源輸出 `[Pending]`，並在一致性報告列警告。此階段只建立骨架，不將佔位內容視為正式完成的章節。
3. SDS 4.1 欄位表只在提供 SQL Server 連線時由 `INFORMATION_SCHEMA` 產生；未連線時保留佔位並警告。正式產出不得手寫資料表欄位。
4. 以 OpenXML SDK 及 xUnit 直接測試文件結構，取代本環境沒有的 `docx`、`xlsx` Skills。Mermaid 原始碼維持在 Markdown，後續正式圖與截圖工作單元再處理。
5. 任何一致性 `Error` 使 CLI 返回非零；早期模組尚未建立的 `Warning` 允許骨架產出。產物集中 `docs/99-output/`，不手動修改。

## 影響

新增模組後須重跑 docgen。模組文件與正式敘述逐步到位時，警告應減少；最終 SRS/SDS 交付前必須補齊敘述、ER 圖、介面截圖，並通過完整一致性檢查。
