# ADR-003 模組專案結構與資料存取（單一 DbContext、Contracts 專案、路由與權限前綴）

- 狀態：Accepted
- 日期：2026-10-10
- 工作單元：WU-P0-005

## 背景

MASTER_PROMPT 第 5 節要求模組化單體：每個模組一個獨立專案（例如 `MyERP.Modules.Sales`），內部分 Api / Application / Domain / Infrastructure；模組間只能經對方 Application 介面或進程內領域事件溝通，不得讀寫其他模組資料表。同時要求：

- 跨模組業務流程（出貨扣庫存、單據過帳）必須與原單據一致（同一交易）；
- migration 命名 `{Module}_{Purpose}`（例如 `Sales_AddCreditLimit`），建庫時設定定序；
- 權限代碼範例 `SAL.ORDER.APPROVE`、API 路徑 `/api/v1/{module}/{resource}`、資料表前綴 `sal_`。

需要決定：(1) 模組內分層用專案還是資料夾；(2) 別的模組依賴什麼；(3) DbContext 與 migration 的切分；(4) 路由與權限的「模組」段用哪個代碼。

## 決定

1. **每模組兩個專案**：
   - `MyERP.Modules.<Name>`：內部實作，Api / Application / Domain / Infrastructure 為**資料夾**（MASTER_PROMPT「一個獨立專案、內部分層」的字面要求）。
   - `MyERP.Modules.<Name>.Contracts`：對外公開的 Application 介面、整合事件、跨模組 DTO。其他模組**只可**引用 Contracts，不可引用實作專案。
2. **分層與邊界由 `MyERP.ArchitectureTests` 強制**：用 xUnit + 反射檢查組件引用與命名空間（例如 `*.Domain` 不得引用 `Microsoft.EntityFrameworkCore`；模組實作不得引用其他模組實作；禁止使用 `DateTime.Now/UtcNow`、`System.Data.SqlClient`）。不額外引入 NetArchTest 等套件，避免改動 ADR-001 套件清單。
3. **單一 `MyErpDbContext`**（位於 `MyERP.Shared.Infrastructure`）：每個模組以 `IModuleDbModel` 註冊自己的 `IEntityTypeConfiguration`，DbContext 於 `OnModelCreating` 套用全部模組。理由：
   - 同一請求內所有模組共用一個 scoped DbContext → 跨模組同步呼叫與交易內事件處理器自然在同一交易，不需分散式交易或 outbox；
   - 單一 migration 鏈（`MyERP.Migrations` 專案），以 `{Module}_{Purpose}` 命名區分模組，順序明確、可逐一還原；
   - 建庫定序、SP 部署只需一處處理。
   模組邊界不靠 DbContext 分割，而靠：模組 Repository 只存取本模組實體（ArchitectureTests 檢查 `Set<T>()` 的 T 位於本模組命名空間）、跨模組不建 navigation / FK。
4. **前綴統一**：資料表前綴 = API 路由模組段 = 權限代碼模組段（大寫）。例如 SD 模組：`sal_order`、`/api/v1/sal/orders`、`SAL.ORDER.APPROVE`。FI 擁有多個前綴（`gl`、`ar`、`ap`、`fa`、`cm`、`tax`），各自作為路由與權限段。模組代碼（SD、FI…）只用於專案、文件、日誌與 state.json。
5. **測試專案**：每模組一個單元測試專案 `tests/backend.unit/MyERP.Modules.<Name>.Tests`；共用 `MyERP.Shared.Tests`、`MyERP.ArchitectureTests`；整合測試集中於 `tests/backend.integration/MyERP.IntegrationTests`（跨模組流程需同一主機）。

## 考慮過的方案

| 方案 | 不採用原因 |
|---|---|
| 每模組 4 個分層專案 | 15 模組 × 4 = 60 專案，建置慢、維護成本高；資料夾 + 架構測試已足以約束 |
| 每模組一個 DbContext + 各自 migration 歷史表 | 跨模組交易需共用連線與交易物件，複雜且易錯；多條 migration 鏈的建庫順序難保證 |
| 路由使用模組代碼（`/api/v1/sd/orders`）而權限用前綴（`SAL.*`） | 兩套代碼容易混淆；FI 下的子帳權限需要更細粒度 |

## 影響

- WU-P0-006 依此建立骨架；`architecture.md` 第 2 節為結構說明。
- WU-P0-007 / 008：`MyErpDbContext`、interceptor、Global Query Filter 放 `MyERP.Shared.Infrastructure`；migration 放 `MyERP.Migrations`，CLAUDE.md / AGENTS.md 的 migration 指令改為 `-p src/backend/MyERP.Migrations -s src/backend/MyERP.Api`。
- 如日後某模組需獨立部署（拆微服務），以 Contracts 介面為邊界替換為 HTTP / 訊息實作，另寫 ADR。
