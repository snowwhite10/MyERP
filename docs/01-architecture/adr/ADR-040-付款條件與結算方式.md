# ADR-040 — 付款條件與結算方式

- 日期：2026-10-12
- 狀態：Accepted
- 工作單元：WU-MD-018（付款條件與結算方式）

## 背景

BlueWhale 只有「Settlement Method」（4.1.1.8.14，REQ_F4118.14.1–4；介面 4.4.1.8.48–50；資料表 `PayType`＝REQ_DS43.55）：一個公司內的名稱清單（`id`、`shopId`、`names` varchar(100)）。收付款單據的結算明細另有「Settlement Account」（資金帳戶）下拉，兩者互不綁定。舊系統 `payType` 表相同：名稱必填、同店不可重名、刪除時不檢查引用。

付款條件（到期規則）在 BlueWhale SRS／SDS 都沒有；客戶、供應商也沒有帳期欄位。舊系統只在銷售報價單有寫死的「付款時間」下拉（預付款、貨到付款、月結 30／45／60／90／120／180 天），以文字存放，不計算到期日。應收應付（FI）需要依單據日期算出到期日以做帳齡與催收，所以按台灣／中國常見的「月結」實務自行定義（ADR-002 追加需求）。

## 決定

1. **結算方式 `md_settlement_method`（REQ_DS43.122，對應 BlueWhale REQ_DS43.55）。** 沿用分類基底：`code`（1–30 英數、`-`、`_`，轉大寫，公司內永久唯一含已刪除）、`name`（必填，最多 200 字，大於 BlueWhale 的 100）、啟用、軟刪除、`custom_fields`、版本、審計欄位。BlueWhale 只有名稱；加上代碼是為了讓 FI 單據與匯入以穩定代碼引用（與其他 MD 分類一致）。**不綁定資金帳戶**：資金帳戶歸 WU-MD-020／FI，單據結算明細分別選結算方式與資金帳戶。
2. **付款條件 `md_payment_term`（REQ_DS43.123）。** 同樣沿用分類基底，另加 `due_type` varchar(20) 與四個可空整數欄位。三種到期規則：
   - `NetDays`：單據日 + `days`（0–365）。`days = 0` 表示即期、貨到付款或現金。
   - `ClosingDays`（月結 N 天）：帳期結帳日 + `days`。
   - `ClosingMonthDay`：結帳日後第 `months`（0–12）個月的 `payment_day` 日（1–31）。例如「25 日結帳，次月 10 日付款」為 `closing_day = 25`、`months = 1`、`payment_day = 10`。`months = 0` 時付款日必須晚於結帳日（400 `paymentDay`）。

   `closing_day`（1–31）是每月結帳日：單據日不晚於當月結帳日屬當期，否則屬下期。31 表示月底；結帳日或付款日大於當月天數時一律取當月最後一天（例如 30 日結帳在 2 月取 28／29 日）。不適用於該規則的欄位一律存 null，由 CHECK `ck_md_payment_term_rule` 保證，範圍由 `ck_md_payment_term_ranges` 保證。API 收到不適用的欄位時忽略，不報錯，讓前端切換規則時不必清欄位。
3. **不支援預付款規則。** 「預付款」是在出貨前收付訂金，屬於單據（訂金／預收付款），不是由單據日推算到期日，因此不在付款條件內建模。需要時可建 `NetDays 0` 的條件命名為「預付」，實際的預收付款流程由 SD／PUR／FI 處理。
4. **到期日計算在 Domain（`PaymentTerm.DueDate`），經契約提供。** MD.Contracts 新增：
   - `IPaymentTermLookup.FindAsync(code)`（含停用，不存在回 null）與 `CalculateDueDateAsync(code, documentDate)`（不存在 404 `MD.PAYMENT_TERM.NOT_FOUND`、停用 422 `MD.PAYMENT_TERM.INACTIVE`、結果超出日期範圍 400 `documentDate`）；
   - `ISettlementMethodLookup.FindAsync(code)` 與 `RequireActiveAsync(code)`（404 `MD.SETTLEMENT_METHOD.NOT_FOUND`、422 `MD.SETTLEMENT_METHOD.INACTIVE`）；
   - `PaymentTermDueType` 列舉以名稱序列化。

   單據保存付款條件代碼與**算出的到期日**；修改付款條件不回溯，所以規則在被引用後仍可修改。
5. **使用檢查由使用方模組提供**（同 ADR-039）。MD.Contracts 定義 `IPaymentTermUsage`、`ISettlementMethodUsage`，SD／PUR／FI 實作並註冊。已被引用的資料不可刪除（409 `MD.PAYMENT_TERM.IN_USE`、`MD.SETTLEMENT_METHOD.IN_USE`），只可停用。MD 不讀其他模組的表；目前沒有實作，視為未使用。
6. **不加 applock。** 兩張表都沒有樹狀關係或期間重疊等跨列規則；重複代碼由唯一索引保證，修改以版本控制。刪除與單據引用的並行由使用方在 FI／SD 的交易中處理（新單據以 `RequireActiveAsync`／`CalculateDueDateAsync` 驗證時讀到已刪除的資料會得到 404）。
7. **權限與 API。** 權限為 `MD.SETTLEMENT_METHOD.VIEW／CREATE／EDIT／DELETE` 與 `MD.PAYMENT_TERM.VIEW／CREATE／EDIT／DELETE`。API：
   - `/api/v1/md/settlement-methods` 與 `/api/v1/md/payment-terms`：分頁列表、建立、帶版本修改與刪除；
   - `GET /api/v1/md/payment-terms/due-date?code=&documentDate=` 讓前端試算到期日。

## 不在本工作單元

- 客戶與供應商的預設付款條件、預設結算方式：在 SD／PUR 單據需要帶出預設值時追加欄位，仍經本契約讀取。已加入 backlog（WU-MD-025）。
- 分期付款（多個到期日與比例）、現金折扣（例如「2/10 net 30」）：目前沒有需求來源，日後由 FI 提出時另寫 ADR。
- 資金帳戶（BlueWhale Account）：WU-MD-020。

## 影響

- 需求：REQ_F4118.14.1–5（結算方式，沿用 BlueWhale 編號，14.5 為追加的契約）、REQ_F4118.40.1–5（付款條件，追加）、REQ_DS43.122–123。介面 8.48–8.50 沿用 BlueWhale 結算方式編號，付款條件介面自 8.89 起（第二段 WU-MD-018b）。
- SD、PUR、FI 取付款條件與結算方式一律經 `IPaymentTermLookup`／`ISettlementMethodLookup`，不得讀 `md_` 表；引用方模組必須實作對應的 Usage 介面（該模組工作單元的驗收條件）。
