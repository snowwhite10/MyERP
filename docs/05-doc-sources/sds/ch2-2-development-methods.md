MyERP is developed in bounded backlog work units. A work unit records requirements and acceptance criteria, updates the module design and test plan, adds tests before implementation when software behavior changes, and verifies the resulting build and tests before completion. Module reviews also examine boundaries, security, user experience, application logs and documentation. Conventional commits and the progress record preserve the history of each completed increment.

The backend uses .NET 10, ASP.NET Core Web API, EF Core and SQL Server migrations. The frontend uses Angular and ng-zorro-antd, with separate language resources and light and dark themes. Unit, integration and browser tests cover their respective boundaries. Changes to startup, authentication or completed modules also require the real startup-path smoke test described in the project instructions. Test results in this SDS are interpreted through the current work-unit and progress records; planned cases do not imply a passing implementation.

If SQL Server or Redis is unavailable, database-dependent implementation and acceptance remain incomplete and are recorded as blocked. Work that does not depend on the unavailable service may proceed as a separately scoped increment. If a generated document is open in another application, DocGen can write to an isolated output directory for consistency checks. That alternate output does not replace the required database schema comparison or a real application smoke test. Failed pushes are logged while local commits and their evidence are retained for a later retry.
