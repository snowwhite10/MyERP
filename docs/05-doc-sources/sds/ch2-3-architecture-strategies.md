The Angular single-page client calls the ASP.NET Core API through versioned routes. The API is one deployable process with separate module implementation and Contracts projects. Within a module, API, application, domain and infrastructure code have distinct responsibilities. Architecture tests enforce dependency direction and reject direct references to another module's implementation. Shared infrastructure supplies the database context, company and soft-delete filters, audit stamping, optimistic concurrency and common error responses.

Authentication uses JWT access tokens and refresh tokens. The server evaluates company access, permission codes and data scope for protected operations; the client may hide unavailable actions but does not grant authorization. Audit entries and structured application logs support investigation. SQL Server stores transactional data, while Redis-compatible infrastructure supports refresh-token and cache behavior. HTTPS, request limiting and other security controls are described in the security architecture; deployment-specific settings must be verified in the target environment.

EF Core handles ordinary persistence, and migrations version database structure and stored procedures. Module-owned contracts coordinate synchronous cross-module operations that require one database transaction. Events after commit are suitable for notifications or rebuildable projections, not for essential posting side effects. Accounting entries pass through the finance posting contract, and stock summaries are not directly adjusted by other modules. Interfaces and data structures in Chapter 4 are generated from module sources; actual database columns require a live schema read, and actual interface screenshots require the implemented application.
