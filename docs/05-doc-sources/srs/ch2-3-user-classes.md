The following classes describe intended access. A person may hold more than one role, and every permission is evaluated for the selected company. Exact permission assignments are configured by the system administrator.

| User class | Characteristics and principal tasks |
|---|---|
| System administrator | Maintains companies, users, roles, security settings, workflow rules and audit access; grants only the permissions required for each role. |
| Master data steward | Creates and maintains partners, products, units, warehouses, tax codes and other reference records; reviews validation and approval results. |
| Operational user | Enters and views purchasing, sales, inventory and other business documents within the assigned company and data scope. |
| Approver | Reviews submitted documents, approves or rejects within configured authority and sees the decision history. |
| Finance user | Reviews accounting sources and performs authorized posting, reconciliation and financial reporting tasks. |
| Manager or analyst | Reads authorized dashboards and reports and examines supporting business records within the assigned data scope. |
| Read-only user | Searches and views permitted records without create, edit, approval or posting rights. |

The same person may be an operational user in one company and a read-only user in another. A request without company access is rejected. Authentication, authorization and data scope requirements are specified in Chapter 4.
