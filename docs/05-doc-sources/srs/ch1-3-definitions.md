The following terms are used throughout this specification.

| Term | Definition |
|---|---|
| ERP | Enterprise resource planning; the integrated business application specified here. |
| SRS | Software Requirements Specification; the statement of required behavior and acceptance criteria. |
| SDS | Software Design Specification; the design and implementation description generated alongside this SRS. |
| API | Application programming interface used by the client and by published module contracts. |
| RBAC | Role-based access control; permissions assigned through roles and evaluated in a selected company. |
| JWT | JSON Web Token used for authenticated API access. |
| EF Core | Entity Framework Core, the data access framework used by the backend. |
| GL | General ledger; the owner of posted accounting entries. |
| ADR | Architecture Decision Record documenting a project design decision. |
| Work unit | One backlog item developed, verified, documented and committed as a bounded increment. |
| Posted | A business state in which a transaction has been committed through its owning module; the exact transition is defined by that module. |

Requirement IDs beginning REQ_F identify functions, REQ_NF identify non-functional requirements, REQ_DS identify data structures, and REQ_IO identify interface items. Their numbering and traceability rules are defined in the project specification and preserved in the generated requirements workbook.
