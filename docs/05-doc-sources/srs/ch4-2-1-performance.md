MyERP shall keep routine transactions responsive as company data and the number of users grow. Performance acceptance uses the workload, data volume, percentile and measurement method defined for each requirement in the architecture baseline. A target below is a requirement, not a claim that the current implementation has passed a load test.

For a table containing 100,000 records, paged list APIs shall have a 95th-percentile response time below 500 ms (REQ_NF421.1). Single-record read and save APIs, excluding stored-procedure batch work, shall have a 95th-percentile response time below 300 ms (REQ_NF421.2). A list request shall execute no more than five SQL commands, so that adding rows does not introduce an N+1 query pattern (REQ_NF421.7). Integration tests shall load the stated data volume, time the requests and count EF Core commands.

An API request taking more than one second shall produce a Warning log entry; under normal load, such warnings shall be fewer than 1% of requests (REQ_NF421.3). The first dashboard view backed by aggregate procedures shall load within two seconds, and a 12-month transaction report within five seconds (REQ_NF421.4). The gzipped initial frontend bundle shall be below 500 KB, module code shall load on demand, and route changes shall complete within one second (REQ_NF421.5). Build budgets and browser timing shall verify the frontend targets; request logs and browser timing shall verify the dashboard and report targets.

The system shall support 200 concurrent online users while the error rate of ordinary APIs remains below 0.1% (REQ_NF421.6). This requires a representative local load test before the BI phase acceptance. Any result must identify the dataset, hardware, concurrent workload and measurement window; an unrun test remains an open acceptance item.
