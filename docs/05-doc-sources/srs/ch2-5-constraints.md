The implementation uses the fixed architecture and versions described in the architecture decisions: an Angular client, a .NET 10 ASP.NET Core modular monolith, EF Core, SQL Server 2022 and a Redis-compatible service on a Windows VM. Schema changes are versioned migrations. Business modules own their tables, and other modules access them through published application contracts or events. Financial entries use the general ledger posting service, and stock changes use inventory-owned operations.

The API uses versioned REST routes and ProblemDetails responses. Authentication uses JWT access and refresh tokens; authorization checks roles, company membership and data scope. Persisted monetary values use decimal types. Business time is obtained through the shared clock abstraction. The interface must support three languages, light and dark modes, and understandable feedback for partial or failed operations.

The repository is public. Reference documents, customer data, secrets and operational logs must remain outside committed source. The SRS, SDS and requirements workbook are generated from controlled Markdown and actual database metadata; a document generated while SQL Server is unavailable cannot claim database schema verification. Production deployment and customer data migration require separate work.
