MyERP shall provide service health signals and recoverable data. The monthly service-time availability target is at least 99.5%, measured from deployment monitoring after production operation begins (REQ_NF424.1). No development-environment run can establish this monthly production target.

The application shall expose /health/live and /health/ready; readiness shall check SQL Server and Redis, and both health responses shall complete within one second (REQ_NF424.2). Database backup and recovery procedures shall target a recovery point of no more than 24 hours for full backups or 15 minutes for transaction logs, and a recovery time of no more than four hours (REQ_NF424.3). Deployment documentation and a timed restore exercise shall supply acceptance evidence; a documented target alone is insufficient.

If Redis is unavailable, an already authenticated user's access token shall remain usable until expiry, with an Error log entry recording the cache failure (REQ_NF424.4). An exception in one module shall return HTTP 500 ProblemDetails without terminating the process or preventing other modules from serving requests (REQ_NF424.5). Integration tests shall inject each failure and verify both the response and continued service.
