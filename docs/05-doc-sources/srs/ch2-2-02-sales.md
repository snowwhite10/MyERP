The Sales module (SD) covers quotations, sales orders, deliveries, pricing and discounts, invoices, customer credit checks and returns. A quotation records an approved customer and commercial terms before an order is created. An order keeps its own priced line snapshot and approval history. Delivery of an approved order requests an inventory-owned outbound posting; an invoice uses posted delivery quantities and creates a receivable through the Finance contract. A return uses a separate, traceable document and inventory reversal flow. These are the target behaviors specified by REQ_F4112.1–2.7.

Sales actions are company-scoped and permission-controlled. The planned approval and posting steps must preserve the source document, prevent duplicate effects on retry, and report unavailable Inventory or Finance services as an explicit failure. Prices, tax and credit exposure are calculated from dated, saved evidence; changing a current rule must not rewrite an approved document.

The current SD implementation contains a module foundation and application-level quotation and order lifecycle calculations. The document tables, authorised transaction APIs, pages, Inventory/FI integration and real SQL acceptance for the Sales workflows remain in the backlog. This section describes the intended product scope and does not assert that an order, delivery or invoice can already be completed in the running application.
